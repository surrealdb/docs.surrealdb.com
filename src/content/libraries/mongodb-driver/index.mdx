# MongoDB driver for JavaScript

`@surrealdb/mql` is a JavaScript library with the same API as the MongoDB Node.js driver, and it stores its data in SurrealDB. Code that uses `MongoClient`, collections and cursors can run on SurrealDB after a change of import and connection string.

The library is a client only. It connects over WebSocket or HTTP, like the JavaScript SDK, so the instance needs no extra protocol listener or setting.

<AgentPrompt text="Connect this project to SurrealDB with the SurrealDB MongoDB driver. Read https://surrealdb.com/docs/libraries/mongodb-driver.md first, and use @surrealdb/mql in place of the mongodb package." />

## When to use the MongoDB driver

- **Existing MongoDB code.** An application that uses the MongoDB Node.js driver or Mongoose can run on SurrealDB, and you can move queries to SurrealQL one at a time.
- **The MongoDB API with SurrealDB features.** The data is stored as ordinary SurrealDB records, so SurrealQL, graph queries and the other data models can read what the driver writes.

If you want SurrealQL and the full data model from JavaScript, use the [JavaScript SDK](/docs/reference/javascript). If you want typed queries from a schema defined in code, use [Surqlize](/docs/libraries/surqlize-typescript). To copy data out of a running MongoDB, see [Migrating from MongoDB](/docs/integrate/migrating/from-other-databases/from-mongodb).

> [!NOTE]
> The package is before version 1.0. It follows the API of the MongoDB Node.js driver v7 and matches MongoDB 8.0 behaviour. A release can correct an answer that differed from MongoDB, and the [changelog](https://github.com/surrealdb/mql.js/blob/main/CHANGELOG.md) lists each correction.

## Requirements

- **SurrealDB 3.0.0 or newer.** SurrealDB 2.x is not supported, and `connect()` fails with a `MongoCompatibilityError` when it detects an older server.
- **Node.js 20.19.0 or newer.** The WebSocket transport needs a global `WebSocket`, which Node.js has from version 22. On Node.js 20.10 and later, start Node.js with `--experimental-websocket`. The HTTP transport needs neither.
- **TypeScript 5.3 or newer**, if you use the types.

Then connect with a MongoDB connection string. The `namespace` parameter is the one addition, because SurrealDB needs a namespace and a MongoDB connection string has no place for one.

```ts
import { MongoClient } from "@surrealdb/mql";

const client = new MongoClient("mongodb://root:secret@localhost:8000/shop?namespace=docs");
await client.connect();

const users = client.db().collection("users");

await users.insertMany([
	{ name: "Alice", age: 30 },
	{ name: "Bob", age: 25 },
	{ name: "Charlie", age: 35 },
]);

const adults = await users.find({ age: { $gte: 30 } }).sort({ age: -1 }).toArray();
await users.updateOne({ name: "Alice" }, { $set: { age: 31 } });

await client.close();
```

The `shop` database and the `users` collection are created on first use. A collection is a SurrealDB table, a database is a SurrealDB database, and `_id` is the record id.

## Read the same data with SurrealQL

Because a collection is a table, SurrealQL can query anything the driver writes. A document with the string `_id` of `"a"` in `accounts` is the record `accounts:a`.

```surql
/**[test]

[[test.results]]
error = false

[[test.results]]
error = false

[[test.results]]
value = '''
[
	{ balance: 500, id: accounts:a },
	{ balance: 100, id: accounts:b }
]'''

*/
-- Setup: the records the driver writes for the _id values "a" and "b"
CREATE accounts:a SET balance = 500;
CREATE accounts:b SET balance = 100;

SELECT * FROM accounts ORDER BY id;
```

```surql title="Output"
[
	{ balance: 500, id: accounts:a },
	{ balance: 100, id: accounts:b }
]
```

An `_id` made by the driver is an `ObjectId`, which is stored as an object, so the record id of such a document is written ``accounts:{ "$oid": '6b04f57ec6c0c248417c0f7f' }``. [Differences from MongoDB](/docs/libraries/mongodb-driver/differences) lists how each `_id` type is stored.

## Use with Mongoose

Mongoose connects through its `setDriver()` extension point. `mongoose` is an optional peer dependency, and the adapter has its own entry point so importing `@surrealdb/mql` never loads it.

```ts
import mongoose from "mongoose";
import { mqlDriver } from "@surrealdb/mql/mongoose";

mongoose.setDriver(mqlDriver(mongoose));
await mongoose.connect("mongodb://root:secret@localhost:8000/app?namespace=docs");

const Author = mongoose.model("Author", new mongoose.Schema({ name: String }));
await Author.create({ name: "Ursula" });
```

Models, queries, `populate()`, sessions and `connection.transaction()` work. Mongoose features that need change streams raise the same errors as a direct call would.
