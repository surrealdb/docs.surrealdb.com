# MySQL wire protocol

<Since v="v4.0.0" />

The MySQL wire protocol listener lets MySQL clients and drivers, such as the `mysql` command-line client, JDBC, and the Python, Go, Node.js and PHP drivers, connect to SurrealDB and run queries. A connection speaks the MySQL dialect of SQL by default, so queries written for MySQL 8.0 run against SurrealDB tables.

> [!IMPORTANT]
> The listener is in binaries built with the `mysql` feature. This feature is not in the default feature set. A binary built without it refuses to start when you pass `--mysql-bind`, with the error `The --mysql-bind option requires a binary built with the 'mysql' feature`.

## Start the listener

Pass [`--mysql-bind`](/docs/reference/cli/db/commands/start) with an address that is different from the HTTP server address:

```bash
surreal db start --user root --pass secret \
  --mysql-bind 127.0.0.1:3306 \
  memory
```

The environment variable `SURREAL_MYSQL_BIND` sets the same address.

Connect with the `mysql` client:

```bash
mysql --host 127.0.0.1 --port 3306 --user root --password=secret --database main/main
```

The database name selects the namespace and the database as **`ns/db`**, with a single slash. `USE ns/db` changes them on an open connection.

## Authentication

The listener verifies the password of a system user against the user's stored credentials. It offers these MySQL authentication plugins:

- **`caching_sha2_password`:** the default plugin of MySQL 8 clients.
- **`mysql_native_password`:** for older clients and drivers.
- **`mysql_clear_password`:** sends the password as clear text. Use it only over TLS.

For TLS, start the server with `--web-crt` and `--web-key`. The MySQL listener uses the same certificate as the HTTP server.

## Query languages

### MySQL SQL (default)

Every new connection uses the MySQL dialect. Tables that you create with SQL are SurrealDB tables, so SurrealQL and the other surfaces can read the same rows.

```sql
CREATE TABLE customer (id INT PRIMARY KEY, name VARCHAR(100), city VARCHAR(100));
INSERT INTO customer (id, name, city) VALUES (1, 'Ada', 'London'), (2, 'Bob', 'Paris');
SELECT city, COUNT(*) AS customers FROM customer GROUP BY city;
```

### Other dialects

A connection can change its dialect with `SET dialect`:

| Statement | Dialect |
| --- | --- |
| `SET dialect = 'mysql'` | MySQL SQL (the default). `'sql'` selects the same dialect. |
| `SET dialect = 'surrealql'` | SurrealQL. `'surql'` selects the same dialect. |
| `SET dialect = 'pgsql'` | The [PostgreSQL dialect](/docs/reference/rest-api/postgres-protocol#postgresql-sql-optional-dialect). `'postgres'` and `'postgresql'` select the same dialect. |
| `SET dialect = 'gql'` | [ISO GQL](/docs/learn/querying/gql/overview) |

Each dialect needs its route capability: `mysql` for MySQL SQL and SurrealQL, `postgres` for the PostgreSQL dialect, and `gql` for GQL. If the server denies the route, the `SET dialect` statement fails.

## Supported SQL

| Supported | Not supported yet |
| --- | --- |
| `SELECT` with joins, `WHERE`, `GROUP BY`, `HAVING`, `ORDER BY` and `LIMIT` | Window functions (`OVER (...)`) |
| Aggregate functions | Recursive common table expressions |
| Non-recursive common table expressions (`WITH`) | `ALTER TABLE` |
| `INSERT`, `UPDATE`, `DELETE` and `TRUNCATE` | `LOAD DATA` |
| `INSERT ... ON DUPLICATE KEY UPDATE` | Schema listing through `information_schema` |
| `CREATE TABLE` and `DROP TABLE` | |
| `START TRANSACTION`, `COMMIT` and `ROLLBACK` | |
| Prepared statements | |
| `SHOW DATABASES`, `SHOW TABLES`, `SHOW COLUMNS`, `SHOW INDEX` and `SHOW VARIABLES` | |

To list tables and columns, use `SHOW TABLES` and `SHOW COLUMNS`.

## Errors

The listener returns MySQL error numbers, so drivers report errors as they do for MySQL:

| Error | When |
| --- | --- |
| `1064` (`42000`) | The statement does not parse as MySQL SQL. |
| `1235` (`42000`) | The statement uses a feature that is not supported yet, such as a window function. |
| `1045` (`28000`) | Authentication fails, or the user is not allowed to query in the selected dialect. |
| `1105` (`HY000`) | Other errors from the database. |

An unsupported statement fails before it changes data.

## Capabilities and security

Connections are gated like other query surfaces:

- **Route:** the route name **`mysql`** is controlled with [`--allow-http`](/docs/reference/cli/db/commands/start) and [`--deny-http`](/docs/reference/cli/db/commands/start).
- **Arbitrary queries:** [`--allow-arbitrary-query`](/docs/learn/security/authorization/capabilities#arbitrary-queries) and [`--deny-arbitrary-query`](/docs/learn/security/authorization/capabilities#arbitrary-queries) apply to `guest`, `record` and `system` users.
- **Limits:** the listener accepts at most 1,024 connections, and refuses a packet that is larger than `max_allowed_packet` with error `1153`.
