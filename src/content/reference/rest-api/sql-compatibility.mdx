# PostgreSQL and MySQL compatibility matrix

<Since v="v4.0.0" />

> [!NOTE]
> SurrealDB is working towards full compatibility with PostgreSQL and MySQL. Coming releases will close the gaps that this matrix lists, and the matrix is updated with each release.

This page compares, feature by feature, what SurrealDB 4 runs for PostgreSQL clients and for MySQL clients. Both listeners run a defined subset of their dialect through the same query planner as SurrealQL, over the same tables. A statement outside the subset is refused with the error code of the original database, before it changes any data. The [Postgres wire protocol](/docs/reference/rest-api/postgres-protocol) and [MySQL wire protocol](/docs/reference/rest-api/mysql-protocol) pages describe each listener in full, and each row below links back to them by name.

The matrix applies to the PostgreSQL dialect, which every connection to the Postgres listener runs, and to the MySQL dialect, which every connection to the MySQL listener runs. The functions of the PostgreSQL dialect are tested against PostgreSQL 18, and the functions of the MySQL dialect against MySQL 8.4.

## How to read the matrix

Each cell starts with a verdict, followed by the detail:

| Verdict | Meaning |
| --- | --- |
| <Verdict value="supported" /> | The statement runs as it does in the original database, apart from the differences the cell lists. |
| <Verdict value="partial" /> | Some forms run and others are refused. The cell lists both. |
| <Verdict value="differs" /> | The statement runs, and the result or the behaviour is not the one the original database gives. |
| <Verdict value="refused" /> | The statement fails with the error code the cell names, before it changes any data. |
| <Verdict value="not-supported" /> | The dialect does not run the statement. |
| <Verdict value="not-documented" /> | The protocol pages do not cover the feature, so the matrix makes no claim about it. |
| <Verdict value="not-applicable" /> | The original database has no such feature. |

## Connecting

| Feature | PostgreSQL | MySQL |
| --- | --- | --- |
| Protocol | <Verdict value="supported" /> Protocol v3.0 with the simple and extended query flows, prepared statements, interactive transactions, cancellation and optional TLS. Available since 3.3. | <Verdict value="supported" /> Plain and prepared statements, statements sent several at a time, and the statements that drivers send while they connect. New in 4.0. |
| Enabling the listener | **Opt-in**. `--postgres-bind` or `SURREAL_POSTGRES_BIND`, on its own address. | **Opt-in**. `--mysql-bind` or `SURREAL_MYSQL_BIND`, on its own address. |
| Default language | **PostgreSQL SQL**. From 4.0, every connection runs the PostgreSQL dialect, and `SET dialect = 'gql'` switches to ISO GQL. SurrealQL is not available over this listener: `SET dialect = 'surrealql'` is refused with `0A000`. Before 4.0, a connection runs SurrealQL. | **MySQL SQL**. `SET dialect = 'gql'` switches to ISO GQL. SurrealQL and the PostgreSQL dialect are not available over this listener: `SET dialect = 'surrealql'` and `SET dialect = 'pgsql'` fail with `1045`. |
| Namespace and database | <Verdict value="supported" /> The database name is `ns/db`, with a single slash. | <Verdict value="supported" /> The database name is `ns/db`, with a single slash, and `USE ns/db` changes both on an open connection. |
| Authentication | <Verdict value="supported" /> `SCRAM-SHA-256` when the user has verifier material, otherwise a cleartext password. A SurrealDB token can be sent as the password. MD5 is not supported, and a failed sign-in returns `28P01`. | <Verdict value="supported" /> `caching_sha2_password`, `mysql_native_password` and `mysql_clear_password`. `caching_sha2_password` works over TLS, and over plaintext with the server's RSA public key, so the `mysql` client needs `--get-server-public-key` over plaintext. `mysql_native_password` is verified directly only for a user who signed in earlier since the server started, and otherwise switches to `mysql_clear_password`. A sign-in that sends the password as clear text needs TLS or a loopback address. |
| TLS | <Verdict value="supported" /> The listener uses the certificate and key of the HTTP server, and advertises the `postgresql` ALPN protocol, so libpq 17 clients connect with `sslmode=require`. | <Verdict value="supported" /> The listener uses the certificate and key of the HTTP server. The default authentication method of MySQL 8 clients works over TLS. |
| Record IDs in results | <Verdict value="differs" /> A record ID is sent as its key, as a SQL client expects a primary key to be: `person:1` is sent as `1`. | <Verdict value="differs" /> A record ID is sent as its key: `person:1` is sent as `1`. |
| Client tools | <Verdict value="partial" /> `pg_isready` works, and `pgbench` runs custom scripts and the initialisation steps except the data load. In `psql`, `\l`, `\dt`, `\dn`, `\du` and `\di` work, and `\d` with a table name does not complete yet. `pg_dump` does not work yet. | <Verdict value="partial" /> `mysqladmin` and `mysqlslap` run. `mysqldump` runs with `--no-tablespaces` and `--skip-lock-tables`, and its structure section holds the SurrealQL definition, so pass `--no-create-info` to dump the rows only. |

## Queries

| Feature | PostgreSQL | MySQL |
| --- | --- | --- |
| Joins | <Verdict value="partial" /> Joins run, including `LEFT JOIN`. `FULL OUTER JOIN` is refused with `0A000`. From 4.0.1, a `LATERAL` subquery can read a table, filter, sort, limit and aggregate, and runs in a `CROSS JOIN`, an inner join or a `LEFT JOIN ... ON true`. A `LEFT JOIN LATERAL` on another condition, a `RIGHT` or `FULL` join and `USING` are refused with `0A000`. Before 4.0.1, a lateral subquery runs only in a `CROSS JOIN` or an inner join, as a `SELECT` of expressions with no other clause. | <Verdict value="partial" /> `SELECT` with joins runs, with `WHERE`, `GROUP BY`, `HAVING`, `ORDER BY` and `LIMIT`. A `LATERAL` subquery fails with `1064`. |
| Aggregates and grouping | <Verdict value="partial" /> Aggregates, `GROUP BY` and `HAVING` run. From 4.0.1, an aggregate call takes an `ORDER BY`, and two aggregates of one query that ask for different orders are refused with `0A000`. Before 4.0.1, an `ORDER BY` inside an aggregate call fails with `42601`. A column that is neither grouped nor aggregated is not refused, and in the select list it returns the values of its group as an array, unless, from 4.0.1, it is an expression over the grouped columns or a column of a table whose primary key is grouped. An aggregate in `WHERE` is not refused, and an aggregate in `GROUP BY` fails with `42803`. | <Verdict value="partial" /> Aggregate functions, `GROUP BY` and `HAVING` run. An aggregate in `WHERE` is not refused, and an `ORDER BY` inside `GROUP_CONCAT` fails with `1064`. |
| Common table expressions | <Verdict value="partial" /> Non-recursive `WITH` queries run. From 4.0.1, the `WITH` clause of a `SELECT` can hold `INSERT`, `UPDATE` and `DELETE` statements, and a part of the query that reads a table one of them wrote is refused with `0A000`. Recursive common table expressions are refused with `0A000`. | <Verdict value="partial" /> Non-recursive `WITH` queries run. Recursive common table expressions are refused with `1235`, before the statement changes any data. |
| Window functions | <Verdict value="partial" /> Ranking, offset and aggregate window functions run, with `PARTITION BY`, `ORDER BY`, a named `WINDOW` clause, `ROWS` frames and `RANGE` frames bounded by `UNBOUNDED` or `CURRENT ROW`. `GROUPS` frames, `EXCLUDE`, `RANGE` frames with a numeric offset and `DISTINCT` inside the call are refused with `0A000`. A window function in `WHERE` is `42P20`. | <Verdict value="partial" /> Window functions run as they do over the PostgreSQL dialect. The forms that dialect refuses, such as `GROUPS` frames and `DISTINCT` inside the call, are refused with `1235`. A window function in `WHERE` is `3593`. |
| Set operations | <Verdict value="partial" /> `UNION`, `INTERSECT` and `EXCEPT` run. `INTERSECT ALL` and `EXCEPT ALL` are refused with `0A000`, and so are `INTERSECT` and `EXCEPT` with `*` in either query, inside a subquery used as a value, or with `IN` or `EXISTS`. Before 4.0.1, a chain of three or more `INTERSECT` or `EXCEPT` queries is refused as well, and parentheses in a chain are ignored. | <Verdict value="partial" /> The PostgreSQL dialect's limits apply, with `1235`. Text is compared exactly, so `SELECT 'a' INTERSECT SELECT 'A'` answers no rows, where MySQL's default collation ignores letter case. |
| Subqueries as a value | <Verdict value="partial" /> A subquery used as a single value fails when it returns more than one row or selects more than one column, under `P0001` and not PostgreSQL's `21000`. `IN`, `= ANY` and `EXISTS` accept any number of rows. `ALL` and `ANY` over a subquery with `GROUP BY`, `HAVING`, `LIMIT`, `OFFSET` or a set operation are refused. | <Verdict value="partial" /> A subquery used as a single value fails when it returns more than one row, with `1644`. The dialect shares its planner with the PostgreSQL dialect, so the same limits apply. |
| `LIKE` | <Verdict value="partial" /> Works in a `SELECT`, with `\%` and `\_` as literals, whether the pattern is written in the query, bound as a parameter or read from a column. `LIKE ... ESCAPE` is refused. | <Verdict value="partial" /> Works in a `SELECT`. `LIKE ... ESCAPE` is refused, and `e` and `é` are not equal in a comparison. |
| Columns in a join | <Verdict value="differs" /> In a table with declared columns, an undeclared column fails with `42703`. In a schemaless table, a column named without its table is read from the first table that has a value for it, so qualify the column to choose the table. | <Verdict value="differs" /> The dialect shares its planner with the PostgreSQL dialect, so a column named without its table in a join of schemaless tables is read from the first table that has a value for it. |
| `t.*` | <Verdict value="partial" /> `u.*` over a table or a derived table returns what `SELECT *` returns. In a join, `t.*` of a table with undeclared columns fails with `0A000`. Inside a function call, in `RETURNING`, in `CREATE VIEW` and beside another item in an `INSERT` query it is refused. | <Verdict value="partial" /> Behaves as it does over the PostgreSQL dialect, which shares the planner. |
| Generated rows | <Verdict value="partial" /> `generate_series(start, stop)` works in the select list. The form with a step, and `generate_series` or another set-returning function in `FROM`, are refused. | <Verdict value="not-documented" /> |
| Query nesting | <Verdict value="refused" /> A `FROM` clause of more than about 120 tables, joins nested in more than about 120 parentheses, or subqueries nested more than about 60 deep fail with `42601`. | <Verdict value="refused" /> A `FROM` clause that nests too deeply fails with `1064`. |
| Parameters | <Verdict value="supported" /> `$1`, `$2` and so on, in the extended query protocol. | <Verdict value="partial" /> A `?` placeholder is accepted only in a prepared statement. |
| Prepared statements in SQL | <Verdict value="supported" /> `PREPARE`, `EXECUTE` and `DEALLOCATE` work on the connection. A name already in use fails with `42P05`, and an unknown name with `26000`. | <Verdict value="supported" /> `PREPARE ... FROM`, `EXECUTE ... USING` and `DEALLOCATE PREPARE` work, and so do user variables such as `SET @a = 1`. `EXECUTE` of an unknown name fails with `1243`. |
| Query modifiers | <Verdict value="not-applicable" /> | <Verdict value="partial" /> `SQL_CALC_FOUND_ROWS` is refused. `SQL_NO_CACHE`, `SQL_CACHE`, `SQL_SMALL_RESULT`, `SQL_BIG_RESULT`, `SQL_BUFFER_RESULT` and `HIGH_PRIORITY` are accepted and ignored. |

## Writes

| Feature | PostgreSQL | MySQL |
| --- | --- | --- |
| `INSERT` | <Verdict value="supported" /> Multi-row `INSERT`, `ON CONFLICT` and `RETURNING` run. From 4.0.1, `INSERT ... SELECT` writes each item of the query to the column at its position, and its query can order, limit, group and join. Before 4.0.1, each item is written to the column of the same name, and a query that reads from a join or a subquery is refused with `0A000`. From 4.0.1, `INSERT ... VALUES` without a column list is refused with `0A000`. | <Verdict value="supported" /> Multi-row `INSERT` and `INSERT ... ON DUPLICATE KEY UPDATE` run. An `INSERT` that gives an `AUTO_INCREMENT` primary key `NULL` is refused, where MySQL numbers the row. From 4.0.1, `INSERT ... VALUES` and `REPLACE ... VALUES` without a column list are refused with `1235`. |
| `UPDATE` and `DELETE` | <Verdict value="partial" /> `UPDATE` and `DELETE` run. From 4.0.1, `UPDATE ... FROM`, `DELETE ... USING`, a `WITH` clause in front of a write, and subqueries in the condition, the values and the `RETURNING` list of a write run. A subquery that reads a column of the row being written is refused with `0A000` before the statement changes anything. Before 4.0.1, all of these are refused. | <Verdict value="supported" /> `UPDATE` and `DELETE` run. |
| `LIKE` and `\|\|` in a write | <Verdict value="refused" /> The `\|\|` and `LIKE` operators are refused with `0A000` in an `INSERT`, `UPDATE` or `DELETE`, including in its `WHERE` clause, so `DELETE FROM t WHERE name LIKE 'a%'` fails before it deletes anything. Functions such as `substring`, `ltrim`, `concat` and `extract` work. | <Verdict value="refused" /> `LIKE` is refused with `1235` in an `INSERT`, `UPDATE` or `DELETE`, including in its `WHERE` clause. Functions such as `SUBSTRING`, `LTRIM` and `CONCAT` work. |
| `TRUNCATE` | <Verdict value="supported" /> Takes a list of tables. A `serial` column keeps its count, as PostgreSQL's default `CONTINUE IDENTITY` does, and `TRUNCATE ... RESTART IDENTITY` starts it again from 1. | <Verdict value="partial" /> Starts the `AUTO_INCREMENT` numbering again from 1. It keeps the records that the table's permissions do not let the user delete, and still answers OK. A user who may delete records but not define a sequence is refused `TRUNCATE` of a table with an `AUTO_INCREMENT` column. |
| Constraint violations | <Verdict value="supported" /> A `UNIQUE` or primary key conflict is `23505`, a missing value is `23502` and a missing foreign key target is `23503`. | <Verdict value="supported" /> A `UNIQUE` or primary key conflict is `1062`, `NULL` for a required field is `1048` and an omitted required field is `1364`. |
| Value length | <Verdict value="supported" /> A value too long for a `varchar(n)` column is refused with `22001`, and a `numeric(p,s)` column rounds a value to its scale. | <Verdict value="supported" /> A value too long for a `VARCHAR(n)` column is refused with `1406`. |

## Schema and DDL

| Feature | PostgreSQL | MySQL |
| --- | --- | --- |
| `CREATE TABLE` and `DROP TABLE` | <Verdict value="supported" /> A statement for several tables is answered once. If one part fails, nothing of the statement is kept, so `DROP TABLE a, missing` fails and keeps `a`. | <Verdict value="supported" /> A statement for several tables is answered with one OK packet, and if one part fails nothing of the statement is kept. |
| `ALTER TABLE` | <Verdict value="partial" /> `ALTER TABLE` with several actions runs, including `ADD FOREIGN KEY` and `DROP CONSTRAINT` with the names that `pg_constraint` lists. `RENAME COLUMN` answers with its command tag and changes nothing. | <Verdict value="not-supported" /> |
| Foreign keys | <Verdict value="supported" /> `REFERENCES` or `FOREIGN KEY` makes the column a record link to the other table. A write whose key names no record fails with `23503`. | <Verdict value="not-supported" /> `CREATE TABLE` with a `FOREIGN KEY` constraint fails with `1105`. |
| Indexes and keys | <Verdict value="supported" /> `CREATE INDEX` defines indexes, including `hnsw` indexes for pgvector. An `int` primary key makes the record ID key an `i32`. | <Verdict value="supported" /> `UNIQUE` indexes and primary keys are enforced. `SHOW INDEX` lists them with MySQL's 15 columns, and `Cardinality` is `NULL`. |
| Views and other objects | <Verdict value="partial" /> `CREATE VIEW` over one table with a projection and a filter holds the rows that pass the filter, and stays up to date after every write to the table. From 4.0.1, a column list names the columns, a query that a view cannot keep up to date, such as a join or `GROUP BY`, is refused with `0A000`, and `CREATE MATERIALIZED VIEW` defines a view that is always up to date, so `REFRESH MATERIALIZED VIEW` changes nothing. Before 4.0.1, a column list is ignored, a view over a join fails, and `CREATE MATERIALIZED VIEW` does not parse. `DROP VIEW` answers with the tag `DROP TABLE`. `CREATE EXTENSION vector` is accepted and defines nothing, and any other extension fails with `58P01`. `CREATE FUNCTION` does not parse. | <Verdict value="not-documented" /> |
| Schemas | <Verdict value="partial" /> The schema `public` is the selected database. `DROP SCHEMA public CASCADE` removes every table of the database in one all-or-nothing statement. `CREATE SCHEMA` answers with its command tag and changes nothing, and no other schema exists. | <Verdict value="differs" /> A database is named `ns/db`, and a statement that names a table in another database is refused. |
| User-defined types | <Verdict value="supported" /> `CREATE TYPE ... AS ENUM`, `CREATE DOMAIN` and `CREATE TYPE ... AS (...)` each define a named type. An enum column orders its values in declaration order, and a domain checks each `CHECK`. | <Verdict value="supported" /> An `ENUM('s','m','l')` column refuses any other value with `1366`, and orders its values in the order the column lists them. |
| Generated keys | <Verdict value="supported" /> A `serial` or `bigserial` column draws its numbers from a sequence. A table created again after `DROP TABLE` numbers its rows from 1. | <Verdict value="supported" /> An `AUTO_INCREMENT` column draws its numbers from a sequence and is `NOT NULL`. A table created again after `DROP TABLE` numbers its rows from 1. |
| DDL inside a transaction | <Verdict value="supported" /> DDL runs inside the open transaction, and `ROLLBACK` takes it back. | <Verdict value="differs" /> As in MySQL, `CREATE`, `ALTER`, `DROP`, `TRUNCATE` and `RENAME` first commit the open transaction and then run on their own, so `ROLLBACK` does not take back a `CREATE TABLE`. |
| Declared columns | <Verdict value="supported" /> A table declared with `CREATE TABLE` or `DEFINE TABLE ... SCHEMAFULL` is checked as PostgreSQL checks a table. `SELECT *` lists `id` first and then the other columns by name, not in declaration order. | <Verdict value="supported" /> `CREATE TABLE` declares the columns. Columns and indexes are listed by name, not in the order they were defined. |

## Transactions

| Feature | PostgreSQL | MySQL |
| --- | --- | --- |
| Interactive transactions | <Verdict value="supported" /> `BEGIN`, `COMMIT` and `ROLLBACK`, with PostgreSQL's ready-for-query status bytes. After an error in a block, commands receive `25P02` until `COMMIT` or `ROLLBACK`. | <Verdict value="supported" /> `START TRANSACTION` or `BEGIN`, `COMMIT` and `ROLLBACK`. `SET autocommit = 0` makes each statement run in a transaction until `COMMIT`. |
| Autocommit | <Verdict value="differs" /> Each top-level statement outside `BEGIN ... COMMIT` commits on its own, and in a simple query of several statements outside a transaction block, a failing statement does not stop the statements after it. Wrap statements in a transaction for all-or-nothing behaviour. | <Verdict value="supported" /> Each statement commits on its own until `SET autocommit = 0`. |
| Savepoints | <Verdict value="supported" /> `SAVEPOINT`, `RELEASE SAVEPOINT` and `ROLLBACK TO SAVEPOINT` work in a transaction block, and `SET LOCAL` settings are undone on rollback. | <Verdict value="supported" /> `SAVEPOINT` works in a transaction. |
| Isolation levels | <Verdict value="partial" /> `SERIALIZABLE` opens a serializable transaction on the storage engines that offer one, and fails with `0A000` on the others. `REPEATABLE READ` and a plain `BEGIN` run at snapshot isolation. `READ COMMITTED` and `READ UNCOMMITTED` are refused with `0A000`. `BEGIN READ ONLY` is applied. | <Verdict value="not-documented" /> |
| Conflicts | <Verdict value="supported" /> A transaction that conflicts with another fails with `40001`. Retry it. | <Verdict value="supported" /> A transaction that conflicts with another fails with `1213`. Retry it. |

## Types and values

| Feature | PostgreSQL | MySQL |
| --- | --- | --- |
| Sized numbers | <Verdict value="supported" /> `smallint`, `integer`, `bigint`, `real` and `double precision` define fields of the types `i16`, `i32`, `int`, `f32` and `float`. The catalog lists an `int` column as `integer` (`int4`). | <Verdict value="supported" /> `TINYINT` is `i8`, `SMALLINT` is `i16`, `MEDIUMINT` and `INT` are `i32`, `BIGINT` is `int`, `INT UNSIGNED` is `u32`, `FLOAT` is `f32` and `DOUBLE` is `float`. |
| Decimals | <Verdict value="supported" /> A `numeric` column with a precision above 28, or with none, defines a `bigdecimal` field. | <Verdict value="supported" /> A `DECIMAL` column with a precision above 28 defines a `bigdecimal` field. `CAST(x AS UNSIGNED)` of a constant wraps a negative integer to the top of the unsigned range, as in MySQL, and of a negative value read from a column fails with `1366`. |
| Out-of-range and mistyped values | <Verdict value="differs" /> A value out of range, such as `40000` for a `smallint`, is refused with `42804`. SurrealDB refuses text for a number field, even `'5'`, where PostgreSQL accepts it or reports `22P02`. | <Verdict value="differs" /> A value out of range, such as `300` for a `TINYINT` or `-1` for an `INT UNSIGNED`, is refused with `1366`. SurrealDB refuses some values that MySQL converts, such as `'5'` or `true` for an `INT` column. |
| Typed literals | <Verdict value="partial" /> Write a typed value as a cast, such as `'2026-01-01'::date`. The `DATE '2026-01-01'` form does not parse, and a plain string is not converted to a `date` column. | <Verdict value="partial" /> `DATE_ADD(d, INTERVAL 1 DAY)` and the other `INTERVAL` forms run. Compound interval units such as `DAY_HOUR` are refused with `1235`. |
| Result column types | <Verdict value="differs" /> A result column is announced as a type that all its values have. An integer constant is announced as `bigint`, where PostgreSQL announces `integer` when the value fits one. `floor(1.5)` is a float here and `numeric` in PostgreSQL, and a `CASE` over a number and a text answers text where PostgreSQL refuses it. An arithmetic expression over two fields with no declared type is announced as `bigint`. | <Verdict value="differs" /> A column without an alias is named by its expression as written, as in MySQL. In a batch of several statements, only the first statement keeps its column names, and unnamed or repeated columns of later statements are named `?column?1`, `?column?2` and so on. |
| Arrays | <Verdict value="partial" /> From 4.0.1, the array operators `@>`, `<@` and `&&` compare arrays as sets, with a column, a parameter, a cast or a subquery on each side. An array written as a text literal and the `ARRAY[...]` constructor are refused with `0A000`. Before 4.0.1, the three operators are refused as well. | <Verdict value="not-applicable" /> |
| Vectors | <Verdict value="supported" /> `vector(n)` columns, distance operators and `hnsw` indexes, as described under [pgvector](#pgvector). | <Verdict value="not-applicable" /> |

## Functions

| Feature | PostgreSQL | MySQL |
| --- | --- | --- |
| Built-in functions | <Verdict value="partial" /> The implemented functions are tested against PostgreSQL 18, including the keyword forms `extract(year FROM d)`, `position('b' IN s)`, `substring(s FROM 2 FOR 3)` and `overlay`. A function that does not exist fails with `42883`. | <Verdict value="partial" /> The implemented functions are tested against MySQL 8.4, including `EXTRACT(YEAR FROM d)`, `POSITION('b' IN s)`, `SUBSTRING(s FROM 2 FOR 3)` and `INTERVAL` arithmetic. `LENGTH` counts bytes. `CAST(x AS UNSIGNED)` of a text read from a column that is not a number, such as `'12abc'`, fails with `1366`. A function that does not exist fails with `1305`. |
| SurrealQL functions | <Verdict value="not-supported" /> The PostgreSQL dialect calls SQL functions only, so `http::get` and `fn::` functions are unavailable. Switch the dialect to SurrealQL to call them. | <Verdict value="not-supported" /> The MySQL dialect calls SQL functions only. Switch the dialect to SurrealQL to call SurrealQL functions. |
| Date arithmetic | <Verdict value="supported" /> Date functions such as `date_trunc` run. An unknown unit fails with `22023`. | <Verdict value="partial" /> `TIMESTAMPDIFF` with the unit `MONTH`, and compound interval units such as `DAY_HOUR`, are refused with `1235`. |
| Restricted functions | <Verdict value="differs" /> A `LIKE` pattern that is not written in the query uses `string::replace` and `string::concat`, so an instance that [restricts functions](/docs/learn/security/authorization/capabilities#functions) must allow those two. | <Verdict value="differs" /> An instance that denies built-in functions refuses the `SHOW` and `DESCRIBE` statements. |

## Introspection

| Feature | PostgreSQL | MySQL |
| --- | --- | --- |
| Catalog relations | <Verdict value="supported" /> `information_schema.tables`, `information_schema.columns`, `pg_class`, `pg_attribute`, `pg_constraint`, `pg_index` and the other catalog relations that drivers and ORMs read list the tables of the database, in the schema `public`. A table without declared columns lists only `id`. From 4.0.1, `pg_matviews` lists the materialised views, and before 4.0.1 it has no rows. | <Verdict value="differs" /> `information_schema` lists the tables and declared columns in PostgreSQL's form: the tables are in the schema `public`, `data_type` holds PostgreSQL type names and `column_type` is `NULL`, so `WHERE table_schema = DATABASE()` finds none. |
| `SHOW` and `DESCRIBE` | <Verdict value="partial" /> `SHOW` and `RESET` are supported. | <Verdict value="supported" /> `SHOW TABLES`, `COLUMNS`, `FIELDS`, `INDEX`, `KEYS`, `DATABASES`, `VARIABLES`, `ENGINES`, `COLLATION` and `CHARACTER SET`, and `DESCRIBE`, answer with the column names, order and types of MySQL 8.4. `SHOW TABLE STATUS` answers with MySQL's 18 columns. `SHOW STATUS`, `PROCESSLIST`, `WARNINGS`, `ERRORS` and `TRIGGERS` answer with MySQL's columns and no rows. |
| `SHOW CREATE TABLE` | <Verdict value="not-documented" /> | <Verdict value="differs" /> Returns the SurrealQL definition, not MySQL DDL. |
| System variables | <Verdict value="partial" /> `SET`, `SET LOCAL` and `SHOW` work. `SET hnsw.ef_search` is accepted and has no effect. | <Verdict value="partial" /> `@@name`, `@@session.name`, `@@local.name` and `@@global.name` read the same fixed value, and a `SET` does not change it. A name that MySQL 8.4 or 8.0.35 does not have fails with `1193`. Variables that describe the host read `NULL`. |

| Feature | PostgreSQL | MySQL |

| Bulk load and export | <Verdict value="partial" /> `COPY ... FROM STDIN` and `COPY ... TO STDOUT` run in the text and CSV formats. Name the columns in `COPY ... FROM STDIN`. `COPY ... FROM` into a vector column does not convert text to a vector. | <Verdict value="not-supported" /> `LOAD DATA` is not supported yet. |

## pgvector

The PostgreSQL dialect accepts the column type, the distance operators and the `hnsw` indexes of the [pgvector](https://github.com/pgvector/pgvector) extension. The MySQL dialect has no vector type. The [PostgreSQL protocol page](/docs/reference/rest-api/postgres-protocol#pgvector) describes each part in detail.

| Feature | Verdict and detail |
| --- | --- |
| `vector(n)` columns | <Verdict value="supported" /> A field of type `array<float, n>`, up to 16,000 dimensions. A column without `(n)` is refused with `0A000`. Drivers see the `vector` type in the text and binary formats, so the pgvector packages for psycopg, asyncpg and node-postgres find it. |
| Distances | <Verdict value="supported" /> `<->` is `l2_distance`, `<=>` is `cosine_distance`, `<#>` is `vector_negative_inner_product` and `<+>` is `l1_distance`. `inner_product` returns the inner product itself. Vectors of different dimensions fail with `22000`. |
| `hnsw` indexes | <Verdict value="supported" /> `CREATE INDEX ... USING hnsw` with `vector_l2_ops`, `vector_cosine_ops`, `vector_ip_ops` or `vector_l1_ops`. `WITH (m, ef_construction)` takes pgvector's defaults and limits, and an index covers at most 2,000 dimensions. |
| Nearest-neighbour search | <Verdict value="supported" /> `ORDER BY column <op> value LIMIT k` over one table is answered from the index when the column has exactly one index that ranks by the same distance, and by an exact search otherwise. |
| `halfvec`, `sparsevec`, `bit`, `ivfflat` | <Verdict value="not-supported" /> |
| Other `hnsw` forms | <Verdict value="refused" /> Partial, unique, multi-column and expression indexes are refused with `0A000`. |
| `hnsw.ef_search` | <Verdict value="differs" /> `SET hnsw.ef_search` is accepted, and the search uses an `ef` of 40, or `k` when it is larger. |
| Bound limit | <Verdict value="differs" /> `LIMIT $1` sorts every row. Write `k` in the query to use the index. |
| Distance in a write | <Verdict value="refused" /> A distance operator or function in an `INSERT`, `UPDATE` or `DELETE` is refused with `0A000`. |
| Vector utilities | <Verdict value="not-supported" /> `DROP EXTENSION`, `vector_dims`, `vector_norm`, `l2_normalize`, vector arithmetic and `avg` over a vector column. |

## Refusal codes

Features that a dialect does not run are refused with one code, so a client can tell a refusal from a syntax error:

| Listener | Code | Reported when |
| --- | --- | --- |
| PostgreSQL | `0A000` (`feature_not_supported`) | The statement uses a feature that SurrealDB does not support, such as a `GROUPS` window frame, a recursive common table expression or `INTERSECT ALL`. |
| PostgreSQL | `42601` (`syntax_error`) | The statement does not parse, such as `CREATE FUNCTION`, or exceeds a nesting limit. |
| MySQL | `1235` | The statement uses a feature that SurrealDB does not support, such as `DISTINCT` inside a window function or a recursive common table expression. |
| MySQL | `1064` | The statement does not parse, such as a `LATERAL` subquery, or a `FROM` clause nests too deeply. |

The full list of codes is in [Error codes](/docs/reference/rest-api/postgres-protocol#error-codes) on the Postgres page and [Error codes](/docs/reference/rest-api/mysql-protocol#error-codes) on the MySQL page.

## Limits and capabilities

- The `postgres` and `mysql` routes are [capabilities](/docs/learn/security/authorization/capabilities). `--deny-http postgres` and `--deny-http mysql` refuse every connection to the matching listener, and `SET dialect = 'gql'` needs the `gql` route.
- `--deny-arbitrary-query` applies to both listeners, as it does to the other query surfaces.
- The MySQL listener accepts at most 1,024 connections at a time and refuses further connections with error `1040`. A MySQL packet is limited to 64 MiB, and a larger packet is refused with error `1153`.
