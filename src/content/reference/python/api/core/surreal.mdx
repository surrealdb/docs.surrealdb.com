# `Surreal` / `AsyncSurreal` {#surreal}

`Surreal()` and `AsyncSurreal()` open a connection to SurrealDB and choose the connection class from the scheme of the URL. This page is the reference for every method and property of the connections they return. For explanations and longer examples, follow the links to the concept pages in each section.

`Surreal()` returns a blocking connection and `AsyncSurreal()` returns an asynchronous one, with the same methods. The examples on this page use a blocking connection. On an asynchronous connection, put `await` before each method call, including the methods that return a builder, such as `select()` and `query()`. Five methods are not awaited: `batch()`, `live_of()`, `subscribe()`, `timeout()` and `is_feature_supported()`. Properties such as `status` are read without `await`.

**Source:** [surrealdb.py](https://github.com/surrealdb/surrealdb.py)

## Factory functions {#factory-functions}

### `Surreal()` {#surreal-sync}

Open a blocking connection.

```python title="Syntax"
Surreal(
    url,
    *,
    streaming=True,
    ping_interval=30.0,
    ping_timeout=10.0,
    timeout=30.0,
    version_check=True,
    reconnect=True,
    auth=None,
    renew_access=True,
)
```

**Returns:** `BlockingSurrealConnection`, which is a `BlockingWsSurrealConnection`, `BlockingHttpSurrealConnection` or `BlockingEmbeddedSurrealConnection`, depending on the [URL scheme](#url-schemes).

### `AsyncSurreal()` {#surreal-async}

Open an asynchronous connection. It takes the same arguments as `Surreal()`, and `auth` can also be a coroutine function.

```python title="Syntax"
AsyncSurreal(url, *, ...)
```

**Returns:** `AsyncSurrealConnection`, which is an `AsyncWsSurrealConnection`, `AsyncHttpSurrealConnection` or `AsyncEmbeddedSurrealConnection`.

Both functions only build the connection object. A WebSocket connection opens its socket when you call [`connect()`](#connect), enter a `with` block, or send the first request.

```python
from surrealdb import AsyncSurreal, Surreal

db = Surreal("ws://localhost:8000")
adb = AsyncSurreal("ws://localhost:8000", timeout=10)
```

`Surreal` and `AsyncSurreal` are functions, so they cannot annotate a variable. Use the type aliases that the package exports:

```python
from surrealdb import AsyncSurrealConnection, BlockingSurrealConnection

def report(db: BlockingSurrealConnection) -> None: ...
```

```python title="Options"
from surrealdb import ReconnectOptions, Surreal

db = Surreal(
    "ws://localhost:8000",
    timeout=60,
    reconnect=ReconnectOptions(attempts=10, retry_delay_max=30.0),
    auth={"username": "root", "password": "secret"},
)
```

`ReconnectOptions` takes `enabled` (default `True`), `attempts` (default `5`, or `-1` for no limit), `retry_delay` (default `1.0`), `retry_delay_max` (default `60.0`), `retry_delay_multiplier` (default `2.0`) and `retry_delay_jitter` (default `0.1`). See [Connecting to SurrealDB](/docs/reference/python/concepts/connecting-to-surrealdb) for what a reconnect restores.

### URL schemes {#url-schemes}

| Scheme | Connection | Class |
| --- | --- | --- |
| `ws://`, `wss://` | WebSocket, with every feature | `BlockingWsSurrealConnection`, `AsyncWsSurrealConnection` |
| `http://`, `https://` | HTTP, one request at a time | `BlockingHttpSurrealConnection`, `AsyncHttpSurrealConnection` |
| `mem://`, `memory://`, `memory` | Embedded, in memory | `BlockingEmbeddedSurrealConnection`, `AsyncEmbeddedSurrealConnection` |
| `file://`, `surrealkv://` | Embedded, on disk | as above |
| `surrealkv+versioned://` | Embedded, on disk, with versioned records | as above |

The SDK adds `/rpc` to a remote URL, so `ws://localhost:8000` and `ws://localhost:8000/rpc` are the same address. An embedded URL needs the `embedded` extra: see [Embedded databases](/docs/reference/python/concepts/embedded-databases). An unknown scheme raises `UnsupportedEngineError`, and a URL that cannot be parsed raises `InvalidUrlError`.

## Connection methods

### `.connect()` {#connect}

Open the connection. A WebSocket opens its socket, and an embedded connection opens its engine. An HTTP connection keeps no connection open, so its `connect()` only asks the server for its version.

```python title="Syntax"
db.connect(url=None)
```

### `.version()` {#version}

Return the version of the server, or of the engine on an embedded connection.

**Returns:** `str`, such as `"surrealdb-4.0.0"`

### `.health()` {#health}

Ask the server's `/health` endpoint whether the server is healthy. A WebSocket connection asks over HTTP. Not available on an embedded connection.

```python title="Syntax"
db.health()
```

**Returns:** `None`. Raises `ConnectionUnavailableError` when the server is unhealthy or cannot be reached.

### `.timeout()` {#timeout}

Change how long each request waits for its reply, for the code inside a `with` block only. The block can be on a connection, a session or a transaction. On an asynchronous connection it is a plain `with`, and tasks started inside the block keep the value.

```python title="Syntax"
with db.timeout(seconds):
    ...
```

## Connection state

### `.status` and `.is_connected` {#status}

On a WebSocket connection, `status` is one of `"disconnected"`, `"connecting"`, `"reconnecting"` and `"connected"`. `is_connected` is `True` when `status` is `"connected"`. Both are properties. HTTP and embedded connections do not have them.

```python
if db.status == "reconnecting":
    print("Waiting for the server")
```

### `.subscribe()` {#subscribe}

Call a function each time a WebSocket connection changes state.

```python title="Syntax"
db.subscribe(event, listener)
```

            <th>Type</th>
            <th>Description</th>
        </tr>
    </thead>

            <td><code>str</code></td>

        </tr>
        <tr>
            <td><code>listener</code> <Label label="required" /></td>
            <td><code>Callable</code></td>
            <td>The function to call with the event's arguments. On an asynchronous connection it can be a coroutine function.</td>
        </tr>
    </tbody>
</table>

**Returns:** a function with no arguments that removes the listener.

| Event | Arguments |
| --- | --- |
| `"connecting"` | none |
| `"connected"` | the server version, such as `"4.0.0"` |
| `"reconnecting"` | none |
| `"disconnected"` | none |
| `"error"` | the exception, for example from a failed token renewal |
| `"auth"` | the new `Tokens`, or `None` after a sign-out, then the session id |
| `"using"` | the namespace, the database, then the session id |

The session id is `None` for the connection's own session. An exception in a listener is logged and does not stop the connection.

```python
unsubscribe = db.subscribe("reconnecting", lambda: print("Connection lost"))
unsubscribe()
```

### `.server_version` {#server-version}

The version the server reported when the connection opened, such as `"4.0.0"`, or `None` before that. A property.

### `.is_feature_supported()` {#is-feature-supported}

Return whether the server offers a feature. Call it after the connection has opened, because it reads the version the server reported.

```python title="Syntax"
db.is_feature_supported(feature)
```

### `.wire_format` {#wire-format}

The CBOR format the connection uses: `"cbor.2"` with SurrealDB 4.0 and later, `"cbor"` with earlier servers. A property. An HTTP connection reads `"cbor"` until the first reply arrives.

### `.namespace`, `.database` and `.token` {#session-state}

On a WebSocket connection, the namespace and database that its own session uses, and the access token it is signed in with. All three are properties.

### `.query()` {#query}

Build a SurrealQL query. Nothing is sent until you run the builder.

```python title="Syntax"
db.query(query, vars=None)
```

<table>
    <thead>
        <tr>
            <th>Parameter</th>
            <th>Type</th>
            <th>Description</th>
        </tr>
    </thead>
    <tbody>
        <tr>
            <td><code>query</code> <Label label="required" /></td>
            <td><code>str</code></td>
            <td>One or more SurrealQL statements.</td>
        </tr>
        <tr>
            <td><code>vars</code> <Label label="optional" /></td>

            <td>Variables for the query, read as <code>$name</code>. The SDK sends them as values, never as query text.</td>
        </tr>
    </tbody>

**Returns:** a [query builder](/docs/reference/python/api/core/builders#query-builder). Run it with one of these:

| Method | Returns |
| --- | --- |
| `.execute()` | `list[Value]`, one entry for each statement, also for one statement |
| `.first()` | The result of the first statement, or `None` when the query has no statements |
| `.into(cls)` | The statement results mapped in order onto the fields of `cls` |
| `.into(cls, rows=True)` | `list[cls]`, each record of the one statement mapped onto `cls` |
| `.rows()`, `.statements()`, `.stream()` | The results as they arrive: see [Streaming results](/docs/reference/python/concepts/streaming) |

On an asynchronous connection, `await db.query(...)` is the same as `await db.query(...).execute()`.

```python
db.query("RETURN 1; RETURN 2").execute()
```

```python title="Output"
[1, 2]
```

```python
people = db.query(
    "SELECT * FROM person WHERE age > $age",
    {"age": 18},
).first()
```

> [!NOTE]
> A `SELECT` without `ONLY` returns a list of records even when it names one record, so its result has two levels of lists: one for the statements and one for the records. `.first()` removes the outer one, and `ONLY` removes the inner one on the server.
>
> ```python
> db.query("SELECT name FROM person:tobie").execute()     # [[{'name': 'Tobie'}]]
> db.query("SELECT name FROM person:tobie").first()       # [{'name': 'Tobie'}]
> db.query("SELECT name FROM ONLY person:tobie").first()  # {'name': 'Tobie'}
> ```

### `.query_raw()` {#query-raw}

Run SurrealQL and return the raw response, with the status, time and result of each statement. A statement that fails is reported in the response, not raised.

```python title="Syntax"
db.query_raw(query, vars=None)
```

**Returns:** `dict[str, Any]`. Its `"result"` key holds one entry for each statement, each with `"status"` (`"OK"` or `"ERR"`), `"time"` and `"result"`.

```python
raw = db.query_raw("RETURN 1; THROW 'stop'")
for statement in raw["result"]:
    print(statement["status"], statement["result"])
```

```text title="Output"
OK 1
ERR An error occurred: stop
```

### `.batch()` {#batch}

Collect statements to send as one transaction in one request. All of them are applied, or none. Because nothing stays open on the server between requests, a batch works over HTTP, against SurrealDB 2.x, and in sessions. A transaction object has no `batch()`, because its statements already run in one transaction.

```python title="Syntax"
db.batch().query(query, vars=None).execute()
```

**Returns:** a [batch](/docs/reference/python/api/core/builders#batch). `.query()` adds statements and returns the batch. `.execute()` sends them and returns one result for each statement, or raises the error of the statement that failed.

```python
results = (
    db.batch()
    .query("UPDATE account:alice SET balance -= $amount", {"amount": 10})
    .query("UPDATE account:bob SET balance += $amount")
    .execute()
)
```

The statements share their variables, so a name bound twice must have the same value. Only the last statement can be a `RETURN`, and a statement that begins, commits or cancels a transaction is refused with `ValueError`.

## CRUD methods

The CRUD methods take a target, which decides what they work on:

| Target | Meaning | A read returns |
| --- | --- | --- |
| `RecordID("person", "tobie")` | One record | The record, or `None` |
| `StringRecordId("person:tobie")` | One record, written as SurrealQL text for the server to parse | The record, or `None` |
| `RecordID("person", Range(...))` | Every record in a range of ids | A list |
| `Table("person")` or `"person"` | Every record in the table | A list |

> [!IMPORTANT]
> A plain string is always a table name, also when it holds a colon. `db.select("person:tobie")` reads a table that is named `person:tobie`, and `db.create("person:tobie", data)` creates a record in that table. Use [`RecordID`](/docs/reference/python/api/values/record-id) or [`StringRecordId`](/docs/reference/python/api/values/record-id#stringrecordid) to name a record.

Each method returns a [CRUD builder](/docs/reference/python/api/core/builders#crud-builder). On a blocking connection, a write that you give its data runs at once and returns the result. `select()`, `delete()`, and a write without data return the builder, which you run with `.execute()`, with a data clause such as `.merge()`, or by iterating it. On an asynchronous connection, `await` runs every builder.

| Data clause | SurrealQL |
| --- | --- |
| `.content(data)` | `CONTENT`, the whole content. `create(target, data)` and `update(target, data)` use it. |
| `.replace(data)` | `REPLACE` |
| `.merge(data)` | `MERGE`, which keeps the fields that `data` does not name |
| `.patch(operations)` | `PATCH`, with a list of JSON Patch operations |

A builder also takes modifiers that become clauses of the statement: `.where(condition, variables)` on `select`, `update`, `upsert` and `delete`; `.fetch(*paths)`, `.limit(n)`, `.start(n)` and `.version(at)` on `select`; `.output(mode)` on the writes and `insert`; and `.timeout(duration)` on all of them. See [Data manipulation](/docs/reference/python/concepts/data-manipulation).

Every CRUD method except `relate()` takes `into=Model` as a keyword argument. It maps each returned record onto a dataclass, a pydantic model, or any class that takes the fields as keyword arguments.

### `.live()` {#live}

Start a live query on a table.

```python title="Syntax"
db.live(table, diff=False)
```

<table>
    <thead>
        <tr>
            <th>Parameter</th>
            <th>Type</th>
            <th>Description</th>
        </tr>
    </thead>
    <tbody>

```python
        print(change["action"], change["result"])
```

### `.live_of()` {#live-of}

Attach to a live query that was started some other way, such as with `LIVE SELECT` through `query()`. A reconnect does not restart it, because the connection does not know its definition. This method is not awaited.

```python title="Syntax"
db.live_of(live_id)
```

**Returns:** a [`LiveSubscription`](/docs/reference/python/api/core/live-subscription)

```python
live_id = db.query("LIVE SELECT * FROM person WHERE age > 18").first()
adults = db.live_of(live_id)
```

### `.subscribe_live()` {#subscribe-live}

Iterate the notifications of a live query by its id. Iterating a subscription gives the same notifications.

```python title="Syntax"
db.subscribe_live(query_uuid)
```

**Returns:** a generator of notifications. On an asynchronous connection, await the call to get an asynchronous generator: `async for change in await db.subscribe_live(live_id):`. Each notification is a `dict` with `action` (`"CREATE"`, `"UPDATE"` or `"DELETE"`), `result` (the record), `record` (its `RecordID`) and `id` (the live query id).

### `.kill()` {#kill}

Stop a live query. Iteration over its subscription ends.

```python title="Syntax"
db.kill(query_uuid)
```

**Returns:** `None`

## Transactions

Client-side transactions need a WebSocket connection and SurrealDB 3.0 or later. Over HTTP or against SurrealDB 2.x, use [`batch()`](#batch). See [Transactions](/docs/reference/python/concepts/transactions).

### `.begin_transaction()` {#begin-transaction}

Begin a transaction on the connection's own session, or on another session.

```python title="Syntax"
db.begin_transaction(session_id=None)
```

**Returns:** a [`BlockingSurrealTransaction`](/docs/reference/python/api/core/surreal-transaction), or an `AsyncSurrealTransaction` on an asynchronous connection

A transaction is a context manager that commits when the block finishes and cancels when the block raises an exception:

```python
with db.begin_transaction() as txn:
    txn.update(RecordID("account", "alice")).merge({"balance": 90})
    txn.update(RecordID("account", "bob")).merge({"balance": 60})
```

On an asynchronous connection, write `async with await db.begin_transaction() as txn:`.

### `.begin()` {#begin}

Begin a transaction and return its id, for use with the `txn_id=` keyword that the connection methods take. `begin_transaction()` does this and returns a transaction object.

```python title="Syntax"
db.begin(session_id=None)
```

**Returns:** `UUID`

### `.commit()` {#commit}

Apply the changes of a transaction that `begin()` started.

```python title="Syntax"
db.commit(txn_id, session_id=None)
```

**Returns:** `None`

### `.cancel()` {#cancel}

Discard the changes of a transaction that `begin()` started.

```python title="Syntax"
db.cancel(txn_id, session_id=None)
```

**Returns:** `None`

## Availability by connection type {#availability}

| Feature | WebSocket | HTTP | Embedded |
| --- | --- | --- | --- |
| Queries, CRUD, `relate()`, `run()`, `batch()` | Yes | Yes | Yes |
| `api()` | Yes | Yes | Yes |
| `gql()`, `graphql()` | Yes | Yes | No |
| Live queries | Yes | No | No |
| Sessions | Yes | No | No |
| Client-side transactions | Yes | No | No |
| Streaming results | Yes, from SurrealDB 3.3 | No, results are buffered | No, results are buffered |
| Import and export, `health()` | Yes | Yes | No |
| Reconnection, keepalive pings | Yes | Not needed | Not needed |
| `status`, `subscribe()` | Yes | No | No |
| Factory options | All | `timeout`, `version_check`, `auth`, `renew_access` | None |

A method that a connection type does not support raises `UnsupportedFeatureError`.
