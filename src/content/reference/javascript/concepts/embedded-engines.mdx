# Embedded engines

The JavaScript SDK supports running SurrealDB as an embedded database through two engine plugins. Choose the one that matches your environment:

<Tabs syncKey="surrealkv-version">
<TabItem label="SurrealDB 4.0 and later">

| Engine | Package | Environment | Storage options |
|--------|---------|-------------|-----------------|
| WebAssembly | `@surrealdb/wasm` | Browsers | `mem://`, `surrealkv://` (dedicated worker only) |
| Node.js | `@surrealdb/node` | Node.js, Bun, Deno | `mem://`, `surrealkv://` |

RocksDB (`rocksdb://`) and IndexedDB (`indxdb://`) were removed in SurrealDB 4.0. The [Node.js](/docs/reference/javascript/engines/node) and [WebAssembly](/docs/reference/javascript/engines/wasm#moving-from-indexeddb) engine pages describe how existing data moves to SurrealKV.

</TabItem>
<TabItem label="Before SurrealDB 4.0">

| Engine | Package | Environment | Storage options |
|--------|---------|-------------|-----------------|
| WebAssembly | `@surrealdb/wasm` | Browsers | `mem://`, `indxdb://` |
| Node.js | `@surrealdb/node` | Node.js, Bun, Deno | `mem://`, `rocksdb://`, `surrealkv://` |

</TabItem>
</Tabs>

Both plugins work with ES modules (`import`), not CommonJS (`require`).

> [!NOTE]
> Neither engine runs on Android or iOS. Hermes has no WebAssembly runtime, and the Node.js engine is a native Node addon that React Native cannot load. Apps built with [Expo](/docs/reference/javascript/frameworks/expo) or [React Native](/docs/reference/javascript/frameworks/react-native) connect to a remote instance over `wss://` or `https://`.

## Engine version

Each plugin runs a SurrealDB engine that ships as its own package: `@surrealdb/wasm-native` for WebAssembly and `@surrealdb/node-native` for Node.js. From plugin version 3.0.4, the engine is a peer dependency, so you choose which SurrealDB release runs embedded in your app, independently of the plugin version. Install a specific release with `npm install --save @surrealdb/node-native@3.3.2`, or let your package manager pick the newest release in the supported range. The [Node.js](/docs/reference/javascript/engines/node#choosing-the-engine-version) and [WebAssembly](/docs/reference/javascript/engines/wasm#choosing-the-engine-version) engine pages describe pinning and how to check the loaded version.

## WebAssembly engine (browser)

The `@surrealdb/wasm` package runs SurrealDB inside a browser environment. It can run inside a Web Worker to keep the main thread responsive.

<Tabs syncKey="surrealkv-version">
<TabItem label="SurrealDB 4.0 and later">

The engine supports in-memory databases, and persistent storage with SurrealKV over the browser's Origin Private File System (OPFS). Persistent storage requires a web worker.

</TabItem>
<TabItem label="Before SurrealDB 4.0">

The engine supports in-memory databases and persistent storage via IndexedDB.

</TabItem>
</Tabs>

### Installation

```bash
npm install --save @surrealdb/wasm @surrealdb/wasm-native
```

### Registering the engine

```ts
import { Surreal, createRemoteEngines } from 'surrealdb';
import { createWasmEngines } from '@surrealdb/wasm';

const db = new Surreal({
    engines: {
        ...createRemoteEngines(),
        ...createWasmEngines(),
    },
});

await db.connect('mem://');
```

<Tabs syncKey="surrealkv-version">
<TabItem label="SurrealDB 4.0 and later">

These engines run on the main thread of the page, so they support `mem://` only. A `surrealkv://` database needs the web worker setup below.

</TabItem>
<TabItem label="Before SurrealDB 4.0">

To persist the database with IndexedDB, connect with an `indxdb://` endpoint:

```ts
await db.connect('indxdb://myapp');
```

</TabItem>
</Tabs>

### Running in a web worker

Offload database operations from the main thread to keep your interface responsive:

```ts
import { Surreal, createRemoteEngines } from 'surrealdb';
import { createWasmWorkerEngines } from '@surrealdb/wasm';
import WorkerAgent from '@surrealdb/wasm/worker?worker';

const db = new Surreal({
    engines: {
        ...createRemoteEngines(),
        ...createWasmWorkerEngines({
            createWorker: () => new WorkerAgent(),
        }),
    },
});

await db.connect('mem://');
```

<Tabs syncKey="surrealkv-version">
<TabItem label="SurrealDB 4.0 and later">

A worker created this way is a dedicated worker, which is where a persistent `surrealkv://` database has to run. Connect to one with a `surrealkv://` endpoint:

```ts
await db.connect('surrealkv://myapp');
```

The [WebAssembly engine](/docs/reference/javascript/engines/wasm#persistent-storage) page describes what a persistent browser database needs from the page, including persistent storage permission and one tab per database.

</TabItem>
<TabItem label="Before SurrealDB 4.0">

A worker also supports `indxdb://`, in the same way as the main thread:

```ts
await db.connect('indxdb://myapp');
```

</TabItem>
</Tabs>

### Bundler configuration

If you are using a bundler like Vite, you may need to exclude the WASM package from dependency optimisation and enable top-level await:

```js title="vite.config.js"
export default {
    optimizeDeps: {
        exclude: ['@surrealdb/wasm'],
        esbuildOptions: {
            target: 'esnext',
        },
    },
    esbuild: {
        supported: {
            'top-level-await': true,
        },
    },
};
```

## Node.js engine (server)

The `@surrealdb/node` package runs SurrealDB within Node.js, Bun, or Deno. It supports in-memory databases and persistent storage via SurrealKV.

### Installation

```bash
npm install --save @surrealdb/node @surrealdb/node-native
```

### Registering the engine

```ts
import { Surreal, createRemoteEngines } from 'surrealdb';
import { createNodeEngines } from '@surrealdb/node';

const db = new Surreal({
    engines: {
        ...createRemoteEngines(),
        ...createNodeEngines(),
    },
});

await db.connect('mem://');
// or persist with SurrealKV:
await db.connect('surrealkv://./data');
```

To enable [versioned storage](/docs/reference/query-language/statements/select#the-version-clause) for temporal queries, append `?versioned=true` to the connection string:

```ts
await db.connect('surrealkv://./data?versioned=true');
```

### Closing the connection

When using the Node.js engine, you must close the connection with `.close()` when you are done to ensure the database is properly shut down:

```ts
await db.close();
```
