# Surqlize installation

Surqlize is published on npm as [`surqlize`](https://www.npmjs.com/package/surqlize). It depends on the [JavaScript SDK](/docs/reference/javascript/installation) as a peer dependency, so you install both packages in your project.

## Install the packages

<Tabs syncKey="node-package-manager">
<TabItem label="bun">
```bash
bun add surqlize surrealdb
```
</TabItem>
<TabItem label="npm">
```bash
npm install surqlize surrealdb
```
</TabItem>
<TabItem label="yarn">
```bash
yarn add surqlize surrealdb
```
</TabItem>
<TabItem label="pnpm">
```bash
pnpm add surqlize surrealdb
```
</TabItem>
</Tabs>

Surqlize ships ESM and CommonJS builds with type declarations, so it works from either module system without extra configuration.

## Requirements

| Requirement | Version |
| ----------- | ------- |
| `surrealdb` JavaScript SDK | `^2.1.0` |
| TypeScript | 5 or 6 |
| SurrealDB server | 3.0 or later |

The SDK and the server are versioned separately: version 2 of the SDK is the one that connects to a SurrealDB 3.x server.

Surqlize targets SurrealDB 3.x. A few features need a particular server version, and the page for each feature says which. [Computed fields](/docs/reference/javascript/libraries/surqlize/schema#computed-fields) need 3.0, filtering a [live query](/docs/reference/javascript/libraries/surqlize/live-queries) needs 3.0, and structured conflict errors for [retries](/docs/reference/javascript/libraries/surqlize/request-options#retrying-conflicts) arrive in 3.1.0.

## Use a single copy of the SDK

The connection you pass to Surqlize and Surqlize itself must resolve the same copy of the `surrealdb` package. The SDK encodes values with `instanceof` checks, so with two copies it does not recognise the table that Surqlize uses as the subject of a query, and sends an empty object instead. The server then replies with `Cannot execute CREATE statement using value: {  }`.

Surqlize detects this case and throws a `DuplicateSurrealError` that points back to this page. To fix it:

1. Run `npm ls surrealdb` (or `bun pm ls --all`) to see which versions are installed.
2. Dedupe so that a single version is installed. An `overrides` entry in `package.json` (`resolutions` for Yarn) can force one version.
3. Avoid `file:` dependencies, which copy a package together with its own `node_modules`.

> [!NOTE]
> In a symlinked setup, TypeScript can report `Property '#private' in type 'Surreal' refers to a different member`. Set `preserveSymlinks: true` in `tsconfig.json` to resolve it.
