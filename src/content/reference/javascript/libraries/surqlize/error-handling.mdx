# Surqlize error handling

A query can fail in Surqlize, in the SDK, or on the server. Surqlize throws its own error classes for the first group and passes the other two through unchanged, so the same `instanceof` checks work for both.

| Error | Thrown when |
| ----- | ----------- |
| `OrmError` | A query is built or used incorrectly. |
| `ValidationError` | Data you write does not match the schema, with [runtime validation](/docs/reference/javascript/libraries/surqlize/validation) on or through `parse()`. It extends `OrmError`. |
| `TypeParseError` | A value from the database does not match the type in your schema. |
| `DuplicateSurrealError` | More than one copy of the `surrealdb` package is installed. It extends `OrmError`. |
| SDK and server errors | The database rejects a query, a request times out, or a connection fails. |

All of these classes are exported from `surqlize`, except the SDK errors, which come from `surrealdb`.

## OrmError

`OrmError` reports a mistake in how a query is built. Typical causes are a filter object that names an unknown field, calling `relate()` with a table that is not an edge, calling `.content()` after `.set()` on the same query, and calling `batch()` inside a transaction. Most of these are also rejected by the type checker, and the error covers the cases where the types are loose, such as data from `JSON.parse`.

```ts title="Catch a build error"
import { OrmError } from "surqlize";

try {
    db.select("user").where(filterFromRequest);
} catch (error) {
    if (error instanceof OrmError) {
        console.error(error.message); // for example: Unknown field "nope" in where object
    }
}
```

## TypeParseError

Surqlize parses every result against your schema. When a stored value does not match, for example because a field was written with another type, the query rejects with a `TypeParseError`. It has the following properties:

- **`name`** is the name of the type that failed.
- **`expected`** is the type, or the list of types, that the schema describes.
- **`found`** is the value that was received.

```ts title="Catch a result that does not match the schema"
import { TypeParseError } from "surqlize";

try {
    const users = await db.select("user");
} catch (error) {
    if (error instanceof TypeParseError) {
        console.error(`Expected ${error.expected} but found ${error.found}`);
    }
}
```

`TypeParseError` stops at the first mismatch. It does not extend `OrmError`.

> [!NOTE]
> A write that leaves a required field unset stores the record, and then rejects with a `TypeParseError` when the result is parsed. See [mutations](/docs/reference/javascript/libraries/surqlize/mutations#how-to-write-data).

## ValidationError

`ValidationError` is thrown before a query is sent, and lists every failing field in `issues`. See [runtime validation](/docs/reference/javascript/libraries/surqlize/validation#validationerror).

## DuplicateSurrealError

`DuplicateSurrealError` means the connection comes from a different copy of the `surrealdb` package than the one Surqlize uses. The original error is available as `cause`. See [installation](/docs/reference/javascript/libraries/surqlize/installation#use-a-single-copy-of-the-sdk) for the fix.

## SDK and server errors

Errors from the database and the connection reach your code as the SDK's own classes, for example `AlreadyExistsError` when you create a record whose id is taken. See [error handling](/docs/reference/javascript/concepts/error-handling) in the SDK documentation for the full list.

```ts title="Handle a duplicate record"
import { AlreadyExistsError } from "surrealdb";

try {
    await db.create("user", "ada").content(input);
} catch (error) {
    if (error instanceof AlreadyExistsError) {
        // The record user:ada exists already
    } else {
        throw error;
    }
}
```

A query that is abandoned with `.signal()` or `withSignal()` rejects with the reason of the signal. A query whose `.requestTimeout()` expires rejects with an error named `TimeoutError`. A query that fails with a conflict can be [retried](/docs/reference/javascript/libraries/surqlize/request-options#retrying-conflicts).
