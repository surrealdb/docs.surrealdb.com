# Performance

Surqlize builds queries from immutable builders, and building and rendering one takes microseconds. The cost is far below the time of a network round trip to the database, so the library does not cache rendered queries.

On a development machine, the benchmarks in the repository measure a simple `select` at a few microseconds, and a `select` with `where`, `orderBy`, `fetch`, and `return` at a few tens of microseconds. Parsing the result of a select of 1,000 records takes well under a millisecond. Your numbers depend on the hardware and the shape of the schema.

## Reuse a built query

Builders are immutable, so a query you build once is safe to share and to run many times. Build queries that do not change at module level, and run them where you need them.

```ts title="Build once, run many times"
const activeUsers = db
    .select("user")
    .where((user) => user.isActive.eq(true))
    .orderBy("name", "ASC");

export const listActiveUsers = () => activeUsers.execute();
```

A built query also works as a base for others. Each chained method returns a new query, so the shared base is never changed.

```ts title="Extend a shared base"
const publishedPosts = db.select("post").where((post) => post.published.eq(true));

const latest = publishedPosts.orderBy("created", "DESC").limit(10);
const oldest = publishedPosts.orderBy("created", "ASC").limit(10);
```

## Reduce round trips

The SDK sends concurrent queries over one connection, so independent queries can run at the same time with `Promise.all()`. Queries that must succeed or fail together can go in one [batch](/docs/reference/javascript/libraries/surqlize/transactions#batches), which is a single request.

```ts title="Run independent queries concurrently"
const [users, posts] = await Promise.all([
    db.select("user").limit(50),
    db.select("post").limit(50),
]);
```

Keep one `Surreal` connection for the process and share it between ORM instances. A pool is not needed. See [connections](/docs/reference/javascript/libraries/surqlize/connections#connections-and-pooling).

## Reduce the size of results

- **Project the fields you need** with `.return()`. The result is smaller, and the type shows exactly what you receive.
- **Paginate** with `.limit()` and `.start()` instead of selecting a whole table.
- **Skip the result** of a write you do not read with `.return("none")`. Nothing is returned or parsed.
- **Fetch only what you use.** `.fetch()` returns whole linked records, so name only the links you need.

## Skip the ORM for a single call

`.prepare()` returns the SurrealQL and its bindings as an SDK `BoundQuery`, without parsing the result. Use it when you want Surqlize's typed builders to produce a query and the SDK to run it, for example inside a transaction you manage with the SDK.

```ts title="Hand a query to the SDK"
const prepared = db
    .select("user")
    .return((user) => ({ name: user.name, email: user.email }))
    .prepare();

const [users] = await surreal.query(prepared).collect();
```

The caller decodes the result. See [querying](/docs/reference/javascript/libraries/surqlize/querying#inspecting-a-query).

## Run the benchmarks

The benchmarks in the `benchmarks/` directory of the [repository](https://github.com/surrealdb/surqlize) need no database. Run them with `bun run bench`. An optional name filter selects scenarios, for example `bun run bench select`, and `--json file` saves the results.
