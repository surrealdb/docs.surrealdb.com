# `ALTER BUCKET` statement

<Since v="v3.0.5" />

The `ALTER BUCKET` statement can be used to modify an existing defined [bucket](/docs/reference/query-language/statements/define/bucket).

## Statement syntax

<Tabs syncKey="alter-statement">
  <TabItem label="SurrealQL Syntax">

```syntax title="SurrealQL Syntax"
ALTER BUCKET [ IF EXISTS ] @name
  [ ON [ ROOT | NAMESPACE | DATABASE ] ]
  [ READONLY | DROP READONLY ]
  [ BACKEND @string ]
  [ PERMISSIONS @expression ]
  [ COMMENT @string | DROP COMMENT ]
  [ REVOKE SIGNATURES ]
```

## Example usage

```surql
DEFINE BUCKET my_bucket BACKEND "memory";

ALTER BUCKET my_bucket COMMENT "Should we make this read-only too??";
```

## Changing the backend

<Since v="v4.0.0" />

`BACKEND` moves the bucket to another backend. The files in the old backend stay where they are, and the bucket serves the files of the new one. A `global://` backend needs a root user, as on [`DEFINE BUCKET`](/docs/reference/query-language/statements/define/bucket#global-backend). From SurrealDB 4.0, a bucket always has a backend, so `DROP BACKEND` no longer parses.

Changing `BACKEND` or `READONLY` makes SurrealDB open a new connection to the backend once the statement commits. For a `memory` backend, a new connection starts empty, so a `memory` bucket loses its files when either clause changes.

## Root and namespace buckets

<Since v="v4.0.0" />

Without `ON`, `ALTER BUCKET` changes a bucket of the database in use. To change a [root or namespace bucket](/docs/reference/query-language/statements/define/bucket#root-and-namespace-buckets), name its level:

```surql
ALTER BUCKET shared ON NAMESPACE COMMENT "Files for every database in this namespace";
```

## Revoking presigned URLs

<Since v="v4.0.0" />

`REVOKE SIGNATURES` stops every [presigned URL](/docs/learn/schema-management/files/presigned-urls) already issued for the bucket from working. A request with one of those URLs then answers `403`. URLs created after the statement work as usual.

```surql
ALTER BUCKET my_bucket REVOKE SIGNATURES;
```

Each bucket holds a random value that is part of the key that signs its URLs, and `REVOKE SIGNATURES` replaces it. `DEFINE BUCKET ... OVERWRITE` keeps the value, so redefining a bucket does not make revoked URLs work again. Removing a bucket and defining it again gives it a new value, which also revokes its URLs. To revoke the URLs of every bucket on a server at once, change `SURREAL_BUCKET_PRESIGN_SECRET`.
