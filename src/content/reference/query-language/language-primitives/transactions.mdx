# Transactions

Each statement within SurrealDB is run within its own transaction by default. If a set of changes need to be made together, then groups of statements can be run together as a single transaction. If all of the statements within a transaction succeed, and the transaction is successful, then all of the data modifications made during the transaction are committed and become a permanent part of the database. If a transaction encounters errors and must be cancelled or rolled back, then any data modification made within the transaction is rolled back, and will not become a permanent part of the database.

## Starting a transaction

The `BEGIN` or `BEGIN TRANSACTION` statement starts a transaction in which multiple statements can be run together.

```surql title="Starting a transaction"
BEGIN [ TRANSACTION ];
```

The following query shows example usage of this statement.

```surql title="Example usage of BEGIN TRANSACTION"
/**[test]

[[test.results]]
value = "[{ balance: 135605.16f, id: account:one }]"

[[test.results]]
value = "[{ balance: 91031.31f, id: account:two }]"

[[test.results]]
value = "NONE"

[[test.results]]
value = "[{ balance: 135905.16f, id: account:one }]"

[[test.results]]
value = "[{ balance: 90731.31f, id: account:two }]"

[[test.results]]
value = "NONE"

*/

-- Create a new account with the ID 'one' and set its initial balance to 135605.16
CREATE account:one SET balance = 135605.16;

-- Create another new account with the ID 'two' and set its initial balance to 91031.31
CREATE account:two SET balance = 91031.31;

-- Start a new database transaction. Transactions are a way to ensure multiple operations
-- either all succeed or all fail, maintaining data integrity.
BEGIN TRANSACTION;

-- Update the balance of account 'one' by adding 300.00 to the current balance.
-- This could represent a deposit or other form of credit on the balance property.
UPDATE account:one SET balance += 300.00;

-- Update the balance of account 'two' by subtracting 300.00 from the current balance.
-- This could represent a withdrawal or other form of debit on the balance property.
UPDATE account:two SET balance -= 300.00;

-- Finalise the transaction. This will apply the changes to the database. If there was an error
-- during any of the previous steps within the transaction, all changes would be rolled back and
-- the database would remain in its initial state.
COMMIT TRANSACTION;
```

## Committing a transaction

The [COMMIT](/docs/reference/query-language/statements/commit) statement is used to commit the statements within a transaction, ensuring that all data modifications become a permanent part of the database.

```surql title="Committing a transaction"
COMMIT [ TRANSACTION ];
```

The following query shows example usage of this statement.

```surql title="Example usage of COMMIT TRANSACTION"
/**[test]

[[test.results]]
value = "[{ balance: 135605.16f, id: account:one }]"

[[test.results]]
value = "[{ balance: 91031.31f, id: account:two }]"

[[test.results]]
value = "NONE"

[[test.results]]
value = "[{ balance: 135905.16f, id: account:one }]"

[[test.results]]
value = "[{ balance: 90731.31f, id: account:two }]"

[[test.results]]
value = "NONE"

*/

-- Setup accounts
CREATE account:one SET balance = 135605.16;
CREATE account:two SET balance = 91031.31;

BEGIN TRANSACTION;

-- Move money
UPDATE account:one SET balance += 300.00;
UPDATE account:two SET balance -= 300.00;

-- Finalise all changes
COMMIT TRANSACTION;
```

## Cancelling a transaction

The [CANCEL](/docs/reference/query-language/statements/cancel) statement can be used to cancel the statements within a transaction, reverting or rolling back any data modification made within the transaction as a whole.

```surql title="Cancelling a transaction"
CANCEL [ TRANSACTION ];
```

The following query shows example usage of this statement.

```surql title="Example usage of CANCEL TRANSACTION"
/**[test]

[[test.results]]
value = "[{ balance: 135605.16f, id: account:one }]"

[[test.results]]
value = "[{ balance: 91031.31f, id: account:two }]"

[[test.results]]
value = "NONE"

[[test.results]]
error = "The query was not executed due to a cancelled transaction"

[[test.results]]
error = "The query was not executed due to a cancelled transaction"

[[test.results]]
value = "NONE"

*/

-- Setup accounts
CREATE account:one SET balance = 135605.16;
CREATE account:two SET balance = 91031.31;

BEGIN TRANSACTION;

-- Move money
UPDATE account:one SET balance += 300.00;
UPDATE account:two SET balance -= 300.00;

-- Rollback all changes
CANCEL TRANSACTION;
```

A cancelled transaction only rolls back changes to the database. Changes outside it, such as [files written to a bucket](/docs/reference/query-language/functions/database-functions/file), are kept.

> [!WARNING]
> `BEGIN`, `COMMIT` and `CANCEL` only take effect as top-level statements of a query. Inside a block, such as an `IF` or `FOR` body, a bare `{ }` block or a `DEFINE FUNCTION` body, they are ignored without an error. A `CANCEL` inside `IF` does not cancel the transaction, so the statements after it are still committed. To cancel a transaction on a condition, use `THROW` as shown below.

## THROW to conditionally cancel a transaction

While transactions are automatically rolled back if an error occurs in any of its statements, [THROW](/docs/reference/query-language/statements/throw) can also be used to explicitly break out of a transaction at any point. `THROW` can be followed by any value which serves as the error message, usually a string.

```surql
CREATE account:one SET dollars =  100;
CREATE account:two SET dollars =  100;

LET $transfer_amount = 150;

BEGIN TRANSACTION;

UPDATE account:one SET dollars -= $transfer_amount;
UPDATE account:two SET dollars += $transfer_amount;
IF account:one.dollars < 0 {
    THROW "Insufficient funds, would have $" + <string>account:one.dollars + " after transfer"
};
COMMIT TRANSACTION;
SELECT * FROM account;
```

```surql title="Output when $transfer_amount set to 150"
'An error occurred: Insufficient funds, would have $-50 after transfer'
```

```surql title="Output when $transfer_amount set to 50"
[
	{
		dollars: 50,
		id: account:one
	},
	{
		dollars: 150,
		id: account:two
	}
]
```

## Skipping writes on a condition

A rollback in SurrealQL, whether from `CANCEL` or from an error, always reports every statement in the transaction as not executed. Where the transaction should succeed but some writes are not needed, put those writes inside an `IF` block instead of throwing an error. In the following example, the counter only changes when the vote changes its score.

```surql
BEGIN;
LET $old = (SELECT VALUE score FROM ONLY vote:1);
UPSERT vote:1 SET score = 4;
IF $old != 4 { UPSERT counter:1 SET n += 1 };
COMMIT;
```

For more than one dependent statement, a block with an early `RETURN` works as a guard clause, and `CONTINUE` and `BREAK` control a loop, all without ending the transaction. See [Control flow inside a transaction](/docs/learn/querying/concepts-and-guides/transactions#control-flow-inside-a-transaction).

To roll back on a condition without returning an error, use a client-side transaction from an SDK instead. The client starts the transaction, checks the results of its queries, and then commits or cancels it. See [manual transactions in Rust](/docs/reference/rust/concepts/transaction) and [transactions in JavaScript](/docs/reference/javascript/concepts/transactions).

## Nested transactions and savepoints

A transaction cannot contain another transaction, and SurrealQL has no savepoints to roll back part of one. A `BEGIN` inside an open transaction aborts the whole outer transaction, so none of its changes are written.

```surql
BEGIN;
CREATE account:three SET dollars = 100;
BEGIN;
CREATE account:four SET dollars = 100;
COMMIT;
COMMIT;
```

```surql title="Error output"
'Tried to start a transaction while another transaction was open'
'Cannot COMMIT: the transaction was aborted due to a nested BEGIN'
```

A transaction always commits or cancels as a whole. To keep the earlier steps when a later one fails, put them in separate transactions that each commit on their own.

## Transactions across several requests

A transaction written with `BEGIN` and `COMMIT` has to begin and end in the same query: one call to `query()` in an SDK, or one request to the HTTP `/sql` endpoint. When the query ends, a transaction that is still open is cancelled, and a `COMMIT` sent in a later request has no transaction to commit:

```surql
-- First request
BEGIN;
CREATE step:one;
```

```text title="Error output"
Missing COMMIT statement
```

```surql
-- Second request
COMMIT;
```

```text title="Error output"
Invalid statement: Cannot COMMIT without starting a transaction
```

To keep a transaction open while an application runs several queries, for example between migration steps that each need a result from the one before, use a client-side transaction from the SDK. It is started and finished by the client, and every query sent through it runs in the same transaction until the client commits or cancels it. Client-side transactions work over a WebSocket connection and with an embedded database, but not over HTTP. See [manual transactions in Rust](/docs/reference/rust/concepts/transaction) and [transactions in JavaScript](/docs/reference/javascript/concepts/transactions).
