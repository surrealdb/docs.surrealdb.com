# Numbers

In SurrealDB, numbers can be one of three types: 64-bit integers, 64-bit floating point numbers, or 128-bit decimal numbers. From SurrealDB 4.0, a number can also be one of the [sized number](#sized-numbers) types, such as `u8` or `f32`.

## Integer numbers
If a numeric value is specified without a decimal point and is within the range `-9223372036854775808` to `9223372036854775807` then the value will be parsed, stored, and treated as a 64-bit integer.

```surql
/**[test]

[[test.results]]
value = "[{ id: event:j3tdh7wrm2kv1ymbbsek, year: 2022 }]"
skip-record-id-key = true

*/

CREATE event SET year = 2022;
```

## Floating point numbers
If a number value is specified with a decimal point, then the number will automatically be parsed, stored, and treated as a 64-bit floating point value. An integer outside the range specified above is a parse error (`Failed to parse number: number cannot fit within a 64bit signed integer`), so write it with an `f` or `dec` suffix, or with a [`u64`](#sized-numbers) suffix from SurrealDB 4.0. This ensures efficiency when performing mathematical calculations within SurrealDB.

```surql
/**[test]

[[test.results]]
value = "[{ id: event:5h756te17xakgdzfbghe, temperature: 41.5f }]"
skip-record-id-key = true

*/

CREATE event SET temperature = 41.5;
```

## Decimal numbers
To opt into 128-bit decimal numbers when specifying numeric values, you can use the `dec` suffix.

```surql
/**[test]

[[test.results]]
value = "[{ id: product:64vljvh12gdfwolgfhux, price: 99.99dec }]"
skip-record-id-key = true

*/

CREATE product SET price = 99.99dec;
```

The `dec` suffix is an instruction to the parser and not a cast, and is thus preferred when making a decimal.

```surql
/**[test]

[[test.results]]
value = "3.888888888888889dec"

[[test.results]]
value = "3.8888888888888888dec"

*/

-- Creates the imprecise float 3.888888888888889 and casts it into a decimal as 3.888888888888889dec
<decimal>3.8888888888888888;
-- Uses the input 3.8888888888888888 to directly create a decimal
3.8888888888888888dec;
```

A decimal holds up to 28 digits after the decimal point. A `dec` literal that needs more, in plain or exponent notation, is a parse error. Zeros after the last significant digit do not count, because the value is still exact, so `1.500000000000000000000000000000dec` gives `1.5dec`. A string cast with `<decimal>` is rounded to 28 places instead.

```surql
0.0000000000000000000000000000001dec;
```

```surql title="Error output"
Parse error: Failed to parse decimal: Scale exceeds the maximum precision allowed: 31 > 28
```

```surql
<decimal>"0.0000000000000000000000000000001";
```

```surql title="Output"
0dec
```

## Using a specific numeric type
To use a specific type when specifying numeric values, you can cast the value to a specific numeric type or use the appropriate suffix.

```surql
/**[test]

[[test.results]]
value = "[{ horizon: 34dec, id: event:8vpjsysxnskyfuh9ve87, temperature: 46.5f, year: 2022 }]"
skip-record-id-key = true

*/

CREATE event SET
	year = <int> 2022,
	temperature = <float> 41.5 + 5f,
	horizon = <decimal> 31 + 3dec
;
```

## Sized numbers

<Since v="v4.0.0" />

As well as `int`, `float` and `decimal`, a number can have a fixed size. A sized number keeps its size when it is stored and when it is used in a calculation, and a field of a sized type refuses a value that does not fit.

| Type | Suffix | Range |
| --- | --- | --- |
| `i8` | `i8` | `-128` to `127` |
| `u8` | `u8` | `0` to `255` |
| `i16` | `i16` | `-32768` to `32767` |
| `u16` | `u16` | `0` to `65535` |
| `i32` | `i32` | `-2147483648` to `2147483647` |
| `u32` | `u32` | `0` to `4294967295` |
| `int` | `i64`, or none | `-9223372036854775808` to `9223372036854775807` |
| `u64` | `u64` | `0` to `18446744073709551615` |
| `f16` | `f16` | 16-bit floating point |
| `f32` | `f32` | 32-bit floating point |
| `float` | `f64` or `f` | 64-bit floating point |

`i64` and `f64` are other names for `int` and `float`, so `42i64` is the same value as `42`. A sized integer suffix cannot follow a number with a decimal point or an exponent, and a literal that does not fit its type is a parse error.

```surql
/**[test]

[[test.results]]
value = "['u8', 'i16', 'u64', 'f32', 'int']"

*/

[type::of(255u8), type::of(-32768i16), type::of(18446744073709551615u64), type::of(1.5f32), type::of(42i64)];
```

```surql title="Output"
['u8', 'i16', 'u64', 'f32', 'int']
```

A calculation on two numbers of the same type gives that type, and fails instead of wrapping when the result does not fit. A calculation on two different types gives the smallest type that holds both: `1u8 + 2i16` is `3i16`, a sized integer and a sized float give a float, and any number with a `decimal` gives a `decimal`.

```surql
/**[test]

[[test.results]]
value = "[3u8, 3i16, 300u16]"

[[test.results]]
error = "Cannot perform addition with '255u8' and '1u8'"

*/

[1u8 + 2u8, 1u8 + 2i16, 200u8 + 100u16];
255u8 + 1u8;
```

```surql title="Output"
-------- Query 1 --------

[3u8, 3i16, 300u16]

-------- Query 2 --------

"Cannot perform addition with '255u8' and '1u8'"
```

A field of a sized type converts a number that fits exactly, and refuses a number that is out of range or has a fractional part. A cast such as `<u8>` and the functions `type::u8()` to `type::f32()` do the same, and `type::is_u8()` to `type::is_f32()` check for each type. A sized number is equal to a number of any other type with the same value, so `5u8 == 5` is `true`, and a `GROUP BY`, a set or a `UNIQUE` index treats the two as one value.

```surql
/**[test]

[[test.results]]
value = "NONE"

[[test.results]]
value = "[{ id: reading:1, level: 200u8 }]"

[[test.results]]
error = "Couldn't coerce value for field `level` of `reading:2`: Expected `u8` but found `256`"

*/

DEFINE FIELD level ON reading TYPE u8;
CREATE reading:1 SET level = 200;
CREATE reading:2 SET level = 256;
```

```surql title="Output"
-------- Query 1 --------

NONE

-------- Query 2 --------

[{ id: reading:1, level: 200u8 }]

-------- Query 3 --------

"Couldn't coerce value for field `level` of `reading:2`: Expected `u8` but found `256`"
```

> [!NOTE]
> A record ID keeps the type of a number in an array or object key. `r:[5u8]` and `r:[5]` are two different records, so a lookup has to use the same type that the record was created with.

A client keeps the size of a number only when it uses a protocol that carries it, such as CBOR version 2. The original CBOR protocol and JSON send a sized number as an ordinary integer or float.

## Numeric precision
Different numeric types can be compared and used together in calculations.

The benefits of floating point numeric values are speed and storage size, but there is a limit to the numeric precision.

```surql
/**[test]

[[test.results]]
value = "13.571938471938472f"

*/

13.5719384719384719385639856394139476937756394756;
```

```surql title="Output"
13.571938471938472f
```

In addition, when using floating point numbers specifically, mathematical operations can result in a loss of precision (as is normal with other databases).

```surql
/**[test]

[[test.results]]
value = "0.9999999999999999f"

*/

0.3 + 0.3 + 0.3 + 0.1;
```

```surql title="Output"
0.9999999999999999f
```

Common rounding errors can be avoided by performing calculations using decimals.

```surql
/**[test]

[[test.results]]
value = "1.0dec"

*/

0.3dec + 0.3dec + 0.3dec + 0.1dec;
```

```surql title="Output"
1.0dec
```

## Underscores

As a convenience, underscores are ignored when using a number. This allows input to be more readable than it would otherwise. Because underscores are ignored, they will not display in the output.

```surql
RELATE dr:evil->bribes->other:character SET dollars = 1_000_000.99;
//- [{ dollars: 1000000.99, id: bribes:4bfld2ukwnja24dzrpw9, in: dr:evil, out: other:character }]

-- Input Korean currency counted in units of 10000, not 1000
RELATE korean:purchaser->buys_house_from->korean:seller
              -- 10억 4천만 5천
    SET amount = 10_4000_5000;
//- [{ amount: 1040005000, id: buys_house_from:9070t2ctgwwg202cpw1z, in: korean:purchaser, out: korean:seller }]
```

## Mathematical constants
A set of floating point numeric constants are available in SurrealDB. Constant names are case insensitive, and can be specified with either lowercase or capital letters, or a mixture of both.

```surql
/**[test]

[[test.results]]
value = "[{ circumference: 10, id: circle:syccb27abtyo6d53fkps }]"
skip-record-id-key = true

[[test.results]]
value = "[{ circumference: 10, id: circle:syccb27abtyo6d53fkps, radius: 1.5915494309189535f }]"
skip-record-id-key = true

*/

CREATE circle SET circumference = 10;
UPDATE circle SET radius = circumference / ( 2 * MATH::PI );
```
