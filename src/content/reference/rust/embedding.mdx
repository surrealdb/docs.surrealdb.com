# Embedding in Rust

SurrealDB is designed to be run in many different ways and in many environments. Due to the [separation of the storage and API layers](/docs/learn/data-models/architecture), SurrealDB can be run in embedded mode, from within a number of different language environments. In Rust, SurrealDB can be run as an in-memory database, it can persist data using a file-based storage engine, or on a distributed cluster.

## Install the SDK

First, create a new project using `cargo new` and add the SurrealDB crate to your dependencies, enabling the key-value store you need:

```sh
# For an in memory database
cargo add surrealdb --features kv-mem

# For a RocksDB file
cargo add surrealdb --features kv-rocksdb
```

RocksDB is a C++ library, so `kv-rocksdb` compiles it as part of your build and needs a C++ compiler and `libclang` on the build machine. [SurrealKV](/docs/running/file-backed#surrealkv) is written in Rust and stores data on disk without either. Enable it with `cargo add surrealdb --features kv-surrealkv` and connect with the `SurrealKv` engine.

You will need to add the following additional dependency:

```bash
cargo add tokio --features macros,rt-multi-thread
```

The structs in the example derive [`SurrealValue`](/docs/reference/rust/concepts/surrealvalue-attributes), which the SDK uses to convert Rust types to and from SurrealDB values. Types that only derive serde's `Serialize` and `Deserialize` do not implement it, and passing one to a method such as `.content()` or `.select()` fails to compile with `the trait bound ...: SurrealValue is not satisfied`.

## Connect to SurrealDB

Open `src/main.rs` and replace everything in there with the following code to try out some basic operations using the SurrealDB SDK with an embedded database. Look at [integrations to connect to a database](/docs/reference/rust).

```rust
use surrealdb::types::{RecordId, SurrealValue};
use surrealdb::Surreal;

// For an in memory database
use surrealdb::engine::local::Mem;

// For a RocksDB file
// use surrealdb::engine::local::RocksDb;

#[derive(Debug, SurrealValue)]
struct Name {
    first: String,
    last: String,
}

#[derive(Debug, SurrealValue)]
struct Person {
    title: String,
    name: Name,
    marketing: bool,
}

#[derive(Debug, SurrealValue)]
struct Responsibility {
    marketing: bool,
}

#[derive(Debug, SurrealValue)]
struct Record {
    #[allow(dead_code)]
    id: RecordId,
}

#[tokio::main]
async fn main() -> surrealdb::Result<()> {
    // Create database connection in memory
    let db = Surreal::new::<Mem>(()).await?;
    
    // Create database connection using RocksDB
    // let db = Surreal::new::<RocksDb>("path/to/database-folder").await?;

    // Select a specific namespace / database
    db.use_ns("main").use_db("main").await?;

    // Create a new person with a random id
    let created: Option<Record> = db
        .create("person")
        .content(Person {
            title: "Founder & CEO".to_string(),
            name: Name {
                first: "Tobie".to_string(),
                last: "Morgan Hitchcock".to_string(),
            },
            marketing: true,
        })
        .await?;
    dbg!(created);

    // Update a person record with a specific id
    let updated: Option<Record> = db
        .update(("person", "jaime"))
        .merge(Responsibility { marketing: true })
        .await?;
    dbg!(updated);

    // Select all people records
    let people: Vec<Record> = db.select("person").await?;
    dbg!(people);

    // Perform a custom advanced query
    let groups = db
        .query("SELECT marketing, count() FROM type::table($table) GROUP BY marketing")
        .bind(("table", "person"))
        .await?;
    dbg!(groups);

    Ok(())
}
```

Run your program from the command line with:

```sh
cargo run
```

## Logging and one process per datastore

The embedded engine logs through the [`tracing`](https://docs.rs/tracing) crate, so its output appears once your program installs a subscriber. With [`tracing-subscriber`](https://docs.rs/tracing-subscriber) and its `env-filter` feature, the `RUST_LOG` environment variable chooses the level:

```rust
use tracing_subscriber::EnvFilter;

#[tokio::main]
async fn main() -> surrealdb::Result<()> {
    tracing_subscriber::fmt()
        .with_env_filter(EnvFilter::from_default_env())
        .init();

    // Connect and query as usual
    Ok(())
}
```

```sh
RUST_LOG=surrealdb=info cargo run
```

`info` shows the datastore starting up. `trace` also shows each statement as it is parsed and executed, which is useful for debugging a query but produces a lot of output, and it only works in a debug build such as plain `cargo run`. SurrealDB enables the `release_max_level_debug` feature of `tracing`, which removes trace-level logging from release builds at compile time. Cargo combines a crate's features across the whole build, so this also applies to `trace!` calls in your own code when your program depends on SurrealDB.

The limit applies when `debug_assertions` is off, not to optimised builds as such. To trace an optimised build, add a profile that inherits from `release` and keeps debug assertions on:

```toml
[profile.release-trace]
inherits = "release"
debug-assertions = true
```

```sh
RUST_LOG=surrealdb=trace cargo run --profile release-trace
```

Within one process, the RocksDB and SurrealKV engines run many queries at once, including concurrent writes from many users to the same records, so the application has no single writer to wait for.

The datastore itself can only be open in one process at a time. RocksDB and SurrealKV lock the directory, so a second process that opens the same path, such as a `surreal start` server pointed at it while your application runs, fails with an error like `Database at mydb/LOCK is already locked by another process`. To share the data between processes, or to look at it in [SurrealDB Studio](/docs/explore/studio) during development, run the database as a server with [`surreal start`](/docs/reference/cli/surrealdb-cli/commands/start) and connect your application to it over `ws://`. With `surrealdb::engine::any::connect`, only the connection string changes between the embedded and the server setup, as [Tips and tricks on using the Rust SDK](https://surrealdb.com/blog/tips-and-tricks-on-using-the-rust-sdk#interchangeable-engines) shows. Stop the application's embedded connection before starting the server on the same path, because the lock is held for as long as the datastore is open.

The lock also applies within a single process. A second `Surreal::new()` or `connect()` call on a path that is already open fails. RocksDB reports `IO error: lock hold by current process ... LOCK: No locks available`, and SurrealKV reports `Database at mydb/LOCK is already locked by another process` even though the same process holds the lock. Open the datastore once and clone the client wherever another handle is needed, because a clone shares the open datastore. Tests often hit this error, because each `#[tokio::test]` function that runs its own setup code opens the path again. Give each test its own directory, or connect with `memory` so that every test has a separate in-memory datastore.

## `.init()` {#init}

The DB static singleton ensures that a single database instance is available across very large or complicated applications. With the singleton, only one connection to the database is instantiated, and the database connection does not have to be shared across components or controllers.

```rust title="Method Syntax"
Surreal::init()
```

### Example usage
```rust
static DB: LazyLock<Surreal<Client>> = LazyLock::new(Surreal::init);

#[tokio::main]
async fn main() -> surrealdb::Result<()> {
    // Connect to the database
    DB.connect::<Wss>("cloud.surrealdb.com").await?;
    // Select a namespace + database
    DB.use_ns("main").use_db("main").await?;
    // Create or update a specific record
    let tobie: Option<Record> = DB
        .update(("person", "tobie"))
        .content(Person { name: "Tobie" })
        .await?;
    Ok(())
}
```

```rust title="Method Syntax"
db.update(resource).merge(data)
```

> [!NOTE]
> This function merges the current document / record data with the specified data.

### Arguments
<table>
    <thead>
        <tr>
            <th colspan="2">Arguments</th>
            <th colspan="2">Description</th>
        </tr>
    </thead>
    <tbody>
        <tr>
            <td colspan="2" scope="row" data-label="Arguments">
                <code>resource</code>
                <label label="required" />
            </td>
            <td colspan="2" scope="row" data-label="Description">
                The table name or the specific record ID to create.
            </td>
        </tr>
        <tr>
            <td colspan="2" scope="row" data-label="Arguments">
                <code>data</code>
               <label label="optional" />
            </td>
            <td colspan="2" scope="row" data-label="Description">
                The document / record data to insert.
            </td>
        </tr>
    </tbody>
</table>

### Example usage
```rust
// Update all records in a table
let people: Vec<Person> = db.update("person")
    .merge(Document {
        updated_at: Datetime::default(),
    })
    .await?;
// Update a record with a specific ID
let person: Option<Person> = db.update(("person", "tobie"))
    .merge(Document {
        updated_at: Datetime::default(),
        settings: Settings {
            active: true,
        },
    })
    .await?;
```

### Translated query
This function will run the following query in the database:

```surql
UPDATE $resource MERGE $data;
```

## `.update().patch()` {#update-patch}

Applies JSON Patch changes to all records, or a specific record, in the database.

```rust title="Method Syntax"
db.update(resource).patch(data)
```

> [!NOTE]
> This function patches the current document / record data with the specified JSON Patch data.

### Arguments
<table>
    <thead>
        <tr>
            <th colspan="2">Arguments</th>
            <th colspan="2">Description</th>
        </tr>
    </thead>
    <tbody>
        <tr>
            <td colspan="2" scope="row" data-label="Arguments">
                <code>resource</code>
                <label label="required" />
            </td>
            <td colspan="2" scope="row" data-label="Description">
                The table name or the specific record ID to modify.
            </td>
        </tr>
        <tr>
            <td colspan="2" scope="row" data-label="Arguments">
                <code>data</code>
               <label label="optional" />
            </td>
            <td colspan="2" scope="row" data-label="Description">
                The JSON Patch data with which to modify the records.
            </td>
        </tr>
    </tbody>
</table>

### Example usage
```rust
// Update all records in a table
let people: Vec<Person> = db.update("person")
    .patch(PatchOp::replace("/created_at", Datetime::default()))
    .await?;

// Update a record with a specific ID
let person: Option<Person> = db.update(("person", "tobie"))
    .patch(PatchOp::replace("/settings/active", false))
    .patch(PatchOp::add("/tags", &["developer", "engineer"]))
    .patch(PatchOp::remove("/temp"))
    .await?;
```

### Translated query
This function will run the following query in the database:

```surql
UPDATE $resource PATCH $data;
```

## `.delete()` {#delete}

Deletes all records in a table, or a specific record, from the database.

```rust title="Method Syntax"
db.delete(resource)
```

### Arguments
<table>
    <thead>
        <tr>
            <th colspan="2">Arguments</th>
            <th colspan="2">Description</th>
        </tr>
    </thead>
    <tbody>
        <tr>
            <td colspan="2" scope="row" data-label="Arguments">
                <code>resource</code>
                <label label="required" />
            </td>
            <td colspan="2" scope="row" data-label="Description">
                The table name or a record ID to select.
            </td>
        </tr>
    </tbody>
</table>

### Example usage
```rust
// Delete all records from a table
let people: Vec<Person> = db.delete("person").await?;
// Delete a specific record from a table
let person: Option<Person> = db.delete(("person", "h5wxrf2ewk8xjxosxtyc")).await?;
```

### Translated query
This function will run the following query in the database:

```surql
DELETE FROM $resource RETURN BEFORE;
```
