Validate SurrealQL query files, or a query read from standard input, with the [installed](/docs/reference/cli/guides/install) `surreal` CLI and without connecting to a server.

<Synopsis>

</Synopsis>

## Example usage

To perform validation on a SurrealQL local file, in a terminal run the `surreal db validate` command with the required argument.

Using the command on its own will validate all the `.surql` files in the current directory and its subdirectories.

```bash
surreal db validate
```

```text
user1.surql: OK
user2.surql: OK
user3.surql: OK
```

You can perform validation on a single file, regardless of extension.

```bash
surreal db validate user.surql
surreal db validate user.txt
```

You can also perform validation on multiple files using a single glob pattern:

```bash
# equivalent to "surreal db validate"
surreal db validate **/*.surql
```

Finally, you can also perform validation on multiple files using multiple paths/patterns:

```bash
surreal db validate index.surql schemas/*.surql queries/*.surql
surreal db validate *.(txt|surql)
```

The command checks every file, and exits with an error if any of them is invalid.

```bash
surreal db validate
```

```text
user1.surql: OK
user2.surql: FAIL
Parse error: Unexpected token `an identifier`, expected Eof
 --> [1:15]
  |
1 | CREATE person SE name = "Billy";
  |               ^^
```

## Validating input from stdin

<Since v="v3.1.0" />

In addition to files, this command can also be used on the terminal with the `--stdin` flag to validate input from stdin.

An example of a valid query:

```bash
echo "SELECT * FROM example;" | surreal db validate --stdin
```

```text
<stdin>: OK
```

An example of an invalid query:

```bash
echo "CREATE WHERE value = ''" | surreal db validate --stdin
```

```text
<stdin>: FAIL
Parse error: Unexpected token `VALUE`, expected Eof
 --> [1:14]
  |
1 | CREATE WHERE value = ''
  |              ^^^^^
```
