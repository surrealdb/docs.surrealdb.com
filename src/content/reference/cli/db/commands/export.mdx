## Example usage

To perform a SurrealQL database export into a local file, in a terminal run the `surreal db export` command with the required arguments.

```bash
surreal db export --endpoint http://localhost:8000 --user root --pass secret --ns main --db main export.surql
```

Using token-based authentication:

```bash
surreal db export --endpoint http://localhost:8000 --token <token> --ns main --db main export.surql
```

To write the export to standard output instead of a file, for example to pipe it into another command, use `-` as the file name. From SurrealDB 4.0 the command then writes its log lines to standard error, so standard output holds only the export.

```bash
surreal db export --endpoint http://localhost:8000 --user root --pass secret --ns main --db main - > export.surql
```

Before SurrealDB 4.0, add `--log none` to the command above. Without it, the log line `INFO surrealdb::method::export: Exporting bytes` is written to standard output ahead of the export, and importing the result fails with a parse error on that line.

From SurrealDB 4.0, an export over `http://` or `https://` that fails part-way through makes the command fail with an error. Before 4.0, such a failure could end the export early without an error, and leave a file that was cut short, so check the end of an export file taken with an earlier release before you rely on it.

In Windows PowerShell 5, `>` saves the output as UTF-16, which `surreal import` refuses. Write the export to a file with `surreal export <file>` instead, or use PowerShell 7, which writes UTF-8.

## Choosing what to export

`--only` starts from an empty export, and each resource flag after it adds that resource back. The following command exports the table definitions and their records, and leaves out users, access methods, functions and every other definition:

```bash
surreal db export --endpoint http://localhost:8000 --user root --pass secret --ns main --db main --only --tables --records -- export.surql
```

Without `--records`, the same command exports only the table definitions, which gives the schema without the data. `--tables` also takes a comma-separated list, such as `--tables person,order`, to export only those tables.

The resource flags accept an optional value, so a flag directly before the file name reads the file name as its value and the command fails with `invalid value`. Put `--` before the file name, as in the example above, or put the file name before the flags.

### Choosing in SurrealDB Studio

[SurrealDB Studio](/docs/explore/studio) builds the same command for you. Open **Export database** and choose **Choose what to include**, then select the tables and the definitions you want. **Record data** corresponds to `--records`, and each other checkbox to the flag of the same name.

The **Use the CLI instead** section below the checkboxes shows the `surreal db export` command for that selection, with your connection's endpoint, namespace and database filled in. Running it from a terminal is faster for a large database, and it does not depend on the Studio window staying open.

## Passwords and credentials in an export

An export holds the password hash and SCRAM verifier of each database user only when the exporting user is allowed to edit the users of that database: an owner on the database, on its namespace or on the root, or any client of a server started with `--unauthenticated`. For any other user, each `DEFINE USER` statement in the export has `PASSHASH '[REDACTED]'` and `PASSSCRAM '[REDACTED]'` in place of the values. Export as an owner when the file has to restore the users' passwords.

A bucket defined by an earlier release can hold credentials in its `BACKEND` URL. The export replaces them with `[REDACTED]`, whoever runs the export, and SurrealDB 4.0 refuses that `DEFINE BUCKET` statement on import because a `BACKEND` URL cannot carry credentials. Before you import, remove the credentials from the URL and give the server its credentials from the environment. See [`DEFINE BUCKET`](/docs/reference/query-language/statements/define/bucket#credentials).

## Using environment variables

> [!IMPORTANT]
> Most of the flags above have a corresponding [environment variable](/docs/reference/cli/db/environment-variables#command-environment-variables).
> For example, the `--username` flag can be configured with the `SURREAL_USER` environment variable instead.

When using the `surreal db export` command, you can also use environment variables to set the values for the command-line flags.

For more on the environment variables available for CLI commands or SurrealDB instances in general, see the [environment variables](/docs/reference/cli/db/environment-variables#command-environment-variables) page.

## Managing a Cloud instance

To export from a SurrealDB Cloud instance by name, [`surreal cloud`](/docs/reference/cli/cloud) resolves the endpoint and credentials for you and then runs this command. The flags and file-format notes on this page still apply.

## OPTION IMPORT keyword

The output of a database export includes a line that contains the keywords `OPTION IMPORT`. This command is used internally to ensure that side effects do not run when the data is imported, such as [events](/docs/reference/query-language/statements/define/event) and [table views](/docs/reference/query-language/statements/define/table#pre-computed-table-views).

As of SurrealDB 3.0.4, imports via the [`surreal db import`](/docs/reference/cli/db/commands/import) and [`/import`](/docs/reference/rest-api/http-protocol#import) HTTP endpoint require the automatically generated `OPTION IMPORT` line to be present in order to disable events, live queries, field processing, and result output for optimal import performance. If side effects are desired when importing data, remove the line and use the [`/sql`](/docs/reference/rest-api/http-protocol#sql) endpoint instead.
