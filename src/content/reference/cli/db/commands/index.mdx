`surreal db` has **subcommands** for running the server, executing SurrealQL, importing and exporting data, and maintenance tasks. Each page documents that subcommand’s arguments, related environment variables, and typical usage.

<Synopsis>
surreal db [OPTIONS] <COMMAND>
</Synopsis>

| Subcommand | Purpose |
| --- | --- |
| [`surreal db start`](/docs/reference/cli/db/commands/start) | Run a SurrealDB server (in memory, on disk, or clustered). |
| [`surreal db sql`](/docs/reference/cli/db/commands/sql) | Open an interactive SurrealQL shell or run queries from scripts. |
| [`surreal db export`](/docs/reference/cli/db/commands/export) | Dump a database to SurrealQL. |
| [`surreal db fix`](/docs/reference/cli/db/commands/fix) | Apply data or schema fixes offline. |
| [`surreal db help`](/docs/reference/cli/db/commands/help) | Show help for `surreal db` or a subcommand. |
| [`surreal db import`](/docs/reference/cli/db/commands/import) | Load SurrealQL from a file into a database. |
| [`surreal db is-ready`](/docs/reference/cli/db/commands/isready) | Health check for readiness probes. |
| [`surreal db mcp`](/docs/reference/cli/db/commands/mcp) <Since v="v3.1.0" /> | Start the Model Context Protocol server on stdio for IDE integrations. |
| [`surreal db ml`](/docs/reference/cli/db/commands/ml) | Work with machine-learning features from the CLI. |
| `surreal db module` | Before SurrealDB 4.0, built and ran Surrealism modules. From 4.0 the commands are part of [`surreal ext`](/docs/reference/cli/ext), and `surreal db module` only says so. |
| [`surreal upgrade db`](/docs/reference/cli/db/commands/upgrade) | Upgrade the database component. Run by the launcher, not by `surreal db`. |
| [`surreal db validate`](/docs/reference/cli/db/commands/validate) | Validate SurrealQL or configuration. |
| [`surreal db version`](/docs/reference/cli/db/commands/version) | Print the database client version, or the version of a server. |

**Sidebar order:** [`start`](/docs/reference/cli/db/commands/start) and [`sql`](/docs/reference/cli/db/commands/sql) first, then remaining subcommands alphabetically.

## Shared options

Every `surreal db` subcommand accepts `-h` / `--help`, which prints its arguments and options and exits, and the logging option group (`-l` / `--log`, `--log-format`, `--log-file-*`, and the socket and OpenTelemetry overrides). Each page lists `--log` alongside the command's own flags and shows the full group in its command help output.

Most flags have an equivalent environment variable, listed in the tables on each page and in full on the [environment variables](/docs/reference/cli/db/environment-variables#command-environment-variables) page.

## What is not here

These subcommands act on a database that already exists or that you start yourself. Provisioning, pausing, scaling, and deleting SurrealDB Cloud instances is handled by [`surreal cloud instance`](/docs/reference/cli/cloud), which calls out to `surreal db` for SQL, imports, and exports, so the pages here still describe what happens once a Cloud instance has been resolved.

Installing, upgrading and selecting versions of the database is done by the launcher, with `surreal install db`, `surreal upgrade db`, `surreal use db@<VERSION>` and `surreal list`, described in the [launcher reference](/docs/reference/cli/launcher). The `surreal db upgrade` form is refused, with a message that names `surreal upgrade db`.

For installation and a minimal end-to-end example, see the [surreal db overview](/docs/reference/cli/db).
