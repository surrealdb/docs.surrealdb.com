SurrealDB has one command line, `surreal`. The `surreal` launcher installs once, then installs, versions and runs **components**, each with its own commands: the database (`surreal db`), SurrealDB Cloud (`surreal cloud`) and WebAssembly modules (`surreal mod`). This section is the reference for all of them. For how they fit together, start with the [SurrealDB CLI guide](/docs/explore/cli).

```bash
surreal install cloud
surreal db start --user root --pass secret
surreal cloud instance list
```

| Reference | Covers |
| --- | --- |
| [Launcher commands](/docs/reference/cli/launcher) | Installing, upgrading, pinning and removing components, version names, `+VERSION`, and the launcher's environment variables |
| [`surreal db`](/docs/reference/cli/db) | The database: run a server, query it, and move data in and out |
| [`surreal cloud`](/docs/reference/cli/cloud) | SurrealDB Cloud: organisations, instances, backups, members and tokens |
| [`surreal mod`](/docs/reference/cli/modules) | WebAssembly modules |
| [`surqlfmt`](/docs/reference/cli/formatter/overview) | Formatting `.surql` files, distributed separately as an npm package |

## Launcher commands

These commands belong to the launcher, and nothing else installs or changes component versions. See [Launcher commands](/docs/reference/cli/launcher) for options and examples.

| Command | Purpose |
| --- | --- |
| `surreal install <COMPONENT[@VERSION]>...` | Install components, or another version of one beside those installed |
| `surreal upgrade [<COMPONENT[@VERSION]> \| cli]...` | Upgrade the launcher and every installed component, or those named |
| `surreal use <COMPONENT@VERSION>` | Make an installed version the default |
| `surreal uninstall <COMPONENT[@VERSION]>...` | Remove a version, or a component entirely |
| `surreal version` | Show each component, the version that runs, and where it runs from |
| `surreal --version` | Print the launcher's version and each component's |
| `surreal +VERSION <COMPONENT> ...` | Run another version for one command |
| `surreal help` | Print the launcher's help |

## surreal db

The database component. Everything after `db` goes to the database, so the same flags and `SURREAL_*` variables apply. Each command has its own page under [database commands](/docs/reference/cli/db/commands).

| Command | Purpose |
| --- | --- |
| [`surreal db start`](/docs/reference/cli/db/commands/start) | Run a SurrealDB server |
| [`surreal db sql`](/docs/reference/cli/db/commands/sql) | Open an interactive SurrealQL shell |
| [`surreal db import`](/docs/reference/cli/db/commands/import) | Load a SurrealQL file into a database |
| [`surreal db export`](/docs/reference/cli/db/commands/export) | Dump a database to SurrealQL |
| [`surreal db is-ready`](/docs/reference/cli/db/commands/isready) | Check that a server accepts connections |
| [`surreal db validate`](/docs/reference/cli/db/commands/validate) | Validate SurrealQL files |
| [`surreal db fix`](/docs/reference/cli/db/commands/fix) | Repair storage issues |
| [`surreal db ml`](/docs/reference/cli/db/commands/ml) | Import and export machine-learning models |
| [`surreal db mcp`](/docs/reference/cli/db/commands/mcp) | Run the Model Context Protocol server over stdio |
| [`surreal db extension`](/docs/reference/cli/db/commands/extension) | Build, sign, install and run Surrealism extensions |
| [`surreal db version`](/docs/reference/cli/db/commands/version) | Print the database or server version |

The old top-level forms, such as `surreal start`, still run and print a deprecation warning. Upgrading the database is `surreal upgrade db`, a launcher command.

## surreal cloud

The SurrealDB Cloud component. Every command takes `--json`, and sends its data to stdout and everything else to stderr. See [global flags](/docs/reference/cli/cloud/global-flags) and [output and exit codes](/docs/reference/cli/cloud/output-and-exit-codes).

| Command | Purpose |
| --- | --- |
| [`surreal cloud auth`](/docs/reference/cli/cloud/commands/auth) | Sign in, sign out, and inspect credentials |
| [`surreal cloud org`](/docs/reference/cli/cloud/commands/org) | Manage organisations, usage, spend and plans |
| [`surreal cloud instance`](/docs/reference/cli/cloud/commands/instance) | Create, scale, pause, back up, connect to and delete instances |
| [`surreal cloud team`](/docs/reference/cli/cloud/commands/team) | Manage organisation members |
| [`surreal cloud invite`](/docs/reference/cli/cloud/commands/invite) | Manage organisation invitations |
| [`surreal cloud token`](/docs/reference/cli/cloud/commands/token) | Manage personal access tokens |
| [`surreal cloud catalog`](/docs/reference/cli/cloud/commands/catalog) | Browse regions, instance types and versions |
| [`surreal cloud config`](/docs/reference/cli/cloud/commands/config) | Read and write configuration |
| [`surreal cloud context`](/docs/reference/cli/cloud/commands/context) | Inspect and switch profiles |
| [`surreal cloud whoami`, `api`, `open`, `status`, `version`, `completion`](/docs/reference/cli/cloud/commands/misc) | Identity, raw API calls, dashboard links, diagnostics and shell completions |

## surreal mod

The WebAssembly extension component. Its first release is not published yet, and the same workflow is available today as `surreal db extension`, or `surreal db module` before SurrealDB 4.0. See [`surreal mod`](/docs/reference/cli/modules).

## SurrealQL formatter

`surqlfmt` reformats `.surql` files to a consistent style. It is distributed as an npm package rather than as a component of `surreal`, which makes it easy to pin in a project and run in CI.

```bash
npm install -g @surrealdb/surql-fmt
surqlfmt --check ./src/**/*.surql
```

See the [SurrealQL formatter reference](/docs/reference/cli/formatter/overview) for its options and usage patterns.
