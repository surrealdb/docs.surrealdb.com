`mod` is the launcher component for Surrealism extension tooling: scaffolding, building, inspecting and running extensions, which were called modules before SurrealDB 4.0. It is installed and versioned separately from the database, like every other component.

<Synopsis>
surreal mod <COMMAND>
</Synopsis>

> [!NOTE]
> The first release of the `mod` component is not published yet, so `surreal install mod` does not succeed. Until it is, the commands are available as [`surreal db extension`](/docs/reference/cli/db/commands/extension) from the database component, or `surreal db module` before SurrealDB 4.0. The top-level form `surreal module` is deprecated in favour of `surreal mod` and prints a warning.

## Commands available today

| Command | Purpose |
| --- | --- |
| `surreal db extension init [PATH]` | Scaffold a new extension project. |
| `surreal db extension build [SOURCE_PATH]` | Build a `.surli` archive. |
| `surreal db extension run <FILE> --fnc <NAME>` | Run a function with arguments. |
| `surreal db extension sig <FILE> --fnc <NAME>` | Show a function's signature. |
| `surreal db extension info <FILE>` | List the functions an archive exports. |
| `surreal db extension config <COMMAND>` | Read and change the project's `package.toml`. |
| `surreal db extension sign <FILE>` | Sign an archive. |
| `surreal db extension install <SOURCE> --as <NAME>` | Install an archive into a database. |
| `surreal db extension upgrade <NAME> [SOURCE]` | Redefine an installed extension from a new archive. |

Flags and examples are on the [`surreal db extension`](/docs/reference/cli/db/commands/extension) page. For a walkthrough, see [Working with extensions](/docs/explore/cli/extensions).
