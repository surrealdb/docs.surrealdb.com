# Enterprise Edition

SurrealDB Enterprise Edition uses the same core SurrealDB server, with additional capabilities enabled by a licence key. Enterprise and Community use different binaries, so Enterprise-only features are available only in the Enterprise build. Moving between Community and Enterprise does not require changes to your schema, queries, or SDK code.

## What the edition adds

| Capability | What it is | Documented |
| --- | --- | --- |
| **Fault tolerance** | Always-on clusters that run across different availability zones, so the database keeps serving through the loss of a node or a whole zone. | [SurrealDS](/docs/manage/enterprise/product/surrealds) |
| **Storage scalability** | A distributed storage architecture backed by object storage, so storage grows with your data without you having to shard the database. | [SurrealDS](/docs/manage/enterprise/product/surrealds) |
| **Compute scalability** | Horizontal scaling from 3 nodes to tens of nodes, to raise concurrency and the compute capacity available to your workload. | [SurrealDS](/docs/manage/enterprise/product/surrealds) |
| **Audit logging** | An identity-bound record of every authenticated action - statements, queries, transactions, RPC calls, sign-ins, sessions and HTTP requests - written to a durable NDJSON sink, with optional SHA-256 hash chaining and PII redaction. | [Audit logging](/docs/manage/observability/audit-logging) |
| **Distributed live queries** | Live queries that resolve across every node in a cluster rather than the node holding the subscription. | Contact sales |
| **FIPS mode** | FIPS 140-2 validated cryptographic modules, and the switch that enforces their use. | Contact sales |
| **Trusted execution** | Running the server inside a trusted execution environment, with attestation. | Contact sales |
| **Contractual support** | Support tiers with defined response times by severity, and uptime commitments. | Contact sales |

S3-compatible bucket backends were available in Enterprise builds only before 3.3.0. From 3.3.0 the Community build includes them, alongside Google Cloud Storage and Azure Blob Storage, and Enterprise uses the same backends. See [`DEFINE BUCKET`](/docs/reference/query-language/statements/define/bucket#cloud-object-storage-backends).

## Licence key

<Since v="v3.3.0" />

An Enterprise build needs a valid licence key to start. SurrealDB issues the key, and each node reads it from `SURREAL_LICENSE_KEY` or from the file that `SURREAL_LICENSE_KEY_FILE` names. Each node validates the key online against `api.keygen.sh` when it starts and every 30 minutes while it runs.

[Licensing](/docs/manage/enterprise/product/licensing) explains how to get a key, where to put it for Docker, your own machines and the Kubernetes operator, and what a node does when its licence expires or cannot be checked.

The Enterprise build is published on Docker Hub as [`surrealdb/surrealdb-enterprise`](https://hub.docker.com/r/surrealdb/surrealdb-enterprise). [Run with Docker](/docs/running/docker#running-surrealdb-enterprise) has an example that passes the licence key.

## SurrealDS

<Since v="v4.0.0" />

[SurrealDS](/docs/manage/enterprise/product/surrealds) is the distributed storage engine in SurrealDB Enterprise. It provides the fault tolerance, storage scalability and compute scalability in the table above. Run it with the [Kubernetes operator](/docs/manage/enterprise/product/surrealds/kubernetes-operator) or [on your own machines](/docs/manage/enterprise/product/surrealds/own-machines).

## Observability is where most of it is written down

The Enterprise observability surface is documented in full alongside the Community one, with the Enterprise-only parts marked. Start there rather than here:

- [Audit logging](/docs/manage/observability/audit-logging) - events captured, record shape, rotation, hash chaining, redaction and overflow semantics.
- [Configuration](/docs/manage/observability/configuration#audit-log-knobs) - every audit-log environment variable, and the compliance checklist for a tamper-evident deployment.
- [Enterprise observability](/docs/manage/observability/enterprise-observability) - the pipelines that exist only in an Enterprise build.
- [Slow-query logging](/docs/manage/observability/slow-query-logging) - the sister pipeline for the long tail of slow queries.

## Licensing and getting in touch

Licence models, pricing, support tiers and the specifics of FIPS, trusted execution and distributed live queries are handled by the SurrealDB team rather than published here. [Contact us](https://surrealdb.com/contact) to discuss an evaluation, a licence, or an upgrade from an existing Community cluster.

> [!NOTE]
> Moving an existing deployment to Enterprise does not migrate data. The same storage backend and the same schema are read by the Enterprise binary; the licence key is what changes.
