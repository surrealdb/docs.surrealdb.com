# SCIM provisioning

Use SCIM provisioning to let your identity provider create, update and deactivate the SurrealDB accounts of a single sign-on connection. SCIM (System for Cross-domain Identity Management) is a standard protocol that identity providers use to keep user accounts in other apps up to date.

Without SCIM, SurrealDB makes an account the first time a person signs in, and the account stays until you disable it. With SCIM, your identity provider tells SurrealDB when a person joins, changes or leaves, so an account that you disable in your identity provider stops working in SurrealDB too.

## Before you start

You need:

- A [single sign-on connection](/docs/manage/enterprise/single-sign-on) that works.
- Permission to update identity providers in your enterprise.
- An identity provider that supports SCIM 2.0, and access to its admin console.

SCIM is available for these connection types:

| Connection type | SCIM |
| --- | --- |
| Okta | Available |
| Microsoft Entra ID | Available |
| SAML | Available |
| OpenID Connect | Available |
| Google Workspace, ADFS, PingFederate, Keycloak | Not available |

## Step 1: Turn on SCIM for the connection

1. Open **Single sign-on** in your enterprise.
2. Open the connection.
3. Open the **Provisioning** tab.
4. Turn on **SCIM provisioning**.

Studio then shows the **SCIM base URL** for the connection. Each connection has its own URL.

## Step 2: Create a token

Your identity provider uses a bearer token to prove that it may change accounts.

1. On the **Provisioning** tab, select **Create token**.
2. Copy the token.
3. Select **Done**.

> [!WARNING]
> Studio shows the token one time only. Copy it before you select **Done** or leave the page. Anyone who has the token can create and deactivate accounts on this connection, so keep it in a secure place.

## Step 3: Connect your identity provider

In your identity provider, give the SCIM app these values:

| Setting | Value |
| --- | --- |
| Base URL, or tenant URL | The **SCIM base URL** from step 1 |
| Authentication | Bearer token |
| Token | The token from step 2 |
| Objects to manage | Users |

Then assign the people or groups to provision. Most identity providers send the first changes within a few minutes.

### Match the accounts people sign in with

SurrealDB reads one SCIM attribute as the user's ID. That ID must be the same one your identity provider sends when the person signs in. If the two are different, the person gets a second account the first time they sign in.

| Connection type | SCIM attribute used as the ID | Must equal |
| --- | --- | --- |
| Okta | `externalId` | The Okta user ID. Okta sends this by default. |
| Microsoft Entra ID | `externalId` | The user's object ID. |
| SAML | `userName` | The name ID in the SAML assertion. |
| OpenID Connect | `externalId` | The `sub` claim of the ID token. |

### Okta

Okta only allows SCIM on an OpenID Connect integration that you build with the Okta Integration Wizard. [Set up Okta](/docs/manage/enterprise/single-sign-on/okta) that way first.

1. In Okta, edit the `SurrealDB` integration.
2. Add the **SCIM provisioning** capability.
3. Under the provisioning settings, set **Base URL** to the SCIM base URL from step 1.
4. Choose to manage **Users**.
5. Turn on **Create**, **Update**, **Deactivate** and **Support PATCH**.
6. If Okta asks for the unique identifier field for users, enter `userName`.
7. Deploy the integration again.
8. On the `SurrealDB` app, open the **Provisioning** tab.
9. Under **Authentication settings**, set **Authentication mode** to **Bearer**, then paste the token from step 2.
10. Turn on the provisioning actions you want Okta to send: create users, update user attributes, and deactivate users.

### Microsoft Entra ID

Entra ID provisions users through an enterprise application, which is separate from the app registration that your connection signs in with.

1. In the Microsoft Entra admin center, open **Enterprise applications**, then select **New application**.
2. Select **Create your own application**, and choose **Integrate any other application you don't find in the gallery**.
3. Open **Provisioning**, and set **Provisioning Mode** to **Automatic**.
4. Set **Tenant URL** to the SCIM base URL from step 1, followed by `?aadOptscim062020`.
5. Set **Secret Token** to the token from step 2.
6. Select **Test Connection**.
7. Under **Mappings**, open the user mapping, and map `objectId` to `externalId`.
8. Assign the same people or groups as the app registration.
9. Turn provisioning on.

To try one person before everyone, use **Provision on demand**.

## What SurrealDB does with each change

| Change in your identity provider | Result in SurrealDB |
| --- | --- |
| A person is assigned to the app | SurrealDB makes their account. They join the enterprise the first time they sign in. |
| A person's name or email changes | SurrealDB updates their account. |
| A person is deactivated or unassigned | SurrealDB disables their login and ends their sessions. The **Members** page shows them as **Disabled**. |
| A person is activated again | SurrealDB enables their login again. |
| A person is deleted | SurrealDB deletes their account. |

SCIM does not assign roles. A new member holds no roles until you [grant them](/docs/manage/enterprise/roles).

## Rotate a token

A connection holds up to two tokens at a time. To replace a token without a gap in provisioning:

1. Create a new token.
2. Give the new token to your identity provider.
3. Beside the old token, select **Revoke token**.

The **Provisioning** tab shows when each token was last used, which helps you find a token that nothing uses any more.

## Turn off SCIM

Turn off **SCIM provisioning** on the **Provisioning** tab. SurrealDB revokes every token of the connection, and your identity provider can no longer change accounts. The accounts that SCIM made stay, and people can still sign in through the connection.
