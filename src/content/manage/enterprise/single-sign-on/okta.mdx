# Okta

Connect Okta to SurrealDB to allow members of your organisation to sign in with their Okta credentials. You create an OpenID Connect app integration in the Okta Admin Console, then enter its details in a new connection in SurrealDB Studio.

When you finish, people can sign in to SurrealDB through Okta. You can also let them open SurrealDB from their Okta dashboard, sign them out with Universal Logout, and let Okta create and deactivate their accounts with SCIM.

Before you start, [verify the email domain](/docs/manage/enterprise/single-sign-on#step-1-verify-an-email-domain) your company uses. You also need an Okta account that can create app integrations.

## Step 1: Create an app integration

1. In the Okta Admin Console, open **Applications and Resources**, then **Applications**.
2. Select **Create App Integration**.

![The Applications page in the Okta Admin Console, with the Create App Integration button highlighted.](~/assets/img/surrealdb/manage/enterprise-sso-okta-1.webp)

3. Under **Sign-in method**, select **OIDC - OpenID Connect**.
4. Under **Application type**, select **Web Application**.
5. Select **Next**.

![The Create and deploy private app integrations dialogue in Okta, with OIDC - OpenID Connect and Web Application selected.](~/assets/img/surrealdb/manage/enterprise-sso-okta-2.webp)

## Step 2: Configure the integration

1. Enter an **App integration name**, for example `SurrealDB`.
2. Under **Grant type**, make sure **Authorization Code** is selected.
3. Under **Sign-in redirect URIs**, enter `https://auth.surrealdb.com/login/callback`.
4. Under **Assignments**, choose who can use the integration. You can also assign people or groups later, from the integration's **Assignments** tab.
5. Select **Save**.

![The New Web App Integration form in Okta, with the sign-in redirect URI highlighted.](~/assets/img/surrealdb/manage/enterprise-sso-okta-3.webp)

Only the people and groups assigned to the integration can sign in to SurrealDB through it.

## Step 3: Copy the client credentials

Okta opens the **General** tab of the new integration.

1. Under **Client Credentials**, copy the **Client ID**.
2. Under **Client secrets**, copy the secret. Select the eye icon to show it, or the copy icon beside it.

![The General tab of the SurrealDB app integration in Okta, with the client ID and the client secret highlighted.](~/assets/img/surrealdb/manage/enterprise-sso-okta-4.webp)

You also need your Okta domain, for example `example.okta.com`. It is the domain of your Okta sign-in page, without `-admin`.

## Step 4: Add the connection in SurrealDB

1. Open **Single sign-on** in your enterprise and add a new connection.
2. Select **Okta**.
3. Under **Name the connection**, enter a **Display name**. Members see this name on the sign-in screen.
4. Under **Enter the Okta details**, enter:
    - **Okta domain**: your Okta domain, for example `example.okta.com`.
    - **Client ID**: the client ID from step 3.
    - **Scopes**: optional. Leave it empty to request `openid profile email`.
    - **Client secret**: the client secret from step 3.
5. Under **Route sign-in domains**, select the verified domains to send to this connection. This is optional, and you can change it later.
6. Select **Create connection**.

![The New Okta connection form in SurrealDB Studio, with the display name, Okta domain, client ID, client secret and a routed domain filled in.](~/assets/img/surrealdb/manage/enterprise-sso-okta-5.webp)

SurrealDB stores the client secret securely and does not show it again.

The connection's **Sign-on** tab, under **Set up Okta**, shows the values for the next steps, each with a copy button.

## Step 5: Show SurrealDB on the Okta dashboard

The Okta dashboard shows a tile for each app a person is assigned. For the tile to open SurrealDB, Okta needs the address that starts a sign-in.

1. In Studio, copy the **Initiate login URI** from the connection's **Sign-on** tab.
2. In Okta, open the `SurrealDB` app integration, then the **General** tab.
3. Edit **General Settings**.
4. Set **Login initiated by** to **Either Okta or App**.
5. Turn on **Display application icon to users**.
6. Paste the value into **Initiate login URI**.
7. Select **Save**.

When a person selects the tile, Okta sends them to SurrealDB, and SurrealDB signs them in through this connection. They do not have to enter their email address.

## Step 6: Sign people out with Universal Logout

Okta Universal Logout signs a person out of every app at once, for example when Okta detects a risk or an admin ends their sessions. SurrealDB supports it through Global Token Revocation (GTR). When Okta calls the revocation URL, SurrealDB ends that person's sessions and revokes their refresh tokens.

Universal Logout needs Okta Identity Threat Protection in your Okta org. Skip this step if you do not use it.

1. In Studio, copy the **Global token revocation URL** from the connection's **Sign-on** tab.
2. In Okta, open the `SurrealDB` app integration, and edit its logout settings.
3. Select **Okta system or admin initiates logout**.
4. Paste the value as the logout endpoint.
5. Keep the authentication type as **Signed JWT**.
6. Set the **Subject format** to **Issuer and Subject Identifier**.
7. Save the settings.

SurrealDB needs no other configuration. It checks each request with the same keys that it uses to check sign-ins from your Okta org.

## Step 7: Provision users with SCIM

With SCIM, Okta creates, updates and deactivates people's SurrealDB accounts. Skip this step if you do not want Okta to manage accounts.

Okta does not allow SCIM on an OpenID Connect app integration, so SCIM uses a second app integration. People sign in with the first app, and Okta provisions their accounts with the second. The second app does not sign anyone in, and you hide it from the dashboard.

In Studio, [turn on SCIM and create a token](/docs/manage/enterprise/scim-provisioning) for the connection. Keep the **SCIM base URL** and the token ready.

### Create the provisioning app

1. In the Okta Admin Console, open **Applications**, then select **Create App Integration**.
2. Select **SWA - Secure Web Authentication**, then **Next**.
3. Enter an **App name**, for example `SurrealDB provisioning`.
4. Set **App's login page URL** to `https://studio.surrealdb.com`.
5. Turn on **Do not display application icon to users**.
6. Select **Finish**.
7. On the **General** tab, edit **App Settings**, set **Provisioning** to **SCIM**, then select **Save**.

### Connect the provisioning app to SurrealDB

1. Open the **Provisioning** tab, then **Integration**, and select **Edit**.
2. Set **SCIM connector base URL** to the SCIM base URL.
3. Set **Unique identifier field for users** to `userName`.
4. Under **Supported provisioning actions**, select **Push New Users** and **Push Profile Updates**.
5. Set **Authentication Mode** to **HTTP Header**, and paste the token into **Authorization**.
6. Select **Test Connector Configuration**, then **Save**.
7. Open **Provisioning**, then **To App**, and select **Edit**.
8. Turn on **Create Users**, **Update User Attributes** and **Deactivate Users**, then select **Save**.

### Assign people

Assign the same people or groups to both app integrations. A person assigned only to the provisioning app gets an account but cannot sign in. A person assigned only to the sign-in app signs in, but Okta does not manage their account.

Assign one Okta group to both apps, so the two assignments stay the same.

Okta sends the Okta user ID as the SCIM `externalId`, which is the same ID that the sign-in app sends. You do not have to change any attribute mapping.
