# Connect to an instance

An instance exposes one endpoint, and every client reaches it the same way. What differs is the tool you use and how you authenticate.

| Route | Use it for |
| --- | --- |
| [SurrealDB Studio](/docs/manage/instances/connect/via-studio) | Running queries and browsing data in a graphical interface. |
| [CLI](/docs/manage/instances/connect/via-cli) | An interactive SurrealQL shell, and one-off queries from a terminal or a script. |
| [SDK](/docs/manage/instances/connect/via-sdk) | Application code in Rust, JavaScript, Python, .NET, PHP, and the other supported languages. |
| [HTTP](/docs/manage/instances/connect/via-http) | cURL, Postman, and any HTTP client, including bulk import. |

## Before you begin

You need:

- An account — see [Accounts and sign-in](/docs/manage/organisations/sign-in).
- A running instance — see [Create an instance](/docs/manage/instances/create).
- A **namespace** and **database** to work in. SurrealDB needs both to know where a query runs; see [system structure](/docs/concepts#system-structure).
- Credentials, unless you are connecting from SurrealDB Studio, which authenticates with your own session.

## Finding the connection details

The instance's **Connect** menu in [SurrealDB Studio](https://app.surrealdb.com) holds the endpoint and produces a ready-made command or snippet for each route, with your instance's details already filled in. Copying from there avoids transcription mistakes in the hostname.

`surrealctl instance endpoint` prints the same endpoint, and `surrealctl instance token` issues a token for it — useful in scripts and CI, where opening a browser is not an option. See [surrealctl instances](/docs/manage/surrealctl/instances).
