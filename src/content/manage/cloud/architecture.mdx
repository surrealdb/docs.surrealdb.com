# Cloud architecture

SurrealDB Cloud benefits from [SurrealDB's layered architecture](/docs/architecture), which separates storage from compute, enabling improved scalability, durability and availability without the need to operate, manage, scale or shard your database.

## Start

For development and staging applications with vertically scalable requirements. SurrealDB Cloud **Start** provides a single compute node backed by dedicated disk-based storage, which you can resize as workloads grow.

## Scale

For **business-critical** applications that must stay available when a node fails and scale query throughput horizontally. **Scale** clusters run on [SurrealDS](https://surrealdb.com/platform/surrealds), SurrealDB's distributed storage engine — with quorum consensus and compute–storage separation — and start at **three nodes**. Each node runs in a different availability zone within the same region, backed by its own disk-based storage.

Data is continuously replicated between nodes, and every node can serve reads, writes and queries. Scale handles replication and distributed transactions for you. To scale out, add nodes in odd numbers — three, then five, then seven — so the cluster can always reach a quorum.

Provisioning a production cluster on SurrealDB Cloud avoids the operational work of self-hosting: Kubernetes, replication, patching, backups, and upgrade orchestration are managed for you.

<img src="~/assets/img/image/cloud/light/enterprise-multi-node-light.png" darkSrc="~/assets/img/image/cloud/enterprise-multi-node.png" alt="SurrealDB Cloud Scale architecture" />

> [!NOTE]
> Several Scale capabilities are still on the roadmap: object-storage backing (keeping hot data on disk and cold data in object storage, which in turn enables instant database branching), cross-region replication, automatic sharding, and read replicas. See [Pricing](https://surrealdb.com/pricing) and [Roadmap](https://surrealdb.com/roadmap) for current availability.

To learn more about deployment models and self-hosted SurrealDS, see [Deployment](/docs/build/deployment) and [SurrealDS](https://surrealdb.com/platform/surrealds).
