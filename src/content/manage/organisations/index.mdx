# Organisations

An organisation groups instances, people, usage, and billing. It is the boundary that matters operationally: invoices, [instances](/docs/manage/instances), and [access](/docs/manage/organisations/members-and-roles) all belong to exactly one organisation, so nobody in one can change or see the resources of another.

Create one per company, department, or environment you want kept separate. Splitting production from development into two organisations gives each its own member list and its own invoice, which is worth more than the convenience of having everything in one place.

## Creating an organisation

1. On the overview page in [SurrealDB Studio](https://app.surrealdb.com), select **Create organisation**.
2. Enter a name and confirm.

You become its [owner](/docs/manage/organisations/members-and-roles) and land on the organisation overview. The breadcrumb at the top of Studio switches between the organisations you belong to.

`surrealctl org create` does the same from a terminal, and `surrealctl org use` selects which organisation subsequent commands apply to. See [surrealctl organisations](/docs/manage/surrealctl/organisations).

## The organisation view

The overview page collects what the organisation currently holds, with the sidebar leading into each area.

![The overview page for the Acme Corp organisation in SurrealDB Studio, listing the api-production, api-staging and analytics-eu instances with a Deploy new instance button, the support-agent and research-agent Spectron contexts below them, and a Resources panel linking to documentation, SurrealDB University, AI agents and community, with a sidebar holding Overview, Instances, Contexts, Connections, Team, Billing, Support, Usage and Settings.](~/assets/img/surrealdb/manage/studio-overview.webp)

| Section | What it holds |
| --- | --- |
| **Instances** | Every [instance](/docs/manage/instances) in the organisation. Deploy, open, and filter them here. |
| **Team** | [Members, invitations, and roles](/docs/manage/organisations/members-and-roles). |
| **Billing** | [Billing details, payment method, discount codes, and invoices](/docs/manage/organisations/billing). |
| **Usage** | [Compute, storage, and spend](/docs/manage/organisations/billing#usage-and-spend) for the current or previous month. |
| **Support** | [Support plans and tickets](/docs/manage/organisations/support). |
| **Settings** | The organisation name and its id. |

**Contexts** and **Connections** cover [Spectron](/docs/spectron) rather than database instances; they share the organisation for billing and access.

What you see depends on your role. A member without billing permissions does not get the Billing section — see [Members and roles](/docs/manage/organisations/members-and-roles).

## Organisation settings

**Settings** holds two things: the display name, which you can change at any time, and the organisation id.

![The Settings page for the Acme Corp organisation in SurrealDB Studio, with an editable Name field, a read-only Organisation ID field with a copy button noting the id may be requested by the SurrealDB support team, and a Save changes button.](~/assets/img/surrealdb/manage/organisation-settings.webp)

Quote the **organisation id** when raising a [support ticket](/docs/manage/organisations/support); it identifies the organisation unambiguously where a display name might not.

Organisations cannot currently be deleted. Delete the instances inside one you have finished with, and it stops accruing charges.
