# Migrating

This section describes how to move data into SurrealDB: from other databases, from files or streams (for example CSV, JSON Lines, or Kafka), and from older SurrealDB versions. Use the part that matches your source.

## From other databases

Each page maps the data, queries and concepts of a database you may know to SurrealDB. All of these sources can be imported automatically with the [Surreal Sync](https://github.com/surrealdb/surreal-sync/) tool.

- [MongoDB](/docs/integrate/migrating/from-other-databases/from-mongodb)
- [MySQL](/docs/integrate/migrating/from-other-databases/from-mysql)
- [Neo4j](/docs/integrate/migrating/from-other-databases/from-neo4j)
- [PostgreSQL](/docs/integrate/migrating/from-other-databases/from-postgresql)
- [Snowflake](/docs/integrate/migrating/from-other-databases/from-snowflake)

## From files and streams

Surreal Sync also imports these sources. [CSV data](/docs/integrate/migrating/from-files-and-streams/csv) can also be imported in SurrealDB Studio with its [built-in functionality](/docs/reference/studio).

- [CSV data](/docs/integrate/migrating/from-files-and-streams/csv)
- [JSON Lines](/docs/integrate/migrating/from-files-and-streams/json-lines)
- [Kafka](/docs/integrate/migrating/from-files-and-streams/kafka)

## A source that Surreal Sync does not cover

Export the data as [JSON Lines](/docs/integrate/migrating/from-files-and-streams/json-lines) and import it with Surreal Sync, or write it out as SurrealQL `INSERT` statements and load the file with [`surreal db import`](/docs/reference/cli/db/commands/import), which takes a SurrealQL file. You can also use [one of the many available SDKs](/docs/languages) to read from your existing database and transfer its content directly to a SurrealDB instance.

## From an older SurrealDB version

The [upgrade guides](/docs/operate/upgrading) explain how to upgrade, with a guide for each version change: [1.x to 2.x](/docs/operate/upgrading/1x-to-2x), [2.6 to 2.7](/docs/operate/upgrading/26-to-27), [2.x to 3.x](/docs/operate/upgrading/2x-to-3x), [3.2 to 3.3](/docs/operate/upgrading/32-to-33) and [3.x to 4.0](/docs/operate/upgrading/3x-to-4x).

## Moving between SurrealDB Cloud instances

A Free instance moves to a paid instance type in place, from the **Compute** tab of its settings, with no migration. See [Scaling](/docs/operate/instances/scaling#scaling-a-start-instance).

Moving from Start to Scale, or to another region, needs a new instance. Deploy it, then [restore a backup](/docs/operate/instances/backups) or [import an export](/docs/operate/instances/import-and-export) into it.
