This tutorial turns ordinary Rust code into a SurrealDB extension, from `surreal ext init` through to calling its functions from SurrealQL. Extensions were called modules before SurrealDB 4.0, and the earlier commands and statements are shown where they differ.

## Getting started: regular Rust code

Starting a Surrealism project is best done using the `surreal ext init` command, which is similar to `cargo new` when starting a project in Rust. The `Cargo.toml` file will include the following line to instruct cargo to generate a `.wasm` file instead of the standard `.rlib` file when compiling Rust.

```toml
[lib]
crate-type = [ "cdylib" ]
```

The command will also ask for the project and organisation name, which will lead to the following `package.toml` file. Before SurrealDB 4.0 the file was called `surrealism.toml` and held `abi = 2`.

```toml
target = "rust"
abi = 4

[package]
organisation = "my_organisation"
name = "surrealism_fun"
version = "1.0.0"

[capabilities]
allow_scripting = false
allow_arbitrary_queries = false
allow_write = false
allow_functions = []
allow_net = []
strict_timeout = true

[attach]
```

You'll also notice a few sample functions inside `lib.rs`. To internalise how Surrealism works, let's delete them and begin with three of our own functions that we would like to call using SurrealQL.

One is a simple function that returns a bool.

```rust
fn can_drive(age: i64) -> bool {
    age >= 18
}
```

The second returns a `Result`.

```rust
fn parse_number(input: String) -> Result<i64, ParseIntError> {
    input.parse::<i64>()
}
```

And the third returns a `User` struct via a function called `random_user()` which uses the [fake](https://docs.rs/fake/4.4.0/fake/index.html) crate to create a user with a random English first name, French middle name, and German last name. This struct is annotated with the `SurrealValue` trait, allowing its return value to be understood on the SurrealDB side.

```rust
#[derive(Debug, SurrealValue)]
pub struct User {
    first_name: String,
    middle_name: String,
    last_name: String,
	age: i32
}

pub fn random_user() -> User {
    User {
        first_name: FirstName(EN).fake(),
        middle_name: FirstName(FR_FR).fake(),
        last_name: LastName(DE_DE).fake(),
		age: random_range(10..=50)
    }
}
```

Here is all of the code.

```rust
use fake::faker::name::raw::*;
use fake::{Fake, locales::*};
use rand::random_range;
use surrealdb_types::SurrealValue;
use std::num::ParseIntError;

#[derive(Debug, SurrealValue)]
pub struct User {
    first_name: String,
    middle_name: String,
    last_name: String,
	age: i32
}

fn can_drive(age: i64) -> bool {
    age >= 18
}

fn parse_number(input: String) -> Result<i64, ParseIntError> {
    input.parse::<i64>()
}

pub fn random_user() -> User {
    User {
        first_name: FirstName(EN).fake(),
        middle_name: FirstName(FR_FR).fake(),
        last_name: LastName(DE_DE).fake(),
		age: random_range(10..=50)
    }
}
```

## Annotating functions

The functions that we want to call from inside SurrealQL can now be exposed by adding the `#[surrealism]` annotation.

```rust
use fake::faker::name::raw::*;
use fake::{Fake, locales::*};
use rand::random_range;
use surrealdb_types::SurrealValue;
use surrealism::surrealism;
use std::num::ParseIntError;

#[derive(Debug, SurrealValue)]
pub struct User {
    first_name: String,
    middle_name: String,
    last_name: String,
	age: i32
}

#[surrealism]
fn can_drive(age: i64) -> bool {
    age >= 18
}

#[surrealism]
fn parse_number(input: String) -> Result<i64, ParseIntError> {
    input.parse::<i64>()
}

#[surrealism]
pub fn random_user() -> User {
    User {
        first_name: FirstName(EN).fake(),
        middle_name: FirstName(FR_FR).fake(),
        last_name: LastName(DE_DE).fake(),
		age: random_range(10..=50)
    }
}
```

With this done, the Rust code can now be compiled with the [`extension build`](/docs/reference/cli/ext#ext-build) command. The `--out` flag sets the output file name or path, such as `demo.surli`; without it, the archive is named after the organisation, name and version in `package.toml`. If you are in a separate folder, follow this with the path to the Rust code with functions to expose.

```bash
surreal ext build --out demo.surli /Users/my_name/my_rust_code
```

For faster local iteration:

```bash
surreal ext build --debug --out demo.surli /Users/my_name/my_rust_code
```

The file will now be compiled at either your current location or the one specified like in the command above: `/Users/my_name/my_rust_code`.

That's the extension archive that SurrealDB can point to!

## Calling the Surrealism file from SurrealDB

The Surrealism file is ready to be used. All that is left now is to start a database with two environment variables. They are:

* `SURREAL_CAPS_ALLOW_EXPERIMENTAL=surrealism`, which allows the experimental surrealism feature to be used in the first place. The [files](/docs/reference/query-language/statements/define/bucket) feature is not experimental, and files can be used once a `DEFINE BUCKET` statement has set up the location for the files to be stored. Before SurrealDB 4.0, files were experimental too, so use `files,surrealism` there.
* `SURREAL_BUCKET_FOLDER_ALLOWLIST="/Users/my_name/my_rust_code/"`, which tells the database that it's okay to access this folder when using the files feature.

Now it's time to [start the database](/docs/reference/cli/db/commands/start) with the `surreal db start` command and these two env vars.

<Tabs syncKey="shell">

<TabItem label="Bash">
```bash
SURREAL_CAPS_ALLOW_EXPERIMENTAL=surrealism SURREAL_BUCKET_FOLDER_ALLOWLIST="/Users/my_name/my_rust_code/" surreal db start --user root --pass secret
```
</TabItem>

<TabItem label="PowerShell">
```powershell
$env:SURREAL_CAPS_ALLOW_EXPERIMENTAL = "surrealism"
$env:SURREAL_BUCKET_FOLDER_ALLOWLIST = "C:\Users\my_name\my_rust_code"
surreal db start --user root --pass secret
```
</TabItem>
</Tabs>

You can then connect through [SurrealDB Studio](/docs/explore/studio) or the CLI with the [surreal db sql](/docs/reference/cli/db/commands/sql) command:

<Tabs syncKey="shell">

<TabItem label="Bash">
```bash
SURREAL_CAPS_ALLOW_EXPERIMENTAL=surrealism SURREAL_BUCKET_FOLDER_ALLOWLIST="/Users/my_name/my_rust_code/" surreal db sql --user root --pass secret
```
</TabItem>

<TabItem label="PowerShell">
```powershell
$env:SURREAL_CAPS_ALLOW_EXPERIMENTAL = "surrealism"
$env:SURREAL_BUCKET_FOLDER_ALLOWLIST = "C:\Users\my_name\my_rust_code"
surreal db sql --user root --pass secret
```
</TabItem>
</Tabs>

We're almost there! Only two statements left and we can start accessing these functions.

The first is a [DEFINE BUCKET](/docs/reference/query-language/statements/define/bucket) statement to create a bucket called `test`, linked to the folder that we have allowed the database to access. The "file:/" prefix in this statement tells the `DEFINE BUCKET` statement that this path is to a file, not storage in memory.

```surql
DEFINE BUCKET test BACKEND "file:/users/my_name/my_rust_code";
```

Now that we have a bucket called `test`, the `demo.surli` file will be available to us at the f"test:/demo.surli" path. The `f` there is an instruction to treat the string as a file path instead of just a regular string.

Then we can [define an extension](/docs/reference/query-language/statements/define/extension), giving it the name `test` and connecting it to the file. The statement changed in 3.3 and again in 4.0, so pick the tab that matches your version.

<Tabs syncKey="define-module-version">
  <TabItem label="SurrealDB 4.0 and later">

`UNSIGNED` says that the archive is loaded without checking a signature, which suits an extension you built yourself. A signed archive takes `SIGNER` instead, as described in [`SIGNER` and `UNSIGNED`](/docs/reference/query-language/statements/define/extension#signer-and-unsigned).

```surql
DEFINE EXTENSION ext::test FROM f"test:/demo.surli" UNSIGNED;
```

  </TabItem>
  <TabItem label="SurrealDB 3.3">

`FROM` replaces `AS`, and `UNSIGNED` is required.

```surql
DEFINE MODULE mod::test FROM f"test:/demo.surli" UNSIGNED;
```

  </TabItem>
  <TabItem label="Before SurrealDB 3.3">

`AS` connects the module name to the file.

```surql
DEFINE MODULE mod::test AS f"test:/demo.surli";
```

  </TabItem>
</Tabs>

The functions are now ready to call. The `parse_number()` function is available at the `ext::test::parse_number` path. Before SurrealDB 4.0, the path starts with `mod::` instead.

```surql
ext::test::parse_number("10");
//- 10
ext::test::parse_number("Hi I'm number");
//- 'Thrown error: WASM function returned error: invalid digit found in string'
```

Next, we can use `random_user()` to create some random users.

```surql
CREATE user CONTENT ext::test::random_user();
//- [{ age: 18, first_name: 'Thomas', id: user:hr8ohmn36zrpv3zthhnf, last_name: 'Meier', middle_name: 'Ninon' }]
CREATE user CONTENT ext::test::random_user();
//- [{ age: 13, first_name: 'Verda', id: user:zg0ucdjizdp71fzq9syc, last_name: 'Schuster', middle_name: 'Clarisse' }]
CREATE user CONTENT ext::test::random_user();
//- [{ age: 45, first_name: 'Zelda', id: user:rulp2bf82twrh94ifhsh, last_name: 'Berger', middle_name: 'Noah' }]
```

That leaves us with one function left to try out, the `can_drive()` function.

```surql
SELECT 
    first_name + ' ' + middle_name + ' ' + last_name AS name, 
    ext::test::can_drive(age) AS can_drive
FROM user;
```

Two of them can drive, but not Verda Clarisse Schuster who is far too young.

```surql
[
    { can_drive: true,  name: 'Thomas Ninon Meier' }, 
    { can_drive: true,  name: 'Zelda Noah Berger' }, 
    { can_drive: false, name: 'Verda Clarisse Schuster' }
]
```
