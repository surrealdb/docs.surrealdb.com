# Multi-model

A data model is the shape a database gives your data. In a relational database, records with the same fields go in a table, and tables are connected by foreign keys: fields that hold the key of a record in another table. If data models are new to you, [Data models](/docs/learn/database-basics/data-models) in the database basics section introduces the relational, document and graph styles of data, and lookups by record ID.

SurrealDB is a multi-model database, which means that it can store data in different formats. This flexibility allows you to choose the most appropriate data model for your use case, whether you are storing [graph](/docs/learn/data-models/graph/overview), [document](/docs/learn/data-models/document/overview), [time-series](/docs/learn/data-models/time-series/overview), [vector](/docs/learn/data-models/vector-search/overview), [full-text search](/docs/learn/data-models/full-text-search/overview), or [geospatial](/docs/learn/data-models/geospatial/overview) data.

Throughout this section, you will explore the different data models that SurrealDB supports and how they can be achieved using SurrealQL. You will also learn about how to think in SurrealDB whether you are a SQL, NoSQL, or graph developer.
