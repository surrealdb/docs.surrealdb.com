# Recursive traversals

[Recursive queries](/docs/reference/query-language/language-primitives/idioms#recursive-paths) let you follow a path to a specific depth without spelling out every hop.

## Family tree example

`person` records linked by `child_of`:

```surql
/**[test]

[[test.results]]
error = false

[[test.results]]
error = false

[[test.results]]
error = false

[[test.results]]
error = false

[[test.results]]
error = false

[[test.results]]
error = false

[[test.results]]
error = false

[[test.results]]
error = false

*/
CREATE |person:1..16|;
-- parents of person:1
RELATE person:1->child_of->[person:2, person:3];
-- grandparents of person:1
RELATE person:2->child_of->[person:4, person:5];
RELATE person:3->child_of->[person:6, person:7];
-- great-grandparents of person:1
RELATE person:4->child_of->[person:8, person:9];
RELATE person:5->child_of->[person:10, person:11];
RELATE person:6->child_of->[person:12, person:13];
RELATE person:7->child_of->[person:14, person:15];
```

Each step of `->child_of->person` goes back one generation:

The great-grandparents, person:8 to person:15, are returned by @.{3}." />

```surql
error = false

*/
-- Setup from the example above
CREATE |person:1..16|;
-- parents of person:1
RELATE person:1->child_of->[person:2, person:3];
-- grandparents of person:1
RELATE person:2->child_of->[person:4, person:5];
RELATE person:3->child_of->[person:6, person:7];
-- great-grandparents of person:1
RELATE person:4->child_of->[person:8, person:9];
RELATE person:5->child_of->[person:10, person:11];
RELATE person:6->child_of->[person:12, person:13];
RELATE person:7->child_of->[person:14, person:15];

SELECT 
    ->child_of->person AS parents,
    ->child_of->person->child_of->person AS grandparents,
    ->child_of->person->child_of->person->child_of->person AS great_grandparents
FROM ONLY person:1;
```

```surql
RELATE person:3->child_of->[person:6, person:7];
-- great-grandparents of person:1
RELATE person:4->child_of->[person:8, person:9];
```

Recursive syntax can also return a **single nested object** that repeats down a path:

```surql
/**[test]

[[test.results]]
error = false

[[test.results]]
error = false

[[test.results]]
error = false

[[test.results]]
error = false

[[test.results]]
error = false

[[test.results]]
error = false

[[test.results]]
error = false

[[test.results]]
error = false

[[test.results]]
error = false

*/
-- Setup from the example above
CREATE |person:1..16|;
-- parents of person:1
RELATE person:1->child_of->[person:2, person:3];
-- grandparents of person:1
RELATE person:2->child_of->[person:4, person:5];
RELATE person:3->child_of->[person:6, person:7];
-- great-grandparents of person:1
RELATE person:4->child_of->[person:8, person:9];
RELATE person:5->child_of->[person:10, person:11];
RELATE person:6->child_of->[person:12, person:13];
RELATE person:7->child_of->[person:14, person:15];

-- Range to start at a depth of one, try to go down to depth of three
SELECT @.{3}.{
    id,
	-- At each depth, use this path to reach the next one
    parents: ->child_of->person.@
} FROM person:1;
```

Starting from a record id:

```surql
/**[test]

[[test.results]]
error = false

[[test.results]]
error = false

[[test.results]]
error = false

[[test.results]]
error = false

[[test.results]]
error = false

[[test.results]]
error = false

[[test.results]]
error = false

[[test.results]]
error = false

[[test.results]]
error = false

*/
-- Setup from the example above
CREATE |person:1..16|;
-- parents of person:1
RELATE person:1->child_of->[person:2, person:3];
-- grandparents of person:1
RELATE person:2->child_of->[person:4, person:5];
RELATE person:3->child_of->[person:6, person:7];
-- great-grandparents of person:1
RELATE person:4->child_of->[person:8, person:9];
RELATE person:5->child_of->[person:10, person:11];
RELATE person:6->child_of->[person:12, person:13];
RELATE person:7->child_of->[person:14, person:15];

person:1.{3}.{
    id,
    parents: ->child_of->person.@
};
```

Recursive paths are defined in idioms and are not limited to graph traversal. A record link recurses through the same syntax, with no edges involved:

```surql
/**[test]

[[test.results]]
error = false

[[test.results]]
error = false

[[test.results]]
error = false

[[test.results]]
value = "cat:one"

*/
CREATE cat:one   SET likes = cat:two;
CREATE cat:two   SET likes = cat:three;
CREATE cat:three SET likes = cat:one;

cat:one.{1..3}.likes;
```

```surql title="Output"
cat:one
```

What a recursive path needs at each step is a record, or an array of records. That is what a link and an edge have in common. A step landing on any other value ends the query rather than continuing. See [Behaviour of recursive queries](/docs/reference/query-language/language-primitives/idioms#behaviour-of-recursive-queries).

## Trees of any depth

A tree, such as a set of categories or a folder structure, can be stored as one record per node with a `child_of` edge to its parent. Each node can then be read on its own like any other record, and a recursive path reads the tree in either direction without knowing its depth:

```surql
/**[test]

[[test.results]]
error = false

[[test.results]]
error = false

[[test.results]]
error = false

[[test.results]]
error = false

[[test.results]]
value = "[node:a1, node:a, node:root]"

[[test.results]]
value = "[node:a, node:b, node:a1, node:a2, node:a1x]"

*/
CREATE node:root, node:a, node:b, node:a1, node:a2, node:a1x;
RELATE [node:a, node:b]->child_of->node:root;
RELATE [node:a1, node:a2]->child_of->node:a;
RELATE node:a1x->child_of->node:a1;

-- Every ancestor of a node, nearest first
node:a1x.{..+collect}(->child_of->node);
//- [node:a1, node:a, node:root]

-- Every descendant of a node. Possible output, since the order of
-- siblings follows the IDs of their edges
node:root.{..+collect}(<-child_of<-node);
//- [node:a, node:b, node:a1, node:a2, node:a1x]
```

To get the tree or a subtree back in its nested shape, use `.@` to repeat the same structure at each level:

```surql
/**[test]

[[test.results]]
error = false

[[test.results]]
error = false

[[test.results]]
error = false

[[test.results]]
error = false

[[test.results]]
error = false

*/
-- Setup from the example above
CREATE node:root, node:a, node:b, node:a1, node:a2, node:a1x;
RELATE [node:a, node:b]->child_of->node:root;
RELATE [node:a1, node:a2]->child_of->node:a;
RELATE node:a1x->child_of->node:a1;

node:a.{..}.{ id, children: <-child_of<-node.@ };
```

```surql title="Possible output"
{
	children: [
		{
			children: [
				{ children: [], id: node:a1x }
			],
			id: node:a1
		},
		{ children: [], id: node:a2 }
	],
	id: node:a
}
```

Moving a subtree is one change: delete the node's `child_of` edge and relate it to its new parent. A path without an upper bound stops at a depth of 256.

## Routes with costs

<Since v="v4.1.0" />

A recursion can search for the cheapest path as well as the shortest one. The edge between two records carries the cost, and a [marker](/docs/reference/query-language/language-primitives/idioms#naming-an-edge-with-a-marker) names the edge so that `+weight` can read it. In this example a parcel moves from a hub to a shop through depots, and each lane has a transit time in days and a fee:

```surql
/**[test]

[[test.results]]
error = false

[[test.results]]
error = false

[[test.results]]
error = false

[[test.results]]
error = false

[[test.results]]
error = false

[[test.results]]
error = false

[[test.results]]
error = false

[[test.results]]
error = false

[[test.results]]
value = "[depot:shop]"

[[test.results]]
value = "[depot:north, depot:shop]"

[[test.results]]
value = "[depot:east, depot:shop]"

*/
-- Setup
CREATE depot:hub, depot:north, depot:south, depot:east, depot:shop;
RELATE depot:hub->lane->depot:north SET days = 1, cost = 30;
RELATE depot:north->lane->depot:shop SET days = 2, cost = 40;
RELATE depot:hub->lane->depot:south SET days = 2, cost = 10;
RELATE depot:south->lane->depot:shop SET days = 3, cost = 15;
RELATE depot:hub->lane->depot:east SET days = 4, cost = 5;
RELATE depot:east->lane->depot:shop SET days = 4, cost = 5;
RELATE depot:hub->lane->depot:shop SET days = 9, cost = 100;

depot:hub.{..+shortest=depot:shop}(->lane->depot);
//- [depot:shop]

depot:hub.{..+shortest=depot:shop+weight=($l.days)}(->($l = lane)->depot);
//- [depot:north, depot:shop]

depot:hub.{..+shortest=depot:shop+weight=($l.cost)}(->($l = lane)->depot);
//- [depot:east, depot:shop]
```

Without a weight, the shortest path is the one with the fewest lanes, which is the direct lane. Weighting by `days` gives the fastest route through `depot:north`, and weighting by `cost` gives the cheapest route through `depot:east`. The same weight with `+budget` collects every depot that a parcel can reach with a total fee of 30 or less. Each modifier is `+name` or `+name=value`, so with several of them the query can put one on each line:

```surql
/**[test]

[[test.results]]
error = false

[[test.results]]
error = false

[[test.results]]
error = false

[[test.results]]
error = false

[[test.results]]
error = false

[[test.results]]
error = false

[[test.results]]
error = false

[[test.results]]
error = false

[[test.results]]
value = "[depot:east, depot:north, depot:shop, depot:south]"

*/
-- Setup from the example above
CREATE depot:hub, depot:north, depot:south, depot:east, depot:shop;
RELATE depot:hub->lane->depot:north SET days = 1, cost = 30;
RELATE depot:north->lane->depot:shop SET days = 2, cost = 40;
RELATE depot:hub->lane->depot:south SET days = 2, cost = 10;
RELATE depot:south->lane->depot:shop SET days = 3, cost = 15;
RELATE depot:hub->lane->depot:east SET days = 4, cost = 5;
RELATE depot:east->lane->depot:shop SET days = 4, cost = 5;
RELATE depot:hub->lane->depot:shop SET days = 9, cost = 100;

array::sort(depot:hub.{..
	+collect
	+weight=($l.cost)
	+budget=30
}(->($l = lane)->depot));
```

```surql title="Output"
[depot:east, depot:north, depot:shop, depot:south]
```

The [modifiers](/docs/reference/query-language/language-primitives/idioms#modifiers) section of the idioms reference lists the other modifiers, such as `+until` and `+prune` for stopping a walk where a condition holds.
