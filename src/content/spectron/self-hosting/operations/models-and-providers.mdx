# Models and providers

Spectron uses LLMs and embedding models at multiple stages of the extraction and recall pipeline. Each LLM stage can be configured independently, and each Context can override the server-level defaults. Embeddings are fixed deployment-wide.

## Supported providers

| Provider | Typical models |
| --- | --- |
| Google (Gemini) | Flash / Pro family for LLM stages; **`gemini-embedding-2`** for embeddings |
| OpenAI | GPT family for LLM stages |
| Anthropic | Claude family for LLM stages |

**Embeddings are Gemini-only:** `gemini-embedding-2` over the native `embedContent` API at **3072** dimensions. If you use Anthropic or OpenAI for extraction and chat, you still need a Google embeddings key (`SPECTRON_EMBEDDINGS_API_KEY` or `SPECTRON_PROVIDER_GOOGLE_API_KEY`).

---

## Server-level defaults

Set provider keys and optional model overrides before starting the server:

```bash
# Provider keys
SPECTRON_PROVIDER_GOOGLE_API_KEY=…
SPECTRON_PROVIDER_OPENAI_API_KEY=…
SPECTRON_PROVIDER_ANTHROPIC_API_KEY=…

# Embeddings (Gemini Developer API)
SPECTRON_EMBEDDINGS_API_KEY=…

# Explicit default LLM provider for unset stages: openai | anthropic | google
# Unset + a Google key ⇒ Gemini is the implicit default on /chat and /facts?infer=full
SPECTRON_LLM_PROVIDER=google

# Optional global model override when a stage has no per-Context selection
SPECTRON_LLM_MODEL=
```

When `SPECTRON_LLM_PROVIDER` is unset and a Google key is present, request-path stages (`/chat`, `/facts?infer=full`) use Gemini by default so a Google-key-only deployment answers without a void provider. Background stages still require an explicit selection or Context-owned key; they do not silently promote a bare provider key. See [Configuration](/docs/spectron/reference/configuration#default-provider-api-keys).

Per-stage built-in defaults are cost-tiered for the chosen provider (cheaper models for extraction and reconciliation, more capable models for synthesis). Override with Context `models` when you need a specific id.

## Pipeline stages

| Stage | Purpose |
| --- | --- |
| `extraction` | Entity and attribute extraction from turns and documents |
| `reconciliation` | Optional LLM assist when structural entity merge is inconclusive |
| `synthesis` | `/chat` and `/reflect` answer generation |
| `elaboration_consolidation` | Background elaboration and consolidation (worker dreaming tier) |
| `embedding` | Vector embedding — fixed to `gemini-embedding-2` (3072-dim) |

Keeping **extraction** on a fast, inexpensive model matters for throughput. **Synthesis** benefits from a more capable model when answer quality matters more than latency.

---

## Per-context model override

Each Context can set `{provider, model}` for LLM stages via the management API. The embedding field, if set, must be exactly `gemini-embedding-2` — other values are rejected at set-time (HTTP 400). Changing the deployment embedding model requires a [reindex](/docs/spectron/reference/management-api#force-reindex) so vectors and HNSW indexes stay in the same space.

```http
PATCH /api/v1/contexts/{context_id}
Content-Type: application/json

{
  "config": {
    "models": {
      "extraction": { "provider": "google", "model": "gemini-2.5-flash" },
      "synthesis": { "provider": "anthropic", "model": "claude-sonnet-4" },
      "embedding": "gemini-embedding-2"
    }
  }
}
```

You can also attach provider keys per Context so different tenants use different accounts. Unspecified stages inherit the deployment default.

**Document ingest** resolves the **`extraction`** LLM per Context on the worker for each job — including vision description under **`MultimodalFull`**. A Context with its own provider keys and `models.extraction` does not require a deployment-wide default LLM env var for ingest to run.

---

## Provider key security

Provider keys are stored encrypted at rest in SurrealDB, scoped to their Context. The API surface is write-only: once a key is set, you cannot retrieve the plaintext value through the API. Read operations return which providers are configured, not the secrets. To rotate a key, write the new value — it overwrites the previous entry.

---

## Switching providers after deployment

Changing the **LLM provider** for extraction or synthesis takes effect immediately for new work. Existing extracted memory is not rewritten.

Changing the **embedding model** is a deployment-wide decision. Stored vectors are tied to a specific model and width. After a change, trigger a re-embedding / reindex job; recall quality may degrade until the job finishes.

---

## Mixing providers

You can mix providers across stages — for example Gemini for extraction and Anthropic for synthesis — as long as each selected provider has a key available to that Context (deployment or per-Context). Spectron validates provider availability at configuration time and rejects missing keys rather than silently re-routing.
