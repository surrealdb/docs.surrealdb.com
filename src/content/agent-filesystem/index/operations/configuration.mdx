# Configuration reference

This page lists the settings that the Agent Filesystem tools read: the environment variables and flags that choose a SurrealDB server, a database and an identity, the files that supply defaults, and the values that the schema fixes. The tools are the Python commands (`surrealfs`, `surrealfs-mcp` and the `python -m surrealfs.*` modules), the Rust command `surrealfs-rs`, and the gateway `surrealfs-server`, which serves the file browser. [Command-line reference](/docs/agent-filesystem/interfaces/command-line#install) shows how to install `surrealfs` and `surrealfs-rs`.

Each tool opens its own connection to a SurrealDB 3.x server, so the tools do not share one configuration file. The Python tools and `surrealfs-rs` read different variable names and have different defaults, which the first table compares.

## Which tool reads which setting

| Setting | Python tools | `surrealfs-rs` | Gateway (`surrealfs-server`) |
| --- | --- | --- | --- |
| Server URL | `SURREALDB_URL`, default `ws://localhost:8000/rpc`. `surrealfs-mcp` has no default. | `SURREALDB_URL` or `--url`, default `ws://127.0.0.1:8000/rpc` | `SURREALDB_URL` or `--url`, default `http://127.0.0.1:8000` |
| Namespace | `SURREALDB_NAMESPACE`, default `surrealfs` | `SURREALDB_NS` or `--ns`, default `surrealfs` | `SURREALDB_NS` or `--ns`, default `surrealfs` |
| Database | `SURREALDB_DATABASE`, default `demo` | `SURREALDB_DB` or `--db`, default `surrealfs` | `SURREALDB_DB` or `--db`, default `main` |
| User | `SURREALDB_USER`, default `root` | `SURREALDB_USER` or `--user`, default `root` | `SURREALDB_USER` or `--user`, default `root` |
| Password | `SURREALDB_PASS`, default `root` | `SURREALDB_PASS` or `--pass`, default `root` | `SURREALDB_PASS` or `--pass`, default `root` |
| Sign-in level | `SURREALDB_AUTH_LEVEL`, default `root` | A root user only | A root user, or the bearer token in `SURREALDB_TOKEN` |
| Identity that writes | `SURREALFS_AGENT_USER`, else the operating-system user name. Under record access, `SURREALDB_USER`. | `SURREALFS_CALLER` or `--caller`, else the database user. The `lock`, `fork`, `diff`, `merge` and `mount` subcommands use `root` instead. | Each request: the `X-SurrealFS-User` header, else `root` |
| Listen address | Not applicable | `serve gateway -a`, default `127.0.0.1:8787`. `serve webdav` and `serve s3` take their own `-a` | `--bind` or `SURREALFS_BIND`, default `127.0.0.1:8787` |

> [!WARNING]
> The Python tools default to the database `demo` and `surrealfs-rs` defaults to the database `surrealfs`. `surrealfs-rs` also ignores `SURREALDB_NAMESPACE` and `SURREALDB_DATABASE`, so two tools that run with no settings use two different databases. To point both at one database, set both pairs of variables.

```bash
export SURREALDB_URL=ws://localhost:8000/rpc
export SURREALDB_USER=root SURREALDB_PASS=secret
export SURREALDB_NAMESPACE=agents SURREALDB_DATABASE=files
export SURREALDB_NS=agents SURREALDB_DB=files
```

> [!WARNING]
> A command that runs with no settings connects to `ws://localhost:8000/rpc` as `root` with the password `root`. A `surrealfs` subcommand then applies the schema to the namespace `surrealfs` and the database `demo` on whichever server answers on that port. Set `SURREALDB_URL`, `SURREALDB_USER` and `SURREALDB_PASS` before the first command.

## Run a local server

The examples on this page use a local SurrealDB 3.2 server started with this command. Agent Filesystem needs no `--allow-*` flag. The `memory` engine keeps data until the server stops, so choose a persistent engine for data that must last. The [`surreal start`](/docs/reference/cli/surrealdb-cli/commands/start) reference lists the options.

```bash
surreal start --user root --pass secret --bind 127.0.0.1:8000 memory
```

## Python tools

### Environment variables

| Variable | Default | Purpose |
| --- | --- | --- |
| `SURREALDB_URL` | `ws://localhost:8000/rpc` | The WebSocket URL of the server, for example `ws://localhost:8000/rpc`. `surrealfs-mcp` has no default and refuses to start without a value. |
| `SURREALDB_NAMESPACE` | `surrealfs` | The namespace that holds the filesystem. |
| `SURREALDB_DATABASE` | `demo` | The database that holds the filesystem. |
| `SURREALDB_USER` | `root` | The user to sign in as. Under record access this is also the identity that writes. |
| `SURREALDB_PASS` | `root` | The password for that user. |
| `SURREALDB_AUTH_LEVEL` | `root` | The level at which the user is defined: `root`, `namespace`, `database` or `record`. Any other value stops the command with an error. |
| `SURREALFS_AGENT_USER` | The operating-system user name | The identity that writes, for the three system levels. |
| `SURREALFS_NEW_PASSWORD` | None | The password that `python -m surrealfs.users add` sets when `--password` is absent. Without either, the command prompts. |
| `SURREALFS_SEMANTIC` | Unset | `1`, `true` or `yes` (in any case) selects the hybrid search tool of the MCP server and the Hermes plugins. They have no embedding function in this release, so the tool still matches words only. See [search and embedding settings](#search-and-embedding-settings). |

`surrealfs init` and `python -m surrealfs.schema` always sign in as a root user and ignore `SURREALDB_AUTH_LEVEL`.

### Sign-in levels

The first three levels sign in as a SurrealDB system user, and system users bypass table permissions. The fourth level signs in as an Agent Filesystem user and makes the database enforce the permissions.

| Level | Sign-in payload | Identity that writes |
| --- | --- | --- |
| `root` | `SURREALDB_USER` and `SURREALDB_PASS` | `SURREALFS_AGENT_USER`, else the operating-system user |
| `namespace` | Adds the namespace | The same |
| `database` | Adds the namespace and the database | The same |
| `record` | The access method `account`, with the user and password as variables | `SURREALDB_USER`, as written |

The `record` level needs a schema applied with the record access definitions and a user created with `python -m surrealfs.users add`. [Record access](/docs/agent-filesystem/security/record-access) describes the setup, and [Permissions](/docs/agent-filesystem/security/permissions) describes what each level enforces.

### The identity that writes

A system credential does not say which Agent Filesystem user is writing, so the Python tools take the name from `SURREALFS_AGENT_USER`, or from the operating-system user name when the variable is unset. The name becomes the owner of the files that the process creates and the name of its home folder, `/home/<name>`.

The tools turn each run of characters other than letters, digits, `_` and `-` into a single `-`, so `hermes alice` becomes `hermes-alice`. The name `root` is refused, because `root` is the identity that bypasses every permission check:

```bash
SURREALFS_AGENT_USER=root surrealfs status
```

```text title="Error output"
Error connecting to SurrealDB (ws://localhost:8000/rpc): no agent may act as 'root': it bypasses every SurrealFS permission check. Name a real user in SURREALFS_AGENT_USER, or in SURREALDB_USER under record auth. The default unix account in a container is root, which is not a deliberate grant.
```

### Flags that override the environment

`surrealfs init` signs in as a root user, applies the schema with record access, creates one record user and writes a settings file. Each connection flag falls back to the variable in the first table.

| Flag | Default | Purpose |
| --- | --- | --- |
| `--url`, `--username`, `--password`, `--namespace`, `--database` | The variables `SURREALDB_URL`, `SURREALDB_USER`, `SURREALDB_PASS`, `SURREALDB_NAMESPACE` and `SURREALDB_DATABASE` | The server and the root user that runs the setup. |
| `--account` | `admin` | The name of the record user to create. |
| `--account-pass` | `surrealfs-secret` | The password of that user. |

> [!WARNING]
> `surrealfs init` writes the password of the new user, in clear text, to `~/.config/surrealfs/env`, with the mode `0600`. Without `--account-pass`, that password is the fixed value `surrealfs-secret`. Pass `--account-pass` with a password of your own. The command replaces the whole file, so lines such as `SURREALFS_AGENT_USER` or `AGENT_MEMORY_CONTEXT_ID` are lost. It creates the account only when it does not exist, but it always writes the password from `--account-pass`, or the fixed one. Running it again with another password therefore leaves a file that cannot sign in, and the command still exits with status 0.

`python -m surrealfs.schema` applies the schema and takes `--url`, `--username`, `--password`, `--namespace` and `--database`, with the same variables as defaults. `--record-auth` adds the record access definitions. `--print` prints the SurrealQL instead of running it.

## The gateway

`surrealfs-server`, the program that serves the [file browser](/docs/agent-filesystem/interfaces/file-browser), reads the settings below from flags or from variables, and a flag overrides the variable. It reads no settings file, and it connects to SurrealDB over HTTP.

| Flag | Variable | Default |
| --- | --- | --- |
| `--bind` | `SURREALFS_BIND` | `127.0.0.1:8787` |
| `--port`, `-p` | `SURREALFS_PORT` | `8787`, on `127.0.0.1` |
| `--url` | `SURREALDB_URL` | `http://127.0.0.1:8000` |
| `--ns`, `--namespace` | `SURREALDB_NS` | `surrealfs` |
| `--db`, `--database` | `SURREALDB_DB` | `main` |
| `--user`, `-u` | `SURREALDB_USER` | `root` |
| `--pass`, `--password` | `SURREALDB_PASS` | `root` |
| None | `SURREALDB_TOKEN` | Unset. A non-empty value replaces the user and the password as a bearer token. |
| `--static-dir` | `SURREALFS_STATIC_DIR` | `surrealfs/browser/static`, when that folder exists |
| None | `SURREALFS_SERVER_TOKEN` | Unset. When set, requests need it as a bearer token. |
| None | `OPENAI_API_KEY`, `OPENAI_BASE_URL`, `SURREALFS_EMBED_MODEL` | Unset, `https://api.openai.com/v1` and `text-embedding-3-small` |
| None | `ANTHROPIC_API_KEY`, `SURREALFS_CHAT_MODEL` | Unset and `claude-sonnet-4-5` |

The program ignores a flag that it does not know, including `--help`. [Gateway server](/docs/agent-filesystem/interfaces/gateway-server) describes each setting and what the gateway does with it. `surrealfs-rs serve gateway` starts the same gateway with the connection settings of `surrealfs-rs`.

> [!WARNING]
> The gateway has no sign-in page. With a bind address other than `127.0.0.1`, anyone who can reach the port has the access of the configured credentials, and a request that names no user acts as `root`, which reads every private home folder.

## The `surrealfs-rs` command

`surrealfs-rs` reads the options below from flags or from the variables. It opens a new connection for each subcommand, signs in as a root user, and reads no settings file.

| Flag | Variable | Default |
| --- | --- | --- |
| `--url` | `SURREALDB_URL` | `ws://127.0.0.1:8000/rpc` |
| `--ns` | `SURREALDB_NS` | `surrealfs` |
| `--db` | `SURREALDB_DB` | `surrealfs` |
| `--user` | `SURREALDB_USER` | `root` |
| `--pass` | `SURREALDB_PASS` | `root` |
| `--caller` | `SURREALFS_CALLER` | Unset, so the database user. The `lock`, `fork`, `diff`, `merge` and `mount` subcommands use `root` instead. |

The `--caller` value is the identity that the command reports to the database. The command takes it on trust, and only some operations check it. [Permissions](/docs/agent-filesystem/security/permissions) lists which ones. The `serve` subcommands take their own address options, which [WebDAV and S3 servers](/docs/agent-filesystem/interfaces/network-servers) describes.

> [!WARNING]
> `surrealfs-rs` chooses the connection from the prefix of the URL. It removes a leading `ws://` or `wss://` and opens a plain WebSocket connection, so a `wss://` URL does not encrypt the traffic, and the connection to a server that accepts only TLS connections fails with `invalid HTTP version`. An `http://` or `https://` URL makes the program send each statement to the `/rpc` endpoint of SurrealDB over HTTP. The `https://` form is not confirmed against a TLS server. An `sfs://`, `sfs+http://` or `sfs+https://` URL selects a [gateway](/docs/agent-filesystem/interfaces/remote-clients) and not SurrealDB.

## Settings files

A settings file holds the same variables as the environment, one `NAME=value` per line. Some tools read a file in addition to their process environment, and a variable that the process already has takes precedence over the file.

| Tool | Where it looks | Notes |
| --- | --- | --- |
| `surrealfs-mcp` and `surrealfs mcp` | `SURREALFS_ENV_FILE`, else `$XDG_CONFIG_HOME/surrealfs/env`, else `~/.config/surrealfs/env` | Needs the `mcp` extra, which brings `python-dotenv`. Prints a warning when other users can read the file. Reads values as written, without `${...}` expansion. |
| `surrealfs-server` | None | It reads only the process environment. The `just server` recipe loads a `.env` file from the repository. |
| `surrealfs status`, `schema`, `lock`, `history`, `restore`, `grep`, `init` and `users`, and `python -m surrealfs.users` | None | These read only the process environment, and ignore a `.env` file in the working directory. |
| `surrealfs-rs` | None | |

This file configures the MCP server for the database from the earlier examples. Restrict it to your user, because it holds the password.

```text title="~/.config/surrealfs/env"
SURREALDB_URL=ws://localhost:8000/rpc
SURREALDB_NAMESPACE=agents
SURREALDB_DATABASE=files
SURREALDB_USER=root
SURREALDB_PASS=secret
SURREALFS_AGENT_USER=alice
```

The selftest connects, lists the tools and the root folder, and reports whether the optional Agent Memory bridge is configured. It needs at least one file or folder besides `/home` in the database, so the commands below create the folder `/notes` first:

```bash
surrealfs-rs init
surrealfs-rs mkdir /notes
chmod 600 ~/.config/surrealfs/env
surrealfs-mcp --selftest
```

```text title="Sample output"
config    /home/alice/.config/surrealfs/env
server    ws://localhost:8000/rpc
database  agents / files
acting as alice
tools     31
ls /      home, notes
memory    not configured (AGENT_MEMORY_CONTEXT_ID / AGENT_MEMORY_API_KEY)

OK        filesystem reachable; agent memory off, so no
          brain_recall tool. Everything else works.
```

The `config` line shows the path of the settings file, followed by `(absent)` when the file does not exist. A database that holds only `/home` prints a `WARN` line and exits with status 1, because the connection is probably to the wrong database. The server also refuses to start when a variable that starts with `SURREALDB_`, `SURREALFS_` or `AGENT_MEMORY_` still holds an unexpanded `${NAME}` placeholder, which happens when a client passes the literal text of its own configuration file.

> [!WARNING]
> `surrealfs init` always writes `~/.config/surrealfs/env`, but the MCP server reads `$XDG_CONFIG_HOME/surrealfs/env` when `XDG_CONFIG_HOME` is set to another directory. In that case the server does not find the file that `init` wrote. Point the server at it with `export SURREALFS_ENV_FILE="$HOME/.config/surrealfs/env"`.

> [!WARNING]
> Variables that the shell already exports take precedence over the file. If the shell still exports `SURREALDB_USER=root` from the earlier examples when you run the selftest with the file that `init` wrote, the `root` user replaces the record user in the file, and the selftest stops with a traceback that ends in `no agent may act as 'root'`. Unset the connection variables, or open a new shell, after `init`.

## Schema application

Some entry points define the schema when they connect and others expect it to exist.

| Entry point | Applies the schema |
| --- | --- |
| `surrealfs schema apply` and `python -m surrealfs.schema` | Yes, by design. |
| `surrealfs init` and `surrealfs-rs init` | Yes, with the record access definitions. |
| `surrealfs status`, `lock`, `history`, `restore` and `grep` | Yes, once per process, unless the sign-in level is `record`. |
| `surrealfs-mcp` | Yes. The server tries at start and continues when the credential is not allowed to define tables. |
| `surrealfs-mcp --selftest` | Yes. It stops with `FAIL      could not reach the filesystem` when the credential is not allowed to define tables. |
| `surrealfs-server` | Yes, at start. A schema that cannot be applied prints a warning and the server keeps running. |
| `surrealfs-rs serve gateway` | No. Run `surrealfs-rs init` first. |
| `python -m surrealfs.users` | No. Against an empty database `python -m surrealfs.users add` stops with `The table 'file' does not exist`, and `python -m surrealfs.users list` stops with `The table 'user' does not exist`. |
| `surrealfs-rs`, except `init` | No. Against an empty database they stop with `Function 'fn::sfs_ls' not found`. |
| The `SurrealFs` class | Never connects. Call `apply_schema` yourself. |

Applying the schema of the same release again keeps the data. The schema defines tables, functions and events with `OVERWRITE`, so a later release replaces them in place, and this page does not cover the effect of a newer release on an existing database. It defines the analysers and the main vector and full-text indexes with `IF NOT EXISTS`, so one that exists keeps its definition. Applying with `--record-auth` replaces the access methods. Take a [backup](/docs/agent-filesystem/operations/backup-and-restore) before applying the schema of a newer release.

## Search and embedding settings

Full-text search needs no settings. Semantic and hybrid search need an embedding for each file and for each query, and Agent Filesystem does not compute them itself. The `SurrealFs` methods take an embedding function that you supply, and the package provides no embedder and no indexing command. Only the gateway calls an embedding service on its own.

| Setting | Value | Used by |
| --- | --- | --- |
| `OPENAI_API_KEY` | None. It switches the embeddings on. | The gateway |
| `OPENAI_BASE_URL` | `https://api.openai.com/v1` | The gateway |
| `SURREALFS_EMBED_MODEL` | `text-embedding-3-small` | The gateway |
| Vector length | 1,536, fixed by the index on the `file` table. | Every embedder |

The gateway requests an embedding of each file that it writes and of each search query, and it stores none of the vectors, see [Search](/docs/agent-filesystem/concepts/search#limitations-in-this-release). `SURREALFS_SEMANTIC` is read by the MCP server and by the Hermes plugins, and in this release it does not make them embed anything. An embedder that returns vectors of another length is rejected by the database:

```text title="Error output"
Incorrect vector dimension (3). Expected a vector of 1536 dimension.
```

[Search](/docs/agent-filesystem/concepts/search) describes the ranking and how `reindex_embeddings` works.

## Agent Memory and Hermes settings

The MCP server can mirror the text files that its tools write to an [Agent Memory](/docs/agent-memory) context and offer a `brain_recall` tool. The bridge is off until both `AGENT_MEMORY_CONTEXT_ID` and `AGENT_MEMORY_API_KEY` are set, and it needs the `agent-memory` extra.

| Variable | Default | Purpose |
| --- | --- | --- |
| `AGENT_MEMORY_CONTEXT_ID` | None | The context to write into. |
| `AGENT_MEMORY_API_KEY` | None | The bearer token for that context. |
| `AGENT_MEMORY_URL` | A hosted default that the package sets | The base URL of the Agent Memory service. Set it to use another deployment. |
| `AGENT_MEMORY_SCOPE` | `brain` | The scope path to file documents under, without a leading or trailing `/`. |
| `SURREALFS_MIRROR_ROOT` | `/` | Only files under this path are mirrored. |

The Hermes memory provider reads `SURREALFS_MEMORY_DIR`, the folder where it keeps its files, which defaults to `/home/<name>/memories` for the identity that writes. It reads the same connection variables as the other Python tools. [MCP server](/docs/agent-filesystem/interfaces/mcp-server) and [Hermes](/docs/agent-filesystem/interfaces/hermes) describe both integrations.

## Settings fixed by the schema

These values are part of the schema. `python -m surrealfs.schema --print` prints the SurrealQL that defines them.

| Setting | Value |
| --- | --- |
| Vector index on `file.embedding` | HNSW, 1,536 dimensions, cosine distance, `EFC 150`, `M 12`, `M0 24` |
| Full-text analyser `fts_simple` | Tokenizers `blank`, `class`, `camel` and `punct`, with the English snowball stemmer |
| Full-text ranking | BM25 with `k1` 1.2 and `b` 0.75 |
| Default mode of a file | `0o666` |
| Mode of the folder `/home` | `0o777`, owned by `root` |
| Record access methods | `account`, `indexer`, `projector` and `compactor` |
| Record access lifetimes | Token 15 minutes, session 12 hours |
| Reserved user names | `root`, `indexer`, `projector` and `compactor` cannot sign in through the `account` method |
| Default lease time | 60 seconds |

An index that already exists keeps its definition when the schema is applied again, so changing one of these indexes in an existing database needs a `DEFINE INDEX OVERWRITE` statement of your own.

The Python library, and not the schema, sets the mode of a new folder to `0o777` and the mode of a home folder, `/home/<name>`, to `0o700`.
