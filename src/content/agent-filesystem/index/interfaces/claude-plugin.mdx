# Claude plugin

The `surrealfs` plugin gives Claude a persistent filesystem that other agents and people can share. It bundles the [MCP server](/docs/agent-filesystem/interfaces/mcp-server) with two skills: `brain`, which teaches Claude to answer questions about a project from files in the filesystem and to file its conclusions back, and `brain-memory`, which adds recall from [Agent Memory](/docs/agent-memory) when that is configured. A plugin carries its own local MCP server, so installing it does not require adding a connector by hand.

This page covers installation, how the plugin chooses which build of the server to run, and what the two skills do. The server's configuration, tools and selftest are on the [MCP server](/docs/agent-filesystem/interfaces/mcp-server) page, because none of that is specific to Claude.

> [!NOTE]
> The package is in beta, and the plugin can change between releases. The two plugin manifests, `plugin.json` and the repository's `marketplace.json`, pass `claude plugin validate`. The install steps below, the names of the Claude Desktop menus and the namespaced tool and skill names come from the project's README, and Claude's own documentation is the authority for its current interface.

## What the plugin contains

The repository holds one marketplace file at its root, which lists one plugin. The plugin directory has the following layout:

```text
.claude-plugin/marketplace.json                  the marketplace: one plugin named surrealfs
surrealfs/integrations/claude/
    .claude-plugin/plugin.json                   the plugin manifest
    .mcp.json                                    starts scripts/surrealfs-mcp
    scripts/surrealfs-mcp                        the launcher
    skills/brain/SKILL.md                        the brain skill
    skills/brain-memory/SKILL.md                 the brain-memory skill
```

The plugin's `.mcp.json` names the launcher and passes no `env` block, so no SurrealDB setting needs to be in your environment. Configuration lives in the file that the server reads, `~/.config/surrealfs/env`.

## Before you install

You need three things:

1. **`uv`.** The launcher runs the server with `uvx`, which comes with [uv](https://docs.astral.sh/uv/).
2. **A SurrealDB 3.x database** that the machine can reach, with a namespace and a database for the filesystem.
3. **The configuration file.** Write the connection settings to `~/.config/surrealfs/env` as described in [Configure the server](/docs/agent-filesystem/interfaces/mcp-server#configure-the-server). `SURREALDB_URL` is the only setting that the server requires. The user and password default to `root` and `root`, and the namespace and database default to `surrealfs` and `demo`, so set `SURREALDB_USER`, `SURREALDB_PASS`, `SURREALDB_NAMESPACE` and `SURREALDB_DATABASE` as well, unless your database uses those defaults.

## Install the plugin

> [!WARNING]
> The marketplace and the launcher both read the repository's default branch, which registers 15 tools, while the `next` branch that these pages describe registers 31. To run the 31-tool build, set `SURREALFS_SOURCE` to the `next` branch before you start Claude Code, as in [Choose which server build the plugin runs](#choose-which-server-build-the-plugin-runs).

In Claude Code, add the repository as a marketplace and install the plugin from it. The `export` line selects the `next` branch for the server, and it must run in the shell that starts Claude Code:

```bash title="In the shell that starts Claude Code"
export SURREALFS_SOURCE="git+https://github.com/surrealdb/surrealfs.git@next"
```

```text title="Claude Code"
/plugin marketplace add surrealdb/surrealfs
/plugin install surrealfs@surrealfs
```

In Claude Desktop, and in claude.ai and Cowork, open **Customize** in the left sidebar, choose **Plugins**, choose **Add from a repository**, and enter `https://github.com/surrealdb/surrealfs`. Then install `surrealfs` from it.

In Claude Code the tools arrive under the plugin's namespace, for example `mcp__plugin_surrealfs_surrealfs__ls`, and the skills are named `/surrealfs:brain` and `/surrealfs:brain-memory`.

To remove the plugin, run the following in a terminal:

```bash
claude plugin uninstall surrealfs@surrealfs
claude plugin marketplace remove surrealfs
```

After a change to the plugin's manifest, launcher or skills, `claude plugin marketplace update surrealfs` picks it up. For a one-off session without installing, start Claude Code with `claude --plugin-dir ./surrealfs/integrations/claude` from a clone of the repository.

## Choose which server build the plugin runs

The launcher builds the server from a package source each time it starts. By default the source is `git+https://github.com/surrealdb/surrealfs.git`, which is the repository's default branch, and that branch registers 15 tools. The `next` branch that this documentation describes registers 31. The `tools` line of the [selftest](/docs/agent-filesystem/interfaces/mcp-server#check-the-server-with-the-selftest) tells you how many tools a build has, and the command below builds the default source in the same way as the launcher and runs the selftest on it:

```bash title="Check the build that the default source gives"
uvx --from "surrealfs[mcp,agent-memory] @ git+https://github.com/surrealdb/surrealfs.git" surrealfs-mcp --selftest
```

Add `@next` after `.git` to check the `next` branch. The selftest reads the configuration file described above. The launcher passes `--selftest`, and any other arguments, through to the server.

To run another branch, a tag or a local clone, set `SURREALFS_SOURCE` before the client starts:

```bash title="Run the next branch"
export SURREALFS_SOURCE="git+https://github.com/surrealdb/surrealfs.git@next"
```

```bash title="Run a local clone"
export SURREALFS_SOURCE=/path/to/surrealfs
```

`SURREALFS_SOURCE` is the one variable that cannot go in the configuration file, because it decides what the launcher builds before the server exists to read any file. It must be exported in the environment of the process that starts the server. Claude Code inherits the environment of the shell that starts it. Claude Desktop starts servers with a bare environment, so an export does not reach it, and on Desktop the way to run another build is to add the server by hand with the source written into the arguments:

```json title="Claude Desktop connector pinned to the next branch"
{
  "mcpServers": {
    "surrealfs": {
      "command": "/path/to/uvx",
      "args": [
        "--from",
        "surrealfs[mcp,agent-memory] @ git+https://github.com/surrealdb/surrealfs.git@next",
        "surrealfs-mcp"
      ]
    }
  }
}
```

The file is `claude_desktop_config.json`, which is in `~/Library/Application Support/Claude/` on macOS and in `%APPDATA%\Claude\` on Windows. Replace `/path/to/uvx` with the absolute path that `command -v uvx` prints, because a bare `uvx` can fail when Desktop's minimal `PATH` does not contain it. A connector added this way brings no skills, so add the skill folders separately under **Settings**, **Capabilities** and **Skills**.

### How the launcher works

The launcher is a short POSIX shell script, so a Windows installation would need an equivalent script. It exists because a plugin's `.mcp.json` expands a plain `${VAR}` and does not expand `${VAR:-default}`, so a default written there reaches `uvx` as literal text, `uvx` exits with `Failed to parse`, and the client reports only a closed connection. A shell does support the default, so the script chooses the source:

1. It finds `uvx` in this order: the path in `UVX`, then `uvx` on the `PATH`, then `~/.local/bin/uvx`, `/opt/homebrew/bin/uvx` and `/usr/local/bin/uvx`. With none of them, it prints `surrealfs-mcp: no uvx found` and exits with status 127.
2. It runs `uvx --from "surrealfs[mcp,agent-memory] @ $SURREALFS_SOURCE" surrealfs-mcp`, passing along any arguments.

The launcher installs the `mcp` and `agent-memory` extras. With `SURREALFS_SEMANTIC=1`, the server still searches by words only, because it has no embedding function in this release, see [Tools](/docs/agent-filesystem/interfaces/mcp-server#tools).

## The brain skill

The `brain` skill answers questions about the state of a project from the filesystem, and writes the outcome back. Claude uses it for questions about status, priorities, blockers, risks and history, and before it writes anything under `/brain`, so that the file lands in the right place. It is written for one scenario: a shared record of a project's security and compliance state, which scheduled routines fill with evidence and which people and agents read.

The skill describes a layout that Claude follows under `/brain/<project>/`:

| Folder | Holds | How Claude treats it |
| --- | --- | --- |
| `sources/` | Evidence from other systems, one file per finding per day, for example `sources/snyk/2026-09-04/SNYK-JS-AXIOS-1234.md` | Filed once and never edited. Two files that disagree show that something changed. |
| `risks/` | The current state of each risk, one file per risk | Edited in place with `edit`, so the file is always the state as of now. |
| `decisions/` | The reasons behind a change, one file per decision | Append-only. A reversal is a new file. |
| `digests/` | One roll-up per day | Written so that a reader with no other context can follow it. |
| `notes/` | Anything that comes from a conversation | Written with a date and enough context to stand alone. |

The skill sets four working rules: every claim comes from a file that Claude has read, answers cite the file that backs each claim, the outcome of the work is written back to the filesystem, and ranking uses evidence such as severity, reachability and real dates. It also warns about the usual mistakes: paths are absolute, `write_file` replaces a whole file while `edit` changes a part, and `sources/` is never edited.

Everything under `/brain/` is shared and writable by every user, which is how routines, agents and people hand work to each other. Private material belongs under `/home/<user>/`, which the Python class keeps private, see [Permissions](/docs/agent-filesystem/security/permissions). The folder names are a convention in the skill text. You can change them by editing the skill, for example to describe another kind of shared project record.

## The brain-memory skill

The `brain-memory` skill applies only when the server offers the `brain_recall` tool, which exists when Agent Memory is configured. Without that tool, the skill tells Claude to stop and use `brain` alone, and the files are the whole answer. With it, the skill changes where a question starts:

1. Ask `brain_recall` first, with a question and not a keyword.
2. Open the paths that the hits name, and read them before reporting current state, because a hit can be a superseded version of the file.
3. Fall back to `ls`, `cat` and `search` under `/brain/` when recall returns nothing, or when the hits are entities that name no path.
4. Say where each claim came from, and mark a claim that only recall supports, because nothing in the filesystem backs it up yet.

The skill also notes that only what Claude writes through the tools is filed into Agent Memory, so a conclusion that exists only in the chat is not recalled later, and that `write_bytes` is not filed. To configure Agent Memory, see [Optional: Agent Memory](/docs/agent-filesystem/interfaces/mcp-server#optional-agent-memory).

> [!WARNING]
> The plugin installs the `agent-memory` extra. When Agent Memory is configured, the mirror files a file after each `write_file`, `edit` or `touch`, from the root `/` by default, so private files under `/home/<user>` are included. Set `SURREALFS_MIRROR_ROOT=/brain` in the configuration file when they must stay out of Agent Memory.

## Troubleshooting

Run the selftest first, because it names the layer that failed. If it passes and Claude still lists no tools, the client never started the server:

- **Claude Code.** Run `claude mcp list`, or use `/mcp` in a session.
- **Claude Desktop.** The project's README names `~/Library/Logs/Claude/mcp.log` and `~/Library/Logs/Claude/mcp-server-surrealfs.log` on macOS. An empty `mcp.log` and no per-server log mean that Desktop started nothing.
