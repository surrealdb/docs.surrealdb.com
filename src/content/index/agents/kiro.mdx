# Kiro

[Kiro](https://kiro.dev) is an agentic IDE from AWS. SurrealDB publishes its Kiro support as two powers in one GitHub repository, [`surrealdb/kiro-plugin`](https://github.com/surrealdb/kiro-plugin). The `surrealdb` power gives Kiro SurrealQL and CLI knowledge and connects it to the SurrealDB MCP servers. The `agent-memory` power gives it persistent memory across sessions.

Both powers follow the open [Agent Plugins](https://agent-plugins.org) specification, so any other client that loads Agent Plugins can use them as well.

## Install the powers

1. Open the **Powers** panel in Kiro.
2. Choose **Add Custom Power**, then **Import power from a repository URL**. In Kiro versions before 1.4.236 the option is called **Import power from GitHub**.
3. Enter the URL of the power's directory and choose **Install**.

Each power is a directory of the repository, so install them one at a time. The URL for the `surrealdb` power is:

```text
https://github.com/surrealdb/kiro-plugin/tree/main/plugins/surrealdb
```

The URL for the `agent-memory` power is the same with `plugins/agent-memory` at the end. To install from a local clone instead, choose **Import power from a folder** and select the same directory.

Once installed, a power activates on its own when your conversation matches its keywords. Nothing is loaded into the context until then.

## What the surrealdb power provides

The power holds eleven skills. Each one activates from what you are working on, and each is also available as a slash command.

| Skill | Activates on |
| --- | --- |
| `getting-started` | First-run setup, `surreal` not found, MCP tools missing |
| `surrealql` | SurrealQL queries, schemas, graph relations and live queries |
| `surrealql-performance` | Slow queries, record ID design, indexes, `EXPLAIN` and computed fields |
| `surrealql-functions` | Built-in functions and their signatures |
| `surrealdb-cli` | `surreal` commands, import and export, running a server |
| `surrealkit` | Schema migrations, rollouts, type generation and schema tests |
| `surrealdb-python` | The Python SDK, including embedded mode |
| `surrealdb-js` | The JavaScript SDK, including embedded engines and live queries |
| `surrealdb-vector` | Vector search, HNSW indexes, KNN and embeddings |
| `surrealdb-connection` | Endpoints, `USE`, WebSocket against HTTP, and authentication |
| `surrealdb-mcp` | Querying or inspecting a database through MCP tools |

Eight of these are copies of the [Agent Skills](/docs/integrate/ai-agents/agent-skills) that SurrealDB publishes for other agents. The `getting-started`, `surrealdb-connection` and `surrealdb-mcp` skills are written for Kiro.

## MCP servers

The power declares two MCP servers, which Kiro manages. They are not written into your own MCP settings.

| Server | Endpoint | Needs |
| --- | --- | --- |
| `surrealdb` | `https://mcp.surrealdb.com` | A Surreal ID. Kiro prompts you to sign in on first use. |
| `surrealdb-local` | `http://127.0.0.1:8000/mcp` | A SurrealDB instance listening on port 8000 of your machine. |

The `surrealdb` server is the [hosted MCP server](/docs/integrate/ai-agents/mcp), which manages SurrealDB Cloud organisations and instances. The `surrealdb-local` server is the [embedded MCP](/docs/integrate/ai-agents/mcp/embedded) that every SurrealDB instance serves at `/mcp`. If no local instance is running, `surrealdb-local` does not connect, and the skills and the hosted server keep working.

To try the local server, start an instance without authentication on the default port:

```bash
surreal db start --unauthenticated memory
```

> [!WARNING]
> `--unauthenticated` lets anyone who can reach the port read and write the data. Use it only for a throwaway instance on your own machine. To reach a secured or remote instance, add a server entry with credentials to Kiro's own `.kiro/settings/mcp.json`. The `surrealdb-mcp` skill walks through it.

## Check it worked

Install the CLI if `surreal version` fails in a terminal, as the `getting-started` skill reminds you to. Then ask Kiro:

> Which SurrealDB Cloud organisations can you see?

Kiro should list your organisations once you have signed in. If the tools are missing, ask Kiro to set up SurrealDB, which activates the `getting-started` skill.

## Add a health check

The `getting-started` skill can create a hook that reports at the start of each session whether a local instance is reachable and which version is installed. Kiro creates it only when you ask. The hook is written to `.kiro/hooks/` in your workspace.

## The agent-memory power

The `agent-memory` power connects Kiro to [SurrealDB Agent Memory](/docs/agent-memory), so it can recall past decisions and remember durable facts across sessions. It is in preview and needs an Agent Memory context and an API key before it does anything.

The power has two skills, `getting-started` and `agent-memory`. It declares no MCP server of its own, because an Agent Plugins manifest cannot hold the address and key of your own context host. Its `getting-started` skill adds the server to `.kiro/settings/mcp.json` for you, pointing at your context host's `/mcp` path and reading the key from the `SPECTRON_API_KEY` environment variable. It also offers optional hooks that recall and store memories automatically. They store conversation content, so Kiro installs them only when you ask.
