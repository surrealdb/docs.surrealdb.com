# Getting started

The Python SDK for SurrealDB lets you connect to a database and query it from your application. This guide covers connecting, signing in, creating records and reading them back. When you finish, you will have a short script that does each step with the blocking client or the `asyncio` client.

You need a SurrealDB instance to connect to. To run one on your own computer that keeps its data in memory, [install SurrealDB](/docs/running/installation) and start it:

```bash
surreal db start --user root --pass secret
```

## 1. Install the SDK

Follow the [installation guide](/docs/reference/python/installation) to install the SDK as a dependency in your project. Then import the factory function for the style of code you write.

<Tabs syncKey="python-sync-async">
	<TabItem value="sync" label="Synchronous" default>
		```python
		from surrealdb import Surreal

		db = Surreal("ws://localhost:8000")
		```
	</TabItem>
	<TabItem value="async" label="Asynchronous">
		```python
		from surrealdb import AsyncSurreal

		db = AsyncSurreal("ws://localhost:8000")
		```
	</TabItem>
</Tabs>

The `Surreal` and `AsyncSurreal` factory functions accept a connection URL and return the appropriate connection class based on the protocol.

## 2. Connect to SurrealDB

Use the `.connect()` method to open the connection, `.signin()` to authenticate, and `.use()` to select a namespace and database.

Supported connection protocols include:
- **WebSocket** (`ws://`, `wss://`) for long-lived stateful connections
- **HTTP** (`http://`, `https://`) for short-lived stateless connections
- **Embedded** (`mem://`, `file://`, `surrealkv://`) for in-process databases, with the `embedded` extra installed

The figure below shows how the three kinds of connection differ.

<img src="~/assets/img/diagrams/light/conn-protocols-light.webp" darkSrc="~/assets/img/diagrams/conn-protocols.webp" alt="Three panels compare the ways to connect. Over WebSocket, the app opens one socket and keeps it open: it signs in once, sends many queries over the same socket, and the server pushes live query notifications to it without a request. Over HTTP, each request is separate and carries its own credentials or token, and a LIVE SELECT is refused because there is no socket to send notifications to. In an embedded database, the SurrealDB engine runs inside the application process as a library and keeps data in memory or in SurrealKV files, with no network and no server to run." />

<Tabs syncKey="python-sync-async">
	<TabItem value="sync" label="Synchronous" default>
		```python
		from surrealdb import Surreal

		db = Surreal("ws://localhost:8000")
		db.connect()
		db.signin({"username": "root", "password": "secret"})
		db.use("main", "main")
		```
	</TabItem>
	<TabItem value="async" label="Asynchronous">
		```python
		from surrealdb import AsyncSurreal

		db = AsyncSurreal("ws://localhost:8000")
		await db.connect()
		await db.signin({"username": "root", "password": "secret"})
		await db.use("main", "main")
		```
	</TabItem>
</Tabs>

You can also use a context manager to automatically close the connection when you are done.

<Tabs syncKey="python-sync-async">
	<TabItem value="sync" label="Synchronous" default>
		```python
		with Surreal("ws://localhost:8000") as db:
		    db.signin({"username": "root", "password": "secret"})
		    db.use("main", "main")
		```
	</TabItem>
	<TabItem value="async" label="Asynchronous">
		```python
		async with AsyncSurreal("ws://localhost:8000") as db:
		    await db.signin({"username": "root", "password": "secret"})
		    await db.use("main", "main")
		```
	</TabItem>
</Tabs>

## 3. Insert data into SurrealDB

Use the `.create()` method to create records. Pass a table, or a `RecordID` to choose the id, as the first argument and the content of the record as the second. With a table, SurrealDB gives the record a random id.

<Tabs syncKey="python-sync-async">
	<TabItem value="sync" label="Synchronous" default>
		```python
		from surrealdb import RecordID, Table

		person = db.create(Table("person"), {
		    "name": "John",
		    "email": "john@example.com",
		    "age": 32,
		})

		apple = db.create(RecordID("product", "apple"), {
		    "name": "Apple",
		    "price": 1.50,
		    "category": "fruit",
		})
		```
	</TabItem>
	<TabItem value="async" label="Asynchronous">
		```python
		from surrealdb import RecordID, Table

		person = await db.create(Table("person"), {
		    "name": "John",
		    "email": "john@example.com",
		    "age": 32,
		})

		apple = await db.create(RecordID("product", "apple"), {
		    "name": "Apple",
		    "price": 1.50,
		    "category": "fruit",
		})
		```
	</TabItem>
</Tabs>

Each call returns the created record as a `dict`, with its `id`:

```python title="Output"
{
	'category': 'fruit',
	'id': RecordID(table_name=product, record_id='apple'),
	'name': 'Apple',
	'price': 1.5,
}
```

> [!IMPORTANT]
> To name a record, use a `RecordID`. A plain string such as `"product:apple"` is always a table name, so `db.create("product:apple", data)` creates a record in a table called `product:apple`.

## 4. Retrieve data from SurrealDB

### Selecting records

The `.select()` method reads every record in a table, or one record by its `RecordID`. On a blocking connection it returns a builder that sends nothing until you call `.execute()`. On an async connection, `await` sends it.

<Tabs syncKey="python-sync-async">
	<TabItem value="sync" label="Synchronous" default>
		```python
		people = db.select(Table("person")).execute()

		apple = db.select(RecordID("product", "apple")).execute()
		```
	</TabItem>
	<TabItem value="async" label="Asynchronous">
		```python
		people = await db.select(Table("person"))

		apple = await db.select(RecordID("product", "apple"))
		```
	</TabItem>
</Tabs>

A table gives a list of records. A `RecordID` gives the record, or `None` when it does not exist.

### Running SurrealQL queries

For more advanced use cases, use the `.query()` method to run [SurrealQL](/docs/reference/query-language) statements. Pass the values that the query needs as variables, which the SDK sends separately from the query text. `.first()` returns the result of the first statement, and `.execute()` returns a list with the result of every statement.

<Tabs syncKey="python-sync-async">
	<TabItem value="sync" label="Synchronous" default>
		```python
		products = db.query(
		    "SELECT name, price FROM product WHERE price < $max ORDER BY price",
		    {"max": 5.00},
		).first()
		```
	</TabItem>
	<TabItem value="async" label="Asynchronous">
		```python
		products = await db.query(
		    "SELECT name, price FROM product WHERE price < $max ORDER BY price",
		    {"max": 5.00},
		).first()
		```
	</TabItem>
</Tabs>

```python title="Output"
[{'name': 'Apple', 'price': 1.5}]
```

## 5. Close the connection

Close the connection when you are done to release its resources. If you use a context manager, this happens automatically.

<Tabs syncKey="python-sync-async">
	<TabItem value="sync" label="Synchronous" default>
		```python
		db.close()
		```
	</TabItem>
	<TabItem value="async" label="Asynchronous">
		```python
		await db.close()
		```
	</TabItem>
</Tabs>
