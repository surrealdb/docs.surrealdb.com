# Running SurrealDB

You can start with SurrealDB in more than one way. This section orders them from **the least to the most** involved, so you can pick how much you want to set up.

## Try it without installing

1. **[SurrealDB Studio Sandbox](/docs/running/sandbox)** (under a minute) - Open SurrealDB Studio in the browser and use the built-in Sandbox. There is nothing to install. Data is not persistent, which suits quick experiments and learning SurrealQL.

2. **[SurrealDB Cloud](/docs/running/cloud)** (about 5 minutes) - Create a free [SurrealDB Cloud](/docs/manage/instances) instance (you will need an email to sign in). You keep persistence and a managed database without running a server on your own machine. The default is a serverless [SurrealDB Earth](/docs/manage/instances/earth) instance, which scales to zero when idle.

3. **[Installation](/docs/running/installation)** (about 10 minutes) - Install the `surreal` CLI and run SurrealDB locally or on your own infrastructure. This is the path when you want full control, offline work, or production self-hosting.

## How you run the database on your own infrastructure

After you are running SurrealDB (locally or on servers you manage), you can choose storage and topology:

- [Run a single-node, in-memory server](/docs/running/in-memory) with optional persistence (SurrealMX)
- [Run a single-node, on-disk server](/docs/running/file-backed) (SurrealKV)
- [Run a multi-node cluster](/docs/running/multi-node)
- [Run with Docker](/docs/running/docker)
