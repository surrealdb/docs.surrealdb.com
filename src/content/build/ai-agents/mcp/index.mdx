# SurrealDB MCP Server

The SurrealDB MCP Server connects AI tools to your SurrealDB Cloud account. Add one URL to Claude, Cursor, or any other MCP client, sign in with your Surreal ID, and your assistant can work on your databases with you: deploy an instance, query the data inside it, look into why something is slow, and keep track of what it all costs.

```
https://mcp.surrealdb.com
```

We host it, so there is nothing to install and nothing to keep running. The server acts as you: it sees only the organisations you belong to, respects the role you have in each of them, and asks you to confirm anything that cannot be undone.

## What is MCP?

[Model Context Protocol](https://modelcontextprotocol.io) is an open standard for connecting AI assistants to outside tools and data. A server offers a set of tools, and a client such as Claude or Cursor calls them for you. Rather than copying connection strings into a chat window and pasting query results back out, your assistant works with SurrealDB directly.

## What you can do

- **Deploy and manage instances** — spin up a new instance, pause one you are not using, resize it when traffic grows, or upgrade it to a newer version of SurrealDB.
- **Work with your data** — ask questions in plain language and let the assistant write and run the SurrealQL, or have it create tables and seed records while you build.
- **Look into problems** — pull up instance status, metrics, and logs next to the query you were just writing.
- **Manage your team** — invite people to an organisation, change what they can do, and withdraw invitations.
- **Keep an eye on cost** — check usage and invoices, and estimate what an instance will cost before you create it.
- **Give agents long-term memory** — create and manage [Spectron](/docs/spectron) contexts, and store or recall memories from them.

## Connect your AI tool

Most clients need nothing but the URL. Follow the guide for your tool:

- [Connect to Claude](/docs/build/ai-agents/mcp/claude)
- [Connect to Cursor](/docs/build/ai-agents/mcp/cursor)

For anything else, add `https://mcp.surrealdb.com` as a remote MCP server. The usual shape is:

```json
{
  "mcpServers": {
    "surrealdb": {
      "url": "https://mcp.surrealdb.com"
    }
  }
}
```

Some clients use a different key or layout: VS Code wants a `servers` object with `"type": "http"`, and Windsurf and Antigravity use `serverUrl` instead of `url`. Once the server is connected, ask your assistant to list your organisations. If it comes back with them, you are set up.

## Signing in

### With your Surreal ID

If your client supports sign-in, this is all it takes: it opens a browser window, you sign in with the same Surreal ID you use for SurrealDB Cloud, and you approve the connection. Nothing goes in a config file, and you can sign out from the client whenever you like.

A signed-in connection can use every tool the server offers, limited only by your role in each organisation.

### With a personal access token

Use a token when your client cannot sign in through a browser, or when something runs unattended. Create one in the [account portal](https://account.surrealdb.com), pick the permissions it should carry, and pass it to your client as a header:

```json
{
  "mcpServers": {
    "surrealdb": {
      "url": "https://mcp.surrealdb.com",
      "headers": {
        "Authorization": "Bearer sdbp_your_token"
      }
    }
  }
}
```

A token only carries the permissions you tick when you create it:

| Permission | Lets your assistant |
| --- | --- |
| `read:cloud` | See your organisations, instances, Spectron contexts, usage, and logs |
| `write:cloud-instances` | Deploy, resize, pause, upgrade, and delete instances |
| `query:cloud-instances` | Read and write the data inside your instances |
| `write:cloud-organization` | Create organisations, and manage members, roles, and invitations |
| `write:cloud-billing` | Update billing details and manage Spectron plans |
| `write:cloud-spectron` | Create Spectron contexts and manage who can use them |
| `query:spectron-contexts` | Store and recall agent memory in a Spectron context |

Add `read:cloud` alongside any of the others. Without it your assistant cannot look up which organisation or instance to act on, so the write permissions have nothing to work with.

> [!IMPORTANT]
> A personal access token stands in for your whole account and does not expire on its own. Give it only the permissions the job needs, keep it out of files you commit, and delete it in the account portal when you are done with it.

## Available tools

Around 90 tools are grouped by what they do. You never call them by hand; your assistant picks what it needs and, in most clients, shows you the call before it runs. Read-only tools are marked as safe, so clients can approve them without asking you every time.

**Sign-in** — starts the sign-in flow when your assistant is not connected yet.
`mcp_auth`

**Profile and organisations** — find out who you are signed in as and which organisations you can work in.
`get_cloud_profile`, `list_organizations`, `get_organization`, `create_organization`, `update_organization`

**Members and invitations** — manage who else has access to an organisation, and what they can do.
`list_organization_members`, `list_organization_roles`, `update_organization_member_role`, `remove_organization_member`, `list_organization_invitations`, `invite_organization_member`, `revoke_organization_invitation`

**Terms** — review and accept the SurrealDB Cloud terms, which is a one-off step before your first paid resource.
`get_cloud_terms_and_conditions`, `get_cloud_terms_acceptance_status`, `accept_cloud_terms_and_conditions`

**Catalogue** — retrieve the regions, instance types, versions, and countries that other tools ask for.
`list_regions`, `list_instance_types`, `list_instance_versions`, `list_billing_countries`, `list_context_regions`

**Instances** — create, resize, pause, resume, upgrade, and delete instances, and estimate what one will cost.
`list_organization_instances`, `get_instance`, `estimate_instance_cost`, `deploy_instance`, `pause_instance`, `resume_instance`, `update_instance_type`, `update_instance_version`, `update_instance_compute_units`, `update_instance_storage`, `update_instance_access_type`, `update_instance_capabilities`, `get_instance_backup_policy`, `update_instance_backup_policy`, `delete_cloud_instance`

**Instance data** — run SurrealQL and data operations inside a running instance.
`call_instance_tool`, `list_instance_tools`, `get_instance_database_token`

**Monitoring and usage** — check whether an instance is healthy and how much it is being used.
`get_instance_status`, `get_instance_metrics`, `get_instance_logs`, `get_instance_usage`, `get_organization_usage`

**Billing and payment** — set up billing for an organisation, read invoices, and check whether it can deploy yet.
`get_organization_deployment_readiness`, `get_organization_billing_requirements`, `get_organization_billing`, `update_organization_billing`, `copy_organization_billing_from`, `setup_organization_for_instances`, `get_organization_payment`, `get_organization_payment_setup_url`, `get_organization_payment_portal_url`, `list_invoices`, `list_billing_coupons`

**Spectron contexts** — create and configure the memory contexts your agents use.
`list_organization_spectron_contexts`, `get_spectron_context`, `create_spectron_context`, `update_spectron_context`, `delete_spectron_context`, `get_spectron_context_config`, `get_spectron_context_usage`, `list_spectron_context_providers`, `list_spectron_context_verbs`

**Spectron access control** — decide which people, agents, and services may use a context, and issue or revoke their keys.
`list_spectron_context_principals`, `create_spectron_context_principal`, `update_spectron_context_principal`, `delete_spectron_context_principal`, `replace_spectron_principal_grants`, `add_spectron_context_user`, `list_spectron_context_api_keys`, `rotate_spectron_context_api_key`, `delete_spectron_context_api_key`, `mint_spectron_scoped_key`, `mint_spectron_access_token`

**Spectron scopes** — organise memory into paths so each project, team, or user keeps its own.
`list_spectron_context_scopes`, `create_spectron_context_scope`, `delete_spectron_context_scope`

**Spectron plans** — subscribe an organisation to a Spectron package, or cancel one.
`list_spectron_context_packages`, `list_organization_spectron_context_packages`, `assign_organization_spectron_context_package`, `cancel_organization_spectron_context_package`

**Spectron memory and documents** — hold a conversation that remembers, and store, search, or reflect on what it learned.
`call_spectron_tool`, `list_spectron_tools`, `create_spectron_session`, `call_spectron_chat`, `get_spectron_memory_snapshot`, `list_spectron_entities`, `list_spectron_documents`, `search_spectron_documents`

Three reference lists are also offered as resources for clients that prefer them to tool calls: available regions, instance types, and SurrealDB versions. Clients with a prompt menu get a **Deploy a Cloud Instance** wizard, which walks through the choices, prices the result, and waits for your go-ahead.

## Working with your data

The same connection that manages an instance can also query it. Ask a question, and your assistant chooses the namespace and database, writes the SurrealQL, and shows you what came back. See [Example usage](/docs/build/ai-agents/mcp/examples) for prompts to try.

Two things have to be true first. The instance must be running, so resume it if you paused it. And it must be on **SurrealDB 3.1 or later**, since that is the version that started answering these calls. If it is older, ask your assistant to upgrade it.

### Published tools

Inside an instance, these are the tools your assistant has to work with:

| Tool | What it does |
| --- | --- |
| `use` | Choose the namespace and database to work in |
| `query` | Run SurrealQL |
| `select`, `create`, `insert`, `upsert`, `update`, `delete`, `relate` | Read and change records without writing a full statement |
| `run` | Call a database function |
| `list` | List namespaces, databases, tables, indexes, and users |
| `info` | Describe the schema, or the engine itself |

A database you run yourself offers the same set. See [Embedded MCP](/docs/build/ai-agents/mcp/embedded) for how they behave there.

Spectron contexts work the same way: your assistant can `remember`, `recall`, `reflect`, `forget`, `upload`, and `inspect` against a context you own. The [Spectron MCP tools reference](/docs/spectron/integrations/mcp-server/tools-reference) describes each one.

## Deploying an instance

Creating an instance costs money, so the server never quietly does it. Your assistant first checks whether the organisation is ready to deploy and reports back anything standing in the way: no free instances left on the plan, billing details missing, or no payment method on file.

Clearing those blockers is a conversation. The assistant asks for the billing contact and address it needs, then hands you a secure checkout link to add a card yourself. Card numbers never pass through the assistant. Once the payment goes through, it can check readiness again and deploy.

Before it creates anything, ask for an estimate. The assistant can price a configuration, show you the monthly cost, and wait for you to agree.

## What the server will not do

- **Delete an instance on a guess.** Deletion is permanent and takes the instance's backups with it, so the assistant has to name the instance exactly as it stands right now. A stale or mistaken name is refused.
- **Handle your card.** Payment details are only ever entered by you, on a secure checkout page. No tool accepts a card number.
- **Accept terms for you.** Your assistant can fetch the documents and link you to them, but the agreement is yours to give.
- **Show a secret twice.** New Spectron keys and access tokens appear once, at the moment they are created. Store them somewhere safe there and then.

Clients often let you auto-approve tools to save clicks. Reserve that for the read-only ones and keep the confirmation step on anything that changes or removes something.

## Troubleshooting

| What you see | What to do |
| --- | --- |
| Your client says the server needs authentication | Sign in again from the client, or check the personal access token still exists in the [account portal](https://account.surrealdb.com) |
| A tool reports missing permissions | Your token was created without that permission. Permissions are fixed once a token exists, so create a new one with the right boxes ticked |
| Sign-in is refused because your email is not verified | Verify the email address on your Surreal ID, then sign in again |
| Your assistant loses its connection after a while | Idle connections are dropped. Reconnect in the client and carry on |
| An instance cannot be queried | It is paused or still starting. Wait until it reports as ready, or ask your assistant to resume it |
| An instance says it needs a newer version | Data tools need SurrealDB 3.1 or later. Ask your assistant to upgrade the instance |
| Your assistant cannot find an organisation you named | It is looking for the organisation's identifier rather than its display name. Ask it to list your organisations first |
