Surform treats a SurrealDB schema as a file you version. A `schema.surdl` file describes the
catalog — namespaces, databases, tables, fields, indexes, accesses — and the `surform` compiler
turns it into SurrealQL `DEFINE` DDL. It works in the other direction too: the database's
rendered `INFO` output is read back into canonical SDL, so `surform migrate generate` can report
exactly what drifted between the file and the running database, and print the script that
converges it.

Around the compiler there is a formatter, an advisory linter, multi-file composition, schema-level
type aliases, and a migration pipeline (generate / commit / push / status / revert) that records
applied migrations in a ledger inside the database. Surform embeds the official SurrealQL parser,
so the DDL it emits is validated by the same parser the server runs.
