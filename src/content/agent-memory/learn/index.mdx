# Learn

This section explains how SurrealDB Agent Memory works. The mental model comes first, then each step a fact goes through, from ingest to retrieval, and last the architecture underneath. If context windows and embeddings are new to you, start with [How an AI model remembers](/docs/agent-memory/welcome/how-a-model-remembers).

## Concepts

- [Contexts and scope](/docs/agent-memory/learn/mental-model/contexts-and-scope) - where memory is stored, and who can read which part of it
- [Sessions and turns](/docs/agent-memory/learn/mental-model/sessions-and-turns) - the unit of a conversation
- [Memory categories](/docs/agent-memory/learn/mental-model/memory-categories) - the six kinds of experiential memory
- [Supersession, decay, and forget](/docs/agent-memory/learn/mental-model/memory-lifecycle) - how a fact changes and ends
- [Provenance and traceability](/docs/agent-memory/learn/mental-model/provenance-and-traceability) - where each fact came from
- [Unified substrate and authority](/docs/agent-memory/learn/mental-model/two-layer-architecture) - how documents and conversations meet in one graph

Agent Memory stores two kinds of material in one SurrealDB graph, the Authoritative and Experiential pillars from [Eight pillars and six categories](/docs/agent-memory/learn/architecture/eight-pillars-and-categories):

- **Authoritative** - manuals, policies, product data, structured uploads (`source.kind = "document"`, higher default trust).
- **Experiential** - conversation, sessions, and derived facts (`source.kind = "turn"`, reflections, elaborations, consolidations).

The sections below are organised by what you do with them: ingest, retrieve, reason and tune.
