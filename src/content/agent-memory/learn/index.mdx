# Learn

This section explains how SurrealDB Agent Memory works. The mental model comes first, then each step a fact goes through, from ingest to retrieval, and last the architecture underneath. If context windows and embeddings are new to you, start with [How an AI model remembers](/docs/agent-memory/welcome/how-a-model-remembers), and then read [How it works in five minutes](/docs/agent-memory/welcome/how-it-works).

## Two kinds of material

Agent Memory stores two kinds of material in one SurrealDB graph, the Authoritative and Experiential pillars from [Eight pillars and six categories](/docs/agent-memory/learn/architecture/eight-pillars-and-categories):

- **Authoritative** - manuals, policies, product data and structured uploads (`source.kind = "document"`), which have a higher default trust.
- **Experiential** - conversation, sessions and the facts derived from them (`source.kind = "turn"`, reflections, elaborations and consolidations).

Every section below applies to both kinds, except where a page says otherwise.

## Where to start

Reading order depends on what you are doing. To put data in, read [Contexts and scope](/docs/agent-memory/learn/mental-model/contexts-and-scope) and then [Remember](/docs/agent-memory/learn/ingest/experiential/remember) or [Uploading documents](/docs/agent-memory/learn/ingest/authoritative/uploading-documents). To get answers out, read [Recalling memories](/docs/agent-memory/learn/retrieve/recall). To understand why a fact changed, read [Supersession, decay, and forget](/docs/agent-memory/learn/mental-model/memory-lifecycle) and [Reconciliation and supersession](/docs/agent-memory/learn/reasoning/reconciliation-and-supersession). The HTTP tables are in the [REST API reference](/docs/agent-memory/reference/rest-api).
