# Data model and schema

SurrealDB Agent Memory stores all state in SurrealDB. This page describes the key tables, their fields, and the indexes that power retrieval. Schema migrations are bundled in the SurrealDB Agent Memory binary and applied automatically when a Context is created or upgraded.

## Schema namespaces

| Namespace | Database | Contents |
|---|---|---|
| `spectron` | `metadata` | Control plane: Context registry, API keys |
| `spectron` | `_jobqueue` | Async ingestion job queue |
| `<context_ns>` | `<context_db>` | All authoritative knowledge and experiential memory data for one Context |

Each Context is bound to its own `(namespace, database)` pair. Tables are never shared across Contexts.

## Scope on stored records

Scoped tables carry a **`scope`** field: an array of **`scope_sets`** records, read as an OR of clauses. Each `scope_sets` record holds **`members`**, an AND of hierarchical **`scopes`** nodes. Entity and keyword records instead store a derived **`visible_scope_sets`**, so name and type lookups cannot leak facts the caller cannot read whole. See [Contexts and scope](/docs/agent-memory/mental-model/contexts-and-scope) for the visibility rules.

## Control plane tables

### `context`

The Context registry. Records each Context's binding and embedded configuration.

| Field | Type | Notes |
|---|---|---|
| `id` | string | Context identifier (e.g. `acme-prod`) |
| `namespace` | string | Bound SurrealDB namespace |
| `database` | string | Bound SurrealDB database |
| `config` | object | Embedded config (models, providers, limits) |
| `created_at` | datetime | |

### `api_key`

Management keys (not per-Context). Used for creating and managing Contexts.

### `context_api_key`

Per-Context end-user keys, stored as Argon2 hashes. Each key binds to a principal and optionally attenuates that principal's grants.

| Field | Type | Notes |
|---|---|---|
| `context` | `record<context>` | The Context this key belongs to |
| `name` | string | Human-readable label, unique per Context |
| `hash` | string | Argon2 hash of the secret |
| `principal_id` | option\<string\> | The principal this key acts as. Stored as a plain string because the `principal` row lives in the Context's own database, not the control plane |
| `grants` | option\<object\> | Attenuating per-verb pattern map (`grants.*` is `array<string>`). Absent ⇒ inherit the principal's grants |
| `strict` | bool | Opt into hard out-of-region errors instead of empty results. Defaults to `false` |
| `valid_until` | option\<datetime\> | Mint-time expiry. Absent ⇒ no expiry |
| `created_at` | datetime | |
| `last_used_at` | option\<datetime\> | Vestigial - no longer written. Last use is derived as `max(used_at)` over `context_api_key_usage`; the column stays defined so older rows deserialise |

### `context_api_key_usage`

Append-only key-use log: one record per successful data-plane key validation, throttled to at most one record per key per minute. This is what backs the derived `lastUsedAt` on the self-service key listing - it records recent activity, not a per-request audit trail.

| Field | Type | Notes |
|---|---|---|
| `key` | `record<context_api_key>` | The key that validated |
| `context` | `record<context>` | |
| `used_at` | datetime | |

### `knowledge_has_keyword`

Relation edge from a document to its keywords.

```surql
DEFINE TABLE knowledge_has_keyword TYPE RELATION IN document OUT keyword SCHEMAFULL;
DEFINE FIELD created_at ON knowledge_has_keyword TYPE datetime DEFAULT time::now() READONLY;
DEFINE FIELD labels ON knowledge_has_keyword TYPE array<string> DEFAULT [];
DEFINE FIELD scope ON knowledge_has_keyword TYPE array<record<scope_sets>> DEFAULT [];
DEFINE FIELD score ON knowledge_has_keyword TYPE float;
DEFINE INDEX score_index ON knowledge_has_keyword FIELDS score;
DEFINE INDEX unique_pair ON knowledge_has_keyword FIELDS in, out UNIQUE;
```

Structured authoritative facts extracted from documents (or ingested via `POST /facts` with `infer: "triples"`) are stored as **`entity`**, **`attribute`**, and **`relates_to`** records. Their provenance is the **`source`** object, with `source.kind = "document"`.

### Other knowledge tables

| Table | Purpose |
|---|---|
| `knowledge_section` | Document sections, keyed by document and position, with a section embedding so retrieval can find the right section before its chunks. |
| `knowledge_links_to` | Relation from one document to another for a citation or link (`in` cites `out`). |
| `image_chunk` | Visual embeddings and optional OCR text for image documents and sampled video frames. |
| `audio_chunk` | One record per spoken segment of an audio or video document, with start and end times and its own text embedding. |
| `document_deletion` | Queue of objects to remove from the object store after a document is deleted, once no other document references the same hash. |
| `embedding_backfill_job` | Resumable job that re-encodes records when the embedding model changes. |
| `_jobqueue_knowledge_ingestor` | Per-Context queue of document ingest jobs. |

### Other experiential tables

| Table | Purpose |
|---|---|
| `principal` | The data-plane identities of the Context, with `kind`, `display_name`, `grants` and `metadata`. |
| `grant_event` | Recorded grant changes per principal and verb, with `valid_from` and `valid_until`. |
| `action` | Dated events: an `actor`, a `verb` and an `object`, with event time in `occurred_at`. |
| `same_as` | Relation from an alias entity to its canonical entity. |
| `retrieval_trace` | Written by every `/query` and every other ranked read: the query, the candidates per index, the fused ranking and the returned subset. |
| `response_trace` | Written by `/chat` and `/reflect`: the message, the assembled prompt, the LLM response and the cost. |
| `considered`, `returned` | Relations from a `retrieval_trace` to the candidates it considered and the records it returned. |
| `created`, `superseded`, `flagged` | Relations from a `decision_trace` to the records it created or superseded, and to any `uncertainty` it raised. |
| `used_retrieval`, `produced_decision`, `wrote` | Relations from a `response_trace` to its retrievals, its decisions and the records it wrote. |
| `parent_trace` | Relation from a retrieval or decision trace to the `response_trace` that owns it. |
| `consolidation_run` | One record per Context that tracks where the last consolidation pass stopped. |
| `idempotency_record` | Reserved and stored responses for `Idempotency-Key` requests, unique per Context, principal and key. |

## Migrations

Schema is bundled into the SurrealDB Agent Memory binary and applied automatically when a Context is created or upgraded. See [Migration status](/docs/agent-memory/reference/management-api#migration-status) for the fleet-wide catch-up view.
