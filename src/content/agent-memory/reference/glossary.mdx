# Glossary

This page defines the terms that appear throughout the SurrealDB Agent Memory docs, in alphabetical order, with a link to the page that covers each one in depth.

SurrealDB Agent Memory's architecture is described by **eight pillars** of agent memory and by **six memory categories**: the episodic transcript, plus identity, knowledge, context, instructions and uncertainty. Curated documents and conversational memory are the **Authoritative** and **Experiential** pillars, and both are records in the same SurrealDB graph. See [Eight pillars and six categories](/docs/agent-memory/learn/architecture/eight-pillars-and-categories) and [Unified substrate and authority](/docs/agent-memory/learn/mental-model/two-layer-architecture).

The vocabulary is precise, but the intent is everyday: memory that **associates** related ideas, and keeps **time and scope** straight ("I have one" against "I used to" against "they weigh about four kilos in general"). [What is SurrealDB Agent Memory?](/docs/agent-memory/welcome/what-is-surrealdb-agent-memory) and [Memory categories](/docs/agent-memory/learn/mental-model/memory-categories) walk through examples of that kind.

## Action

A dated event that an entity performed, such as a purchase or a visit, recorded with a verb instead of a key. Extraction produces actions alongside entities, attributes and relations, and a `/query` hit can have the result kind `action`. See [Structured fact ingest](/docs/agent-memory/learn/ingest/authoritative/bulk-import).

## Anaphora

Pronouns and phrases in a conversation that refer back to something said earlier ("he", "that project", "the policy we discussed"). Episodic memory keeps the transcript as it was spoken, and extraction uses the surrounding text to work out what they mean.

## Attribute

A named property on an entity, such as `role = Head of Platform`, that records a learned or asserted fact. Attributes are versioned: when a value changes, the old attribute is superseded and not deleted, and each attribute carries `valid_from` and `valid_until` timestamps for temporal queries. See [Supersession](#supersession).

## Authoritative pillar

Curated, vetted knowledge, such as handbooks, policies, product catalogues, FAQs and structured exports. Documents (`source.kind = "document"`) and structured triples (`upsert`) carry a higher default [trust](#trust) than conversation turns.

Curated records are never silently overwritten. When an experiential assertion conflicts with one, the curated record stays unchanged, the user's belief is stored in experiential memory with its provenance, and the clash is recorded as an [uncertainty](#uncertainty) that state and profile responses show. See [Authority when pillars meet](/docs/agent-memory/learn/reasoning/authority-hierarchy).

## Calibration

The pillar that gates assertions by confidence and trust. Below a configurable floor, SurrealDB Agent Memory refuses to overwrite a record and records an [uncertainty](#uncertainty) instead.

## Collective

The pillar for shared memory when several people or agents corroborate the same fact. Independent assertions keep separate provenance records and are not averaged into one anonymous fact.

## Confidence

The reconciler's certainty about an assertion after extraction, stored as `attribute.confidence`. It is separate from [source trust](#source-trust), which describes the source.

## Consolidation

A background process that turns repeated observations into longer-lived beliefs. Its output carries `source.kind = "consolidation"`.

## Context

The unit of memory storage and configuration isolation. Each Context is bound to a SurrealDB `(namespace, database)` pair and has its own API keys, model configuration and data, and Contexts cannot see each other's data. See [Contexts and scope](/docs/agent-memory/learn/mental-model/contexts-and-scope).

## Context category

The memory category for what matters right now in the active conversation, such as the ticket someone is working on. It has a short retention and is replaced quickly. It is a different thing from a [Context](#context).

## Decision trace

A graph record of what the reconciler considered during a write: the candidates, the records it created or superseded, the confidence and trust involved, and links to parent traces. It is one of the three traces in the [trace layer](#trace-layer). See [Traces and memory evolution](/docs/agent-memory/learn/architecture/traces-and-evolution).

## Delegation

Acting on behalf of another principal by sending `X-Spectron-On-Behalf-Of: <principal_id>`. The request reads and writes with the intersection of the caller's key, the caller's grants and the target's grants, so delegation never widens access. It goes one level deep, and the target cannot pass the request on to a third principal.

## Elaboration

A background process that links facts that were stored separately but belong together. Its output carries `source.kind = "elaboration"` and a `derived_from` field that points at its inputs.

## Entity

A thing that memory tracks, such as a person, company, product or location. An entity is identified by a `(type, normalised_name)` pair and carries attributes, relations and actions. Entity types come from a fixed list. See [Extraction vocabulary](/docs/agent-memory/learn/tuning/ontology-grounding#entity-types-are-a-fixed-set).

## Episodic

The memory category for the raw, ordered transcript of sessions and turns, kept as spoken before any extraction. It is the source of truth for quotes through `source.span`.

## Experiential pillar

Knowledge that comes from conversation and the passes derived from it (`turn`, `reflect`, `elaboration`, `consolidation`), usually with a lower default trust than curated material. It holds the six [memory categories](#memory-category).

## Extraction pipeline

The process that converts a conversation turn into structured records: entities, attributes, relations, actions, instructions, uncertainties and invalidations. The turn text is split into windows of up to 8,000 new characters, with at most 10 windows per turn, and each window gets one structured-output model call. See [Extraction pipeline](/docs/agent-memory/learn/reasoning/extraction-pipeline).

## Extraction vocabulary

The entity names, attribute keys, relation labels and action verbs that a Context has already used, fed back into the extraction prompt so that later runs reuse them instead of inventing near-synonyms. It is not configured: there is no per-Context ontology to declare. See [Extraction vocabulary](/docs/agent-memory/learn/tuning/ontology-grounding).

## Forget

Removing memory on request. The default, semantic forget, retires matching memory by setting `valid_until` and leaves the records in storage. Purge and scoped forget erase records, and scoped forget hard-deletes everything stored only under a scope subtree. Every kind needs the `memory:forget` grant. See [Forgetting memories](/docs/agent-memory/learn/operations/forget).

## Grant

A permission on a principal or an API key: a verb such as `memory:read`, `memory:write` or `memory:forget`, mapped to a list of scope patterns where it applies. A key's grants can never exceed those of the principal it acts as. See [Contexts and scope](/docs/agent-memory/learn/mental-model/contexts-and-scope).

## Graph edge kind

A named structural signal that `hybrid_graph` document retrieval uses, such as `knowledge_has_keyword` or `document_link`. Request and response enums reject unknown values with `400 Bad Request`.

## Hybrid retrieval

A query mode that fuses vector similarity and BM25 keyword results with reciprocal rank fusion (RRF). BM25 finds exact-keyword matches that semantic search can miss. The `hybrid_graph` mode adds a graph-density reranking pass for more precision. See [Hybrid search](/docs/agent-memory/learn/retrieve/hybrid-search).

## Identity

The memory category for stable facts about who someone is, such as a name, title or employer. It has a long retention and feeds profile summaries.

## Infer mode

The `infer` parameter of `POST /facts`, which decides how written data becomes memory: `full` (a model extracts structure, the default), `triples` (the caller sends structured triples, stored as given with no model), `preview` (a dry run) and `none` (the text is stored literally). See [Remember](/docs/agent-memory/learn/ingest/experiential/remember).

## Instructions

The memory category for behavioural directives extracted from conversation, such as "always use British English", stored apart from factual memory and applied when the prompt is assembled, not through general retrieval. An instruction is not revoked or superseded: when a user reverses one, the reversal is extracted as a new active instruction beside the earlier one, and a profile shows both. See [Instructions and uncertainties](/docs/agent-memory/learn/reasoning/instructions-and-uncertainties).

## Knowledge

The memory category for facts learnt in conversation, as distinct from uploaded manuals. It has a medium retention and fades without reinforcement.

## Known time

When SurrealDB Agent Memory first recorded a belief, queried with the `asOf` parameter. It is one of the three clocks of the [tri-temporal model](#tri-temporal-model). See [Tri-temporal model](/docs/agent-memory/learn/architecture/tri-temporal-model).

## Labels

Descriptive `key=value` tags, such as `subject=alice`, that filter results within what a caller's scope and permissions already allow. A label never grants access by itself.

## Lens

A parameter on `/query` and `/context` that takes hierarchical scope paths and filters results by involvement, within the caller's grant. A lens of `region/eu` returns every readable record whose scopes include `eu`. A lens never widens access.

## MCP (Model Context Protocol)

An open protocol for connecting AI agents to tools and data sources. SurrealDB Agent Memory serves an MCP server at `/mcp` with seven tools: `remember`, `recall`, `context`, `reflect`, `forget`, `upload` and `inspect`. See [MCP tools reference](/docs/agent-memory/integrations/mcp-server/tools-reference).

## Memory category

The classification of memory by lifecycle and retrieval behaviour: the **episodic** transcript, plus `identity`, `knowledge`, `context`, `instructions` and `uncertainty`. The `memory_category` field on entities, attributes and relations accepts only `identity`, `knowledge` and `context`, and the other two categories have records of their own. See [Memory categories](/docs/agent-memory/learn/mental-model/memory-categories).

## Memory chunk

A record of literal text stored with `infer: none`. Long text is split into several `memory_chunk` records, each with its own embedding, so that vector recall covers the whole passage.

## Principal

The identity that an API key acts as. A principal has a `kind` (`human`, `agent`, `service` or `unknown`) that describes what it is, and a per-verb `grants` map that decides what it may do and where. The kind never affects access. See [Permissions and delegation](/docs/agent-memory/learn/mental-model/contexts-and-scope#permissions-and-delegation).

## Profile

A structured snapshot of the current memory for a scope, from `GET /profile`: identity facts, dynamic context, preferences and active instructions, formatted for an agent's system prompt or an account page. See [State and diffs](/docs/agent-memory/learn/sessions/state-and-diffs#profile-endpoint).

## Provenance

The structured record of where a fact came from. Every record carries a `source` object (`kind`, `ref`, `span`, `trust`, `derived_from` and more) that traces it back to a turn, a document or a trace. See [Provenance and traceability](/docs/agent-memory/learn/mental-model/provenance-and-traceability).

## Reconciliation

The pillar that integrates newly extracted information with existing beliefs: deduplication, supersession, scope coexistence and Authoritative precedence. When confidence is insufficient or provenances disagree, it records an [uncertainty](#uncertainty) and does not pick a silent winner. See [Eight pillars and six categories](/docs/agent-memory/learn/architecture/eight-pillars-and-categories).

## Reflection

The pillar for on-demand synthesis from a question, run with `POST /reflect`. Insights can be transient, or persisted with `source.kind = "reflect"` and a lower default trust.

## Relation

A typed edge between two entities, with a label such as `works_at` or `relocated_to`, that records a fact about their connection. Relations carry temporal validity timestamps like attributes do.

## Response reuse

Tier 2 of the [read ladder](#tier): a cache of earlier `/chat` answers in the same Context, reused when a new query scores at least the `response_cache.similarity_threshold` (0.92 by default) against a prior one and every fact the answer cited is still current. See [Cache settings](/docs/agent-memory/reference/configuration#cache-settings).

## Response trace

A record of a composed answer from `/chat` or `/reflect`, used for response reuse while it is still valid.

## Result kind

The `source` field on each hit that `/query` returns: `entity`, `attribute`, `action`, `memory_chunk`, `chunk` or `section`. Literal `infer: none` writes surface as `memory_chunk`, and structured extraction surfaces as `entity` or `attribute`.

## Retrieval trace

A record of a `/query` or related read: the candidates, the signals, the tier that ran and the results.

## Scope

A hierarchical slash path, such as `org/acme/user/alice`, that partitions data within a Context. Records store their visibility as OR-of-AND clauses, and queries and grants decide which clauses a caller can see. A scope is not a permission and not a label. Register a path with `POST /scopes` or `surreal memory scopes create` before a write uses it. See [Contexts and scope](/docs/agent-memory/learn/mental-model/contexts-and-scope).

## Scope floor

The scope that an API key is bound to. The server clamps any request that tries to go beyond it, so a key bound to `org/acme` cannot act at `org/beta`.

## Scope view

The `scopeView` read parameter, which controls how broadly results are folded within the caller's grant: `strict` (the default), `crossTeam` or `merged`. The last two currently resolve like `strict`.

## Session

A conversation record: its ordered turns, its scope and its metadata. Sessions are durable, so they persist after the conversation ends and can be recalled, diffed and reflected on.

## Source kind

Where a fact came from: `upsert`, `document`, `turn`, `reflect`, `elaboration`, `consolidation` and so on. The default [trust](#trust) depends on it.

## Source span

The character positions in the originating message or passage that make a quotable citation.

## Source trust

The default weight of the source stream. A write with `infer: "triples"` has the source kind `upsert` and a trust of 0.95, a document upload 0.80 and a conversation turn 0.50. See [Provenance and traceability](/docs/agent-memory/learn/mental-model/provenance-and-traceability#default-trust-by-source).

## Supersession

The versioned replacement of an attribute value. When new information contradicts a stored attribute, the old record is marked with `superseded_by` and `valid_until`, and a new record is created with `supersedes` and `valid_from`. Both stay in the database as a correction history. See [Reconciliation and supersession](/docs/agent-memory/learn/reasoning/reconciliation-and-supersession).

## System time

The database's MVCC history: what was stored at an instant. It is one of the three clocks of the [tri-temporal model](#tri-temporal-model).

## Tier

A step of the four-tier ladder that reads follow, so that simple questions use as few model tokens as possible: structured seed reads (tier 1), [response reuse](#response-reuse) (tier 2), hybrid retrieval and synthesis (tier 3) and escalated retrieval (tier 4). A `/query` response reports the tier that answered as `direct`, `cache`, `hybrid` or `escalated`. See [Coherence, retrieval, and cost tiers](/docs/agent-memory/learn/architecture/coherence-retrieval-and-tiers).

## Trace layer

Memory about how memory was used: retrieval traces, decision traces and response traces. The layer feeds the ranker, the calibrator and the consolidator. See [Traces and memory evolution](/docs/agent-memory/learn/architecture/traces-and-evolution).

## Triple

A structured fact that a caller supplies to `POST /facts` with `infer: "triples"`: an entity, a key and a value. An entry with a `verb` in place of a key records an [action](#action). See [Structured fact ingest](/docs/agent-memory/learn/ingest/authoritative/bulk-import).

## Tri-temporal model

The model that keeps three clocks apart: [system time](#system-time), [known time](#known-time) and [valid time](#valid-time). See [Tri-temporal model](/docs/agent-memory/learn/architecture/tri-temporal-model).

## Trust

How far a source stream is believed, used when curated and conversational facts meet. See [source trust](#source-trust) and [calibration](#calibration).

## Turn

A single message in a session, with a role (`user`, `assistant`, `system` or `tool`) and content. Turns are the input to the extraction pipeline and the provenance anchor for the memory produced from them.

## Uncertainty

An explicit record of a gap or a clash, kept in place of a guessed fill-in. It is one of the six memory categories and the output of [reconciliation](#reconciliation) when confidence is insufficient or provenances disagree.

## Unified graph

One SurrealDB store for documents, turns, entities, relations and traces. See [Unified substrate and authority](/docs/agent-memory/learn/mental-model/two-layer-architecture).

## Valid time

When a fact held in the real world, recorded with `valid_from` and `valid_until` on attributes and relations, independent of when SurrealDB Agent Memory learnt it. The fields enable point-in-time queries without deleting old data. See [Temporal validity](/docs/agent-memory/learn/reasoning/temporal-validity).
