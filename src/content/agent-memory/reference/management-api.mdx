# Management API

The management API provides control-plane operations: creating Contexts, managing principals and API keys, connectors, and operator lifecycle. It runs as its own process, separate from the user API, on `SPECTRON_MANAGEMENT_BIND_ADDRESS` (REST) and `SPECTRON_MANAGEMENT_GRPC_BIND_ADDRESS` (gRPC). All management endpoints are under `/api/v1/` and require a management key.

## Authentication

Management endpoints require a **management** API key as a Bearer token:

```http
Authorization: Bearer <management-key>
```

Keys are printed once by bootstrap or seeded with `SPECTRON_MANAGEMENT_API_KEY`. They are distinct from per-Context end-user keys. A data-plane key sent to the management API gets `401`.

## Contexts

### List Contexts

```http
GET /api/v1/contexts
```

Returns all Contexts registered on this SurrealDB Agent Memory deployment.

**Response:**
```json
{
  "contexts": [
    {
      "id": "acme-prod",
      "namespace": "acme",
      "database": "prod",
      "config": {
        "token_limit": 1000000,
        "models": { "extraction": { "provider": "openai", "model": "gpt-5-mini" } },
        "providers_configured": ["openai"]
      },
      "created_at": "2026-01-15T10:00:00Z",
      "schema_version": 29,
      "enforcement_blocked": false
    }
  ],
  "page": { "hasMore": false }
}
```

### Create a Context

```http
POST /api/v1/contexts/{context_id}
Content-Type: application/json

{
  "namespace": "acme",
  "database": "prod",
  "admin_external_id": "surreal-cloud:usr_01HF…",
  "admin_display_name": "Alice Admin",
  "config": {
    "token_limit": 1000000,
    "models": {
      "extraction": { "provider": "openai", "model": "gpt-5-mini" },
      "elaboration_consolidation": { "provider": "openai", "model": "gpt-5.1" }
    },
    "providers": {
      "openai": "sk-..."
    }
  }
}
```

Creates the Context, provisions the SurrealDB namespace and database, and applies schema migrations. Returns `201 Created`.

If provisioning fails **after** the database was created by this request, SurrealDB Agent Memory **discards that database** so a retry starts from a clean migration state. Pre-existing databases (operator-provided or left over from a crash) are never removed - only a database this request created is eligible for discard.

When **`admin_external_id`** is set, SurrealDB Agent Memory seeds an initial **`principal:admin`** bound to that opaque, issuer-qualified identity (for example `surreal-cloud:<user_id>`) with full `/*` grants - so a Cloud proxy can create a Context and immediately resolve the org owner without a follow-up principal call. **`admin_display_name`** is an optional human-readable label. Omit both fields to keep the generic admin principal.

**Response:**
```json
{
  "id": "acme-prod",
  "namespace": "acme",
  "database": "prod",
  "config": {
    "token_limit": 1000000,
    "models": { "extraction": { "provider": "openai", "model": "gpt-5-mini" } },
    "providers_configured": ["openai"]
  },
  "created_at": "2026-05-12T10:00:00Z",
  "schema_version": 29,
  "enforcement_blocked": false
}
```

Each model stage is an object with a `provider` and a `model`. See [Configuration](/docs/agent-memory/reference/configuration#config-fields) for the stages and the accepted models.

### Migration status

```http
GET /api/v1/migrations
```

Returns a fleet-wide view of per-Context schema catch-up after a binary upgrade: version histogram, Contexts still behind the embedded latest, and DLQ entries.

### Run a Context's migration now

```http
POST /api/v1/contexts/{context_id}/migrate
```

Queues this Context's schema migration to run now, ahead of the scheduler's next retry, and returns the queued job immediately. Track it in `GET /api/v1/migrations`.

### Get a Context

```http
GET /api/v1/contexts/{context_id}
```

Returns the Context record. Provider API key values are replaced with a `providers_configured` summary (per-Context keys only). For the full provider and model catalogue - including providers reachable via deployment-wide keys - use **`GET /api/v1/contexts/{context_id}/providers`**.

### List providers

```http
GET /api/v1/contexts/{context_id}/providers
```

Lists the providers available to the Context and the models selectable for each.

### Usage and stats

```http
GET /api/v1/contexts/{context_id}/usage
GET /api/v1/contexts/{context_id}/stats
```

`usage` returns the Context's token consumption for the current billing period. `stats` counts the records in each of the Context's data-plane tables. It scans every table it reports, so fetch it when needed rather than on every request.

### Update Context config

```http
PATCH /api/v1/contexts/{context_id}
Content-Type: application/json

{
  "token_limit": 2000000,
  "models": {
    "elaboration_consolidation": { "provider": "anthropic", "model": "claude-sonnet-4-6" }
  }
}
```

Deep-merges the provided fields into the existing config and returns the updated config. Send the config fields at the top level of the body. Unset fields are left unchanged, and unknown fields are ignored without an error, so a body wrapped in `{"config": ...}` changes nothing.

### Set enforcement

```http
PUT /api/v1/contexts/{context_id}/enforcement
Content-Type: application/json

{ "blocked": true }
```

Sets the Context's runtime hard block (**`enforcement_blocked`**, see [Configuration](/docs/agent-memory/reference/configuration#top-level-context-fields-outside-config)). While blocked, every gated LLM and embedding call for the Context is rejected with `429`, background work included. The call is idempotent.

### Delete a Context

```http
DELETE /api/v1/contexts/{context_id}
```

Drops the bound SurrealDB database (removing all authoritative knowledge and experiential memory data), deletes the associated API keys, and removes the control-plane registry entry. This is irreversible. Returns `204 No Content`.

## Grant verbs

SurrealDB Agent Memory authorises data-plane and admin operations with seven scoped verbs in `<noun>:<verb>` form:

| Verb | Purpose |
| --- | --- |
| `memory:read` | Read facts and document chunks/keywords within the granted region (recall, query, chat, document GET/list) |
| `memory:write` | Write facts and ingest documents (chunks inherit the uploader’s write region) |
| `memory:forget` | Soft or hard forget, entity delete, scoped subtree erasure |
| `scope:read` | List scope names visible within the grant (does not imply data access) |
| `scope:create` | Register new scope paths |
| `scope:delete` | Remove scope paths |
| `grant:manage` | Grant or revoke access on principals |

Documents are governed by **`memory:*`** verbs - there is no separate `document:*` namespace. Upload and reprocess require `memory:write`; document reads are per-record under `memory:read`.

List the machine-readable catalog (for grant pickers and validation):

```http
GET /api/v1/verbs
Authorization: Bearer <management-key>
```

Grant verbs use namespaced forms (`memory:read`, `memory:write`, …). Flat names such as `read` and `write` are rejected.

## Principals and external identity

Principals are the data-plane identity SurrealDB Agent Memory authorises. Create one with a required **`kind`** and **`display_name`**, and an optional **`external_id`** so upstream systems (SurrealDB Cloud, OIDC, on-prem IdP) can resolve “which principal is this user?” without a side mapping table:

```http
POST /api/v1/contexts/{context_id}/principals
Content-Type: application/json

{
  "kind": "human",
  "display_name": "Alice",
  "external_id": "surreal-cloud:usr_01HF…",
  "grants": {
    "memory:read": ["org/acme/user/alice/*"],
    "memory:write": ["org/acme/user/alice/*"]
  }
}
```

`kind` is one of `human`, `agent`, `service` or `unknown`. It describes the identity: what a principal may do comes only from its grants. `grants` is a map from each verb to a list of scope patterns, and defaults to no grants. The response is `201 Created` with the new principal's `id`.

When **`external_id`** is present, create is **create-or-get**: a repeat call with the same issuer-qualified id returns the existing principal unchanged (even if `display_name` differs). Without `external_id`, each call mints a fresh principal. A duplicate **`display_name`** when no matching `external_id` applies returns **`409 Conflict`**. The value is opaque to SurrealDB Agent Memory - qualify it with your issuer prefix.

### Manage principals

| Method | Path | Description |
| --- | --- | --- |
| `GET` | `/api/v1/contexts/{context_id}/principals` | Lists every principal in the Context, ordered by principal id. |
| `GET` | `/api/v1/contexts/{context_id}/principals/{principal_id}` | Returns one principal by id. |
| `PATCH` | `/api/v1/contexts/{context_id}/principals/{principal_id}` | Updates a principal's `kind` and/or `display_name`. |
| `DELETE` | `/api/v1/contexts/{context_id}/principals/{principal_id}` | Deletes a principal and revokes its bound API keys. |
| `PUT` | `/api/v1/contexts/{context_id}/principals/{principal_id}/grants` | Replaces a principal's entire grant map. The body is `{"grants": {"<verb>": ["<pattern>", ...]}}`. |
| `GET` | `/api/v1/contexts/{context_id}/principals/{principal_id}/grant-history` | Reads back the principal's recorded grant changes, oldest first. Grants assigned when the principal was created are not events, so they do not appear here. |
| `GET` | `/api/v1/contexts/{context_id}/scopes` | Lists the Context's registered scope nodes (live and tombstoned), ordered by scope path. |

### Reserved built-in principals

Every Context seeds two reserved principals:

| Principal | Policy |
| --- | --- |
| **`principal:system`** | Fully **immutable** - update, grant change, and delete all return **`403`**. Background jobs stamp provenance against this identity. |
| **`principal:admin`** | **Undeletable** (delete returns **`403`**) but otherwise mutable - rename, re-kind, and grant changes are allowed. Recovery from a broken admin grant map uses the control-plane management key, which is independent of this data-plane principal. |

Grant changes and key minting for ordinary principals enforce **attenuation only** at the store layer: key grants must be a subset of the bound principal's grants on **every** mint path (management nested mint and self-service **`POST /keys`**).

## API keys

Data-plane keys are always **bound to a principal**. Mint them under that principal on every path (management nested mint, Cloud broker, or self-service `POST /{ctx}/keys`). Keys with no principal binding are rejected with **`401`**.

### Mint a key (principal-nested)

```http
POST /api/v1/contexts/{context_id}/principals/{principal_id}/keys/{key_name}?ttl_seconds=2592000
Content-Type: application/json

{
  "grants": {
    "memory:read": ["org/acme/agent/planner/*"]
  }
}
```

Optional **`grants`** in the body **attenuate** (narrow) the principal’s grants per verb (intersect only - widening returns `400`). Omit grants to inherit the principal’s full region. The secret is returned once.

Duplicate key names within a Context return **`409 Conflict`** (names are unique per Context, not per principal).

### List keys for a principal

```http
GET /api/v1/contexts/{context_id}/principals/{principal_id}/keys
```

Each entry includes **`id`**, **`name`**, and optional **`grants`** - the per-key attenuating grant map. When **`grants`** is omitted, the key inherits the principal's grants wholesale; when present, it only narrows per verb.

### Rotate or delete (principal-nested)

```http
POST   /api/v1/contexts/{context_id}/principals/{principal_id}/keys/{key_name}/rotate?ttl_seconds=2592000
DELETE /api/v1/contexts/{context_id}/principals/{principal_id}/keys/{key_name}
```

On nested rotate/delete, a key that does not exist, is unbound, or belongs to a **different** principal returns **`404`** (no cross-principal leakage).

### Context-wide operator views

Flat list endpoints remain for operators auditing all keys in a Context:

```http
GET    /api/v1/contexts/{context_id}/keys
DELETE /api/v1/contexts/{context_id}/keys/{key_name}
POST   /api/v1/contexts/{context_id}/keys/{key_name}/rotate?ttl_seconds=2592000
```

List responses include optional **`grants`** on each key (same semantics as the principal-nested list).

The secret is never returned after creation except on mint and rotate.

**Principal kinds:**

| Kind | Meaning |
|---|---|
| `human` | A person, typically linked to a cloud user. |
| `agent` | An autonomous process, such as a planner or a support bot. |
| `service` | An integration or pipeline. The reserved `system` principal has this kind. |
| `unknown` | A kind for older or unrecognised values. |

The kind does not grant capabilities. A principal's grants decide what its keys can do.

### Cloud-brokered access tokens

For SurrealDB Studio and other Cloud proxies that must mint a **short-lived, member-scoped** key in one round-trip without handing every member a management key:

```http
POST /api/v1/contexts/{context_id}/access-tokens
Content-Type: application/json

{
  "externalId": "surreal-cloud:usr_01HF…",
  "kind": "human",
  "displayName": "Alice",
  "ttlSeconds": 3600,
  "grants": {
    "memory:read": ["org/acme/user/alice/*"],
    "memory:write": ["org/acme/user/alice/*"]
  }
}
```

Unlike the other management bodies, this one uses camelCase field names. It composes **create-or-get principal by `externalId`**, optional grant re-assertion, and **mint a bound key**. **`kind` and `ttlSeconds` are required** - brokered tokens cannot be unbounded, and the Context's `max_token_ttl_seconds` cap still applies. The response is `201 Created` with `key`, `principalId` and `validUntil`. Re-broker before expiry; there are no refresh tokens. The plaintext secret is returned once.

Member-facing **self-service** key management (after a brokered or admin-minted key is held) lives on the [REST API](/docs/agent-memory/reference/rest-api#self-service-keys-and-me) - not the management API. **`issue_access_token`** (Cloud broker path) emits a server warning when the caller sends no grants and the resulting principal is still entirely zero-grant. The warning is diagnostic only and does not change behaviour.

## Knowledge upload

Document upload is a data-plane operation on the user API, not a management operation. It needs a data-plane key with `memory:write` over the target scope. See [Uploading documents](/docs/agent-memory/ingest/authoritative/uploading-documents) for the full upload API.

```http
POST /api/v1/{context_id}/documents
Content-Type: multipart/form-data
Authorization: Bearer <key>

file=@document.pdf
metadata={"title": "Product Catalogue"}
```

Fields such as `title`, `source` and `observedAt` go inside the JSON `metadata` part. Separate form parts with those names are ignored.

## Lifecycle operations

The management API has no decay or reindex route. The lifecycle passes are on the user API: `POST /api/v1/{context_id}/lifecycle/decay` applies importance decay across all memories and needs `grant:manage` over `/`, and `POST /api/v1/{context_id}/lifecycle/expire` runs the expiry sweep for `context`-category memories. The embedding model is fixed, so there is no reindex.

## Connectors and bindings

A connector links an external data source to this cluster, and a binding enables a connector for one Context.

| Method | Path | Description |
| --- | --- | --- |
| `POST` | `/api/v1/connectors/{connector_id}` | Registers an org's connector on this cluster. Credentials in the body are write-only. |
| `GET` | `/api/v1/connectors` | Lists one org's connectors, ordered by connector id. `org_ref` is required. |
| `GET` | `/api/v1/connectors/{connector_id}` | Returns one connector, reporting whether credentials are set but never the credentials. |
| `PATCH` | `/api/v1/connectors/{connector_id}` | Updates a connector's non-secret configuration or its ontology manifest. |
| `PUT` | `/api/v1/connectors/{connector_id}/credentials` | Replaces a connector's credentials wholesale. |
| `DELETE` | `/api/v1/connectors/{connector_id}` | Deletes a connector. Refused with `409` while any of its bindings is still awaiting cleanup. |
| `POST` | `/api/v1/connectors/{connector_id}/check` | Asks the connector host to reach the source and report its change stream, retention and collections. |
| `POST` | `/api/v1/connectors/{connector_id}/introspect` | Asks the connector host what collections the source exposes and what their records look like. |
| `POST` | `/api/v1/connectors/{connector_id}/ontology/validate` | Checks an ontology manifest against the source's schemas without storing it. |
| `POST` | `/api/v1/contexts/{context_id}/bindings/{binding_id}` | Enables a connector for the Context. |
| `GET` | `/api/v1/contexts/{context_id}/bindings` | Lists the Context's bindings, ordered by binding id. |
| `GET` | `/api/v1/contexts/{context_id}/bindings/{binding_id}` | Returns one binding, with its policy, counters, and the reason code it last stopped on. |
| `PATCH` | `/api/v1/contexts/{context_id}/bindings/{binding_id}` | Updates a binding's policy. |
| `POST` | `/api/v1/contexts/{context_id}/bindings/{binding_id}/actions` | Performs an operator action on a binding: `start`, `pause`, `resume`, `resync` or `reground`. |
| `GET` | `/api/v1/contexts/{context_id}/bindings/{binding_id}/events` | One binding's history, newest first. |
| `DELETE` | `/api/v1/contexts/{context_id}/bindings/{binding_id}` | Disables a binding and starts releasing what it holds at the source. Returns `200` with the binding, which moves to `cleanup_pending`. |

Connector routes return `501` when connectors are disabled on the deployment, and `502` when the connector host or the source fails.

## Pagination

List endpoints page with `limit`, `cursor` and `count`, and return the collection beside a `page` block. The contract is identical to the end-user surface, so see [Pagination](/docs/agent-memory/reference/rest-api#pagination) for the parameters, the response shape, and the rule about not terminating on a short page.

```http
GET /api/v1/contexts/{context_id}/keys?limit=50
```

**Response:**
```json
{
  "keys": [
    {
      "id": "cak_01HF...",
      "name": "primary",
      "grants": { "memory:write": ["org/acme/*"] },
      "created_at": "2026-05-12T10:00:00Z"
    }
  ],
  "page": { "hasMore": false }
}
```
