# Models per stage

SurrealDB Agent Memory’s pipeline uses separate LLM stages with different latency and quality needs. A Context can store a model for each stage, but not every stage applies its setting yet: see [Which settings are applied](#which-settings-are-applied). Embeddings are fixed deployment-wide.

For provider keys and Gemini defaults, see [Configuration](/docs/agent-memory/reference/configuration#default-provider-api-keys).

## The stages

### Extraction

Runs on conversational turns and document jobs. Extracts entities, attributes, relations, actions, instructions, and uncertainties, with one structured-output call per window of text. Turn extraction is on the critical path for `POST /facts` with `"infer": "full"`, so latency matters.

### Reconciliation

Stored on the Context but not applied. Reconciliation matches entities by exact key and makes no model call, so this setting currently has no effect.

### Synthesis

Intended for `/chat` and `/reflect` answer generation. The setting is stored but not applied yet: `/chat` and `/reflect` use the deployment default model, and `/chat` also accepts a per-call `model` that overrides it.

### Elaboration and consolidation

Background “dreaming” work on the worker tier: elaboration and consolidation passes. Not on the user-facing critical path.

### Embedding

Converts text (and multimodal content) into dense vectors for HNSW retrieval and the semantic cache. Fixed to **`gemini-embedding-2`** at **3072** dimensions. Not freely assignable per Context - Context config may only pin that same model id, and any other value is rejected with `400`. Vector reads filter by **`embedding_model_id`**.

## Configuring models per stage

Model assignment is per-Context, through the management API. Each LLM stage takes `{provider, model}`, and the request body is the partial config itself, with no wrapper object:

```http
PATCH /api/v1/contexts/{context_id}
Content-Type: application/json

{
  "models": {
    "extraction": { "provider": "google", "model": "gemini-2.5-flash" },
    "elaboration_consolidation": { "provider": "google", "model": "gemini-2.5-flash" }
  }
}
```

Omit any stage to leave the current assignment (or deployment default) unchanged. Missing provider keys for a selected provider fail at configuration time rather than silently re-routing. A model id that the provider does not list (for example `gemini-2.5-pro`) is rejected.

### Which settings are applied

| Stage | Applied |
| --- | --- |
| `extraction` | Yes for document ingest on the worker. Turn extraction on `POST /facts` uses the deployment default model. |
| `reconciliation` | No. Stored only. |
| `synthesis` | No. Stored only. `/chat` and `/reflect` use the deployment default, or the per-call `model` on `/chat`. |
| `elaboration_consolidation` | Yes, for background elaboration and consolidation on the worker. On-demand `POST /elaborate` and `POST /consolidate` calls use the deployment default. |
| `embedding` | Only `gemini-embedding-2` is accepted. |

## Supported providers

| Provider | Role |
| --- | --- |
| Google (Gemini) | LLM stages; **required** for embeddings |
| OpenAI | LLM stages |
| Anthropic | LLM stages |
| Cerebras | LLM stages |
| OpenRouter | LLM stages |

Use the provider names `google`, `openai`, `anthropic`, `cerebras`, and `openrouter` in the `provider` field. Model ids for Cerebras and OpenRouter are checked by shape rather than against a fixed list.

Provider keys may be set deployment-wide (`SPECTRON_PROVIDER_*`) or per Context. Keys are write-only on the API; reads return which providers are configured, not the secrets.

## Latency versus quality

| Stage | Typical path | Prefer |
| --- | --- | --- |
| `extraction` | Sync on write / ingest | Fast, inexpensive model |
| `reconciliation` | Not applied | - |
| `synthesis` | Not applied; `/chat` and `/reflect` use the deployment default | - |
| `elaboration_consolidation` | Worker background | Fast enough for batch work |
| `embedding` | Ingest + query | Fixed: `gemini-embedding-2` (3072-dim) |

A common pattern is a fast, inexpensive model for extraction. To use a stronger model for chat answers today, pass `model` on the `/chat` call.

## Changing the embedding model

Embeddings are Gemini-only at 3072 dimensions, and `gemini-embedding-2` is the only accepted model. There is currently no reindex endpoint, so stored vectors cannot be re-embedded with a different model through the API.
