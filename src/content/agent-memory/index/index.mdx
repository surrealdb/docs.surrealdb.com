# SurrealDB Agent Memory

SurrealDB Agent Memory turns messages and documents into facts that you can query. It keeps each fact with its source, when it was stated, and the facts it replaced, and it answers questions in plain language with a citation for each answer. An agent can use it as a memory that lasts between conversations, and an application can use it as a knowledge base over its own documents.

It runs on SurrealDB Cloud, so there is no server to set up. You can call it from an SDK, over REST, or from any coding assistant that speaks MCP.

## Get started

1. Sign in to [SurrealDB Studio](https://studio.surrealdb.com), open your organisation, and go to **Contexts**. A context is one agent memory store.
2. Create a context, then open its **API keys** view and create a key. Copy the key, the context ID and the context host.
3. Paste one of the snippets below, with your own values in place of the placeholders.

<Tabs syncKey="agent-memory-start">

<TabItem label="TypeScript">
```bash
npm install @surrealdb/memory
```

```typescript
import { AgentMemory } from "@surrealdb/memory";

const memory = new AgentMemory({
  endpoint: "https://<your-context-host>",
  context: "<your-context-id>",
  apiKey: "<your-api-key>",
});

await memory.remember("Alice was promoted to CTO.");
const hits = await memory.recall("What is Alice's role?");
```
</TabItem>

<TabItem label="Python">
```bash
pip install "surrealdb[memory]"
```

```python
from surrealdb.memory import Memory

with Memory(
    endpoint="https://<your-context-host>",
    context="<your-context-id>",
    api_key="<your-api-key>",
) as memory:
    memory.remember("Alice was promoted to CTO.")
    hits = memory.recall("What is Alice's role?")
```
</TabItem>

<TabItem label="MCP">
```bash
npx install-mcp https://<your-context-host>/mcp \
  --client cursor \
  --header "Authorization: Bearer <your-api-key>" \
  --oauth no
```

Change `--client` to `vscode`, `windsurf`, `zed` or `opencode` for those editors. Claude and Codex have a SurrealDB plugin instead. See [Install the MCP server](/docs/agent-memory/integrations/mcp-server/install).
</TabItem>

</Tabs>

The [hosted quickstart](/docs/agent-memory/quickstarts/hosted) goes through the same steps with REST calls, scopes and chat. If a coding agent is writing your integration, give it the [agent guide](/docs/agent-memory/reference/agents) so that it can use Agent Memory without reading every page.

## What you can build

An agent with Agent Memory can know a customer across months of conversations, keep each user's notes private from the others, answer questions about a pile of documents with a citation for every claim, and say what was true at a date in the past as well as what is true now. A team of agents can share one memory, with each agent reading only the scopes its key allows.

The demos below show each of these. Each one is a finished piece: a body of text ingested into a context, and an interactive page drawn from what the memory holds. Every demo page embeds the result and then explains how it was built, so you can repeat the steps with your own data.

## How Agent Memory works

These are the ideas the rest of the documentation builds on. Each one has a page of its own.

| Idea | In short | Read more |
| --- | --- | --- |
| Contexts and scopes | A context is one memory store. Inside it, scopes are paths such as `org/acme/user/alice`. A write goes to scopes, and a read or an API key is limited to the scopes it names. | [Contexts and scope](/docs/agent-memory/mental-model/contexts-and-scope) |
| Writing | A message or a document is sent to the context. A language model extracts the entities, attributes and relations in it, and each one is compared with what the memory already holds before it is stored. | [How it works in five minutes](/docs/agent-memory/welcome/how-it-works) |
| Change over time | A new value replaces an old one without deleting it, so the memory can answer for any point in time as well as for now. | [Supersession, decay, and forget](/docs/agent-memory/mental-model/memory-lifecycle) |
| Sources | Every fact keeps its source: the message or document it came from, and when. Answers cite these sources. | [Provenance and traceability](/docs/agent-memory/mental-model/provenance-and-traceability) |
| Reading | A question goes to the fastest method that can answer it first: in chat, an earlier answer whose facts are still current, then a direct lookup in the graph, a combined vector, keyword and graph search, and last a rewritten query. | [Coherence, retrieval, and cost tiers](/docs/agent-memory/architecture/coherence-retrieval-and-tiers) |
| Storage | All of this is stored in a SurrealDB database as records, graph edges, vectors and documents, written in transactions. | [Unified substrate and authority](/docs/agent-memory/mental-model/two-layer-architecture) |

For the design behind these ideas, start with [Principles and goals](/docs/agent-memory/architecture/principles-and-goals) and the [glossary](/docs/agent-memory/architecture/glossary).
