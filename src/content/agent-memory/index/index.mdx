# SurrealDB Agent Memory

SurrealDB Agent Memory turns messages and documents into facts that you can query. It keeps each fact with its source, when it was stated, and the facts it replaced, and it answers questions in plain language with a citation for each answer. An agent can use it as a memory that lasts between conversations, and an application can use it as a knowledge base over its own documents.

It runs on SurrealDB Cloud, so there is no server to set up. You can call it from an SDK, over REST, or from any coding assistant that speaks MCP.

## Coding agents

If a coding agent is writing your integration, paste this prompt into it. The agent installs the SurrealDB Agent Skills, connects the Agent Memory MCP server to your context, and reads the agent guide before it writes any code:

The MCP server works with Cursor, VS Code, Windsurf, Zed and OpenCode, and Claude and Codex have a SurrealDB plugin. The [agent guide](/docs/agent-memory/reference/agents) is the single page that an agent needs to use Agent Memory correctly.

## Quickstart

1. Sign in to [SurrealDB Studio](https://studio.surrealdb.com), open your organisation, and go to **Contexts**. A context is one agent memory store.
2. Create a context, then open its **API keys** view and create a key. Copy the key, the context ID and the context host.
3. Paste one of the snippets below, with your own values in place of the placeholders.

<Tabs syncKey="agent-memory-start">

<TabItem label="TypeScript">
```bash
npm install @surrealdb/memory
```

```typescript
import { AgentMemory } from "@surrealdb/memory";

const memory = new AgentMemory({
  endpoint: "https://<your-context-host>",
  context: "<your-context-id>",
  apiKey: "<your-api-key>",
});

await memory.remember("Alice was promoted to CTO.");
const hits = await memory.recall("What is Alice's role?");
```
</TabItem>

<TabItem label="Python">
```bash
pip install "surrealdb[memory]"
```

```python
from surrealdb.memory import Memory

with Memory(
    endpoint="https://<your-context-host>",
    context="<your-context-id>",
    api_key="<your-api-key>",
) as memory:
    memory.remember("Alice was promoted to CTO.")
    hits = memory.recall("What is Alice's role?")
```
</TabItem>

<TabItem label="REST">
```bash
export SURREAL_MEMORY_URL="https://<your-context-host>"
export SURREAL_MEMORY_CONTEXT_ID="<your-context-id>"
export SURREAL_MEMORY_API_KEY="<your-api-key>"

curl -sS "$SURREAL_MEMORY_URL/api/v1/$SURREAL_MEMORY_CONTEXT_ID/facts" \
  -H "Authorization: Bearer $SURREAL_MEMORY_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{ "text": "Alice was promoted to CTO.", "infer": "full" }'

curl -sS "$SURREAL_MEMORY_URL/api/v1/$SURREAL_MEMORY_CONTEXT_ID/query" \
  -H "Authorization: Bearer $SURREAL_MEMORY_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{ "query": "What is Alice'\''s role?" }'
```

The `/facts` response includes the entities, attributes and relations extracted from the text. The `/query` response includes a `tier` field that says how the answer was found, and a trace id for the full retrieval trace.
</TabItem>

<TabItem label="MCP">
```bash
npx install-mcp https://<your-context-host>/mcp \
  --client cursor \
  --header "Authorization: Bearer <your-api-key>" \
  --oauth no
```

Change `--client` to `vscode`, `windsurf`, `zed` or `opencode` for those editors. Claude and Codex have a SurrealDB plugin instead. See [Install the MCP server](/docs/agent-memory/integrations/mcp-server/install).
</TabItem>

</Tabs>

### Next steps

- **Scopes.** A scope is a path such as `org/acme/user/alice` that decides who can read a fact. Writes take `scopes`, reads take `lens`, and each path is registered first. [Contexts and scope](/docs/agent-memory/learn/mental-model/contexts-and-scope) explains how.
- **Chat.** `POST /chat` answers a message from what the memory holds, with citations. See the [REST API](/docs/agent-memory/reference/rest-api).
- **Documents.** [Uploading documents](/docs/agent-memory/learn/ingest/authoritative/uploading-documents) adds manuals, policies and other files to the same memory.

> [!NOTE]
> Agent Memory runs on SurrealDB Cloud. Single-tenant deployments are available on the Enterprise plan, and self-hosted deployments in your own cloud account or data centre are in development as part of the same plan. To discuss either, [contact sales](https://surrealdb.com/contact/sales). [Agent Memory Enterprise](/docs/agent-memory/operate/enterprise) lists what the plan includes.

## What you can build

An agent with Agent Memory can know a customer across months of conversations, keep each user's notes private from the others, answer questions about a pile of documents with a citation for every claim, and say what was true at a date in the past as well as what is true now. A team of agents can share one memory, with each agent reading only the scopes its key allows.

These guides build the most common cases from start to finish:

- **Customer service.** The [customer support agent](/docs/agent-memory/cookbooks/build/customer-support-agent) remembers each customer between conversations.
- **Personal assistants.** The [personal AI assistant](/docs/agent-memory/cookbooks/build/personal-ai-assistant) keeps what a user tells it, and forgets on request.
- **Internal knowledge.** [Knowledge-grounded agents](/docs/agent-memory/cookbooks/patterns/knowledge-grounded-agents) answer from your documents with citations.
- **Several agents.** [Multi-agent shared memory](/docs/agent-memory/cookbooks/build/multi-agent-shared-memory) gives each agent its own scopes in one context.
- **Coding and research agents.** A [coding agent with project memory](/docs/agent-memory/cookbooks/build/coding-agent-with-project-memory) and a [long-running research agent](/docs/agent-memory/cookbooks/build/long-running-research-agent).

## How Agent Memory works

These are the ideas the rest of the documentation builds on. Each one has a page of its own. If context windows, compaction and embeddings are new to you, [How an AI model remembers](/docs/agent-memory/welcome/how-a-model-remembers) and the two pages after it explain them first.

| Idea | In short | Read more |
| --- | --- | --- |
| Contexts and scopes | A context is one memory store. Inside it, scopes are paths such as `org/acme/user/alice`. A write goes to scopes, and a read or an API key is limited to the scopes it names. | [Contexts and scope](/docs/agent-memory/learn/mental-model/contexts-and-scope) |
| Writing | A message or a document is sent to the context. A language model extracts the entities, attributes and relations in it, and each one is compared with what the memory already holds before it is stored. | [How it works in five minutes](/docs/agent-memory/welcome/how-it-works) |
| Change over time | A new value replaces an old one without deleting it, so the memory can answer for any point in time as well as for now. | [Supersession, decay, and forget](/docs/agent-memory/learn/mental-model/memory-lifecycle) |
| Sources | Every fact keeps its source: the message or document it came from, and when. Answers cite these sources. | [Provenance and traceability](/docs/agent-memory/learn/mental-model/provenance-and-traceability) |
| Reading | A question goes to the fastest method that can answer it first: in chat, an earlier answer whose facts are still current, then a direct lookup in the graph, a combined vector, keyword and graph search, and last a rewritten query. | [Coherence, retrieval, and cost tiers](/docs/agent-memory/learn/architecture/coherence-retrieval-and-tiers) |
| Storage | All of this is stored in a SurrealDB database as records, graph edges, vectors and documents, written in transactions. | [Unified substrate and authority](/docs/agent-memory/learn/mental-model/two-layer-architecture) |

For the design behind these ideas, start with [Principles and goals](/docs/agent-memory/learn/architecture/principles-and-goals) and the [glossary](/docs/agent-memory/reference/glossary).

## Integrations

Agent Memory connects to the tools an agent is usually built with:

- **SDKs.** [TypeScript](/docs/agent-memory/integrations/sdks/javascript-and-typescript), [Python](/docs/agent-memory/integrations/sdks/python), [Go](/docs/agent-memory/integrations/sdks/go), [Kotlin](/docs/agent-memory/integrations/sdks/kotlin), [Swift](/docs/agent-memory/integrations/sdks/swift), and more under [Integrate](/docs/agent-memory/integrate).
- **Frameworks.** [LangChain](/docs/agent-memory/integrations/frameworks/langchain), [LlamaIndex](/docs/agent-memory/integrations/frameworks/llamaindex), [CrewAI](/docs/agent-memory/integrations/frameworks/crewai), [Pydantic AI](/docs/agent-memory/integrations/frameworks/pydantic-ai), [Mastra](/docs/agent-memory/integrations/frameworks/mastra) and [Google ADK](/docs/agent-memory/integrations/frameworks/google-adk).
- **AI SDKs.** The [Vercel AI SDK](/docs/agent-memory/integrations/ai-sdks/vercel-ai-sdk) and [TanStack AI](/docs/agent-memory/integrations/ai-sdks/tanstack-ai).
- **Voice.** [LiveKit](/docs/agent-memory/integrations/voice/livekit), [ElevenLabs](/docs/agent-memory/integrations/voice/elevenlabs) and [Gradium](/docs/agent-memory/integrations/voice/gradium), for agents that remember a caller.
- **Moving from another memory layer.** Guides for [Mem0](/docs/agent-memory/cookbooks/migrate/from-mem0), [Zep](/docs/agent-memory/cookbooks/migrate/from-zep), [LangMem](/docs/agent-memory/cookbooks/migrate/from-langmem) and [a vector store](/docs/agent-memory/cookbooks/migrate/from-vector-store).

<Details summary="The name Spectron">

SurrealDB Agent Memory was developed under the project name **Spectron**, and the rename is arriving in stages. Already renamed: the client SDKs (`@surrealdb/memory`, `surrealdb-memory`, and so on), the framework integrations, the CLI, which is now `surreal memory`, the Agent Memory component of the `surreal` command-line tool, and the MCP server, which registers as `agent-memory`.

Still carrying the old name: the **`SPECTRON_*`** environment variables, and the **`X-Spectron-*`** request headers. Those are configuration and wire contract rather than things the product is called, so they are unchanged for now.

</Details>
