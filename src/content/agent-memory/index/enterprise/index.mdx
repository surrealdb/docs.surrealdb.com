# Agent Memory Enterprise

Agent Memory Enterprise is the SurrealDB Agent Memory plan for organisations that need a deployment of their own. It has the same memory features as the other plans. It adds control over where Agent Memory runs, which language models it calls and how many tokens it can use.

## What Enterprise adds

| Feature | Sandbox, Lite, Standard and Plus | Enterprise |
| --- | --- | --- |
| Deployment | Contexts on a shared SurrealDB Cloud deployment | A single-tenant deployment, or a self-hosted deployment in your own infrastructure |
| Language models | Google, OpenAI, Anthropic, Cerebras and OpenRouter models, chosen per Context | The same, plus your own model through an OpenAI-compatible endpoint |
| Air-gapped deployment | Not available | Arranged with SurrealDB as part of an Enterprise agreement |
| Tokens | The plan's token allowance | A volume agreed with SurrealDB |
| Support | Community support | Enterprise support with SLAs |

## What stays the same

Every plan has the same memory features: the knowledge graph with entity extraction, conversational memory, tri-temporal versioning and supersession, provenance on every fact, hybrid retrieval, traces, and the multimodal document pipeline. Every plan also has the same isolation and security features: one database per Context, scoped permissions with attenuated API keys, prompt-injection scanning, and the [forget](/docs/agent-memory/operations/forget) operations.

The REST API, the MCP server and the SDKs are also the same. Code written against a Context on SurrealDB Cloud works against an Enterprise deployment after you change the endpoint, the Context ID and the API key.

## Deployment options

- **Single-tenant:** SurrealDB runs an Agent Memory deployment that serves only your organisation. SurrealDB applies the deployment settings agreed with you.
- **Self-hosted:** you run Agent Memory in your own cloud account or data centre, in front of your own SurrealDB deployment and object storage. You set the deployment settings yourself.
- **Air-gapped:** air-gapped deployment is arranged with SurrealDB as part of an Enterprise agreement.

## What you can configure

Settings apply at two levels. Per-Context settings, such as the model for each stage and the response cache, are available on every plan. Deployment settings, such as the default language model, your own model endpoint, storage and limits, apply to every Context on a deployment, so you can change them only on a deployment of your own. Some behaviour, such as when `context` facts expire, is the same on every deployment.

[Enterprise configuration](/docs/agent-memory/enterprise/configuration) lists every setting at each level, and the behaviour that stays fixed.
