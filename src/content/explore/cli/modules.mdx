# Working with extensions

Extensions are WebAssembly packages that add functions to the database. This page shows the command-line workflow for a [Surrealism](/docs/learn/extensions/plugins/overview) extension: scaffold a project, build it, inspect the result, run a function, then sign and install it. Extensions were called modules before SurrealDB 4.0, when the commands below were `surreal db module` commands.

`mod` is the launcher's component for this work, and it is the intended home of these commands. Its first release is not published yet, so `surreal install mod` does not work today. Until it is, the same commands are available from the database component as `surreal db extension`, and the examples below use that form.

## Create a project

```bash
surreal db extension init my-extension
```

`init` scaffolds a Rust project with a `package.toml` and a starter `src/lib.rs`. It asks for the organisation and extension name interactively. In a script, add `--headless` with `--org`, and `--name` when the extension should not take the folder's name.

```bash
surreal db extension init my-extension --headless --org acme --name my-extension
```

## Build the extension

Run `build` from the project folder, or name the source folder. The archive is named after the organisation, name and version in `package.toml` unless `--out` names it.

```bash
surreal db extension build
surreal db extension build ./my-extension --out my-extension.surli
```

A build is a release build. Add `--debug` for a debug build.

## Inspect and run it

`info` lists the functions the archive exports, and `sig` shows the signature of one of them.

```bash
surreal db extension info my-extension.surli
surreal db extension sig --fnc greet my-extension.surli
```

`run` calls a function with arguments, without a database. Repeat `--arg` for each argument, written as a SurrealQL value.

```bash
surreal db extension run --fnc greet --arg '"World"' my-extension.surli
```

## Sign and install it

To let others check where an archive came from, name a signer in `package.toml`, build again, and sign the archive:

```bash
surreal db extension config signer ssh ~/.ssh/release.pub
surreal db extension build --out my-extension.surli
surreal db extension sign --key ~/.ssh/release my-extension.surli
```

Place the archive in a [bucket](/docs/reference/query-language/statements/define/bucket) of the database, then install it. `install` shows the signer, the digest and the capabilities the extension requests, asks which to accept, and defines it:

```bash
surreal db extension install 'f"extensions:/my-extension.surli"' --as greeting \
    -e ws://localhost:8000 -u root -p secret --ns app --db main
```

The extension's functions are then called from SurrealQL as `ext::greeting::greet('World')`. [`DEFINE EXTENSION`](/docs/reference/query-language/statements/define/extension) defines an extension directly, and the [Surrealism guides](/docs/learn/extensions/plugins/overview) cover writing the functions and the attribute reference.

## Reference

The command reference is [`surreal db extension`](/docs/reference/cli/db/commands/extension) today, and the [`surreal mod` page](/docs/reference/cli/modules) in the CLI reference explains how it relates to the `mod` component.
