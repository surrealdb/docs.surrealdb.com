What SurrealDB Agent Memory is holding

The visualisation shows the cast. This page shows what sits under it: the data the Context actually stores for this book, what the endpoints hand back when the demo asks, and which properties of the system the demo is leaning on.

Captured from a live Context at http://localhost:9090/api/v1/robinhood - 1471 entities across 22 chapter documents. Every response below is verbatim, straight from the endpoint. The slowest call on this page took 91 ms.

The alias was read out of the prose and dated to the instant the prose supports, from the chapter text alone. That is what keeps asOf honest - a reader at chapter 10 is still in the dark.

How the book got in

Twenty-two chapters, twenty-two documents, uploaded one at a time and in order. The only unusual thing about the ingest is the timestamp: each chapter is stamped with a date it never had, and that invented date is what the rest of the demo runs on.

1 · Upload

POST /documents, one chapter at a time. Each carries observedAt = 2000-01-01 plus the chapter index, so the book's own order becomes a timeline the database can be queried against.

2 · Extract

Agent memory reads the chapter and proposes entities, attributes and relations. Extraction is shown the entities the Context already holds and told to reuse their exact names, which is why the chapters go in serially.

3 · Reconcile

A second mention of someone updates the state. The value it replaces is kept, dated, and still addressable.

4 · Read

GET /entities/{type}/{name}?asOf=…. Only what was written at or before that instant comes back. A reader's position in the book is a timestamp.

What the demo is leaning on

Five properties, all of them visible in the responses further down this page.

Narrative time, not wall clock

The observedAt given at upload becomes createdAt on every row the chapter produces. The Context runs two clocks - the one the story happens on, and the one the server happens on - and the demo queries the first.

Supersession

Every write is kept. Each carries supersedes and supersededBy, and the row it displaces gets a validUntil. The current value is the end of a chain.

Identity across names

Reynold Greenleaf resolves to a node of his own, with his own attributes and edges, joined back to Little John by an is_called relation dated to the chapter where the book makes the connection.

Provenance

Every attribute and every relation names the document it came from, so any claim on the page can be walked back to the chapter that produced it.

Memory categories

Rows are filed as identity, knowledge or context and carry an importance score. Roughly: what someone is, what is known about them, and what happens to be true right now.
